# 111 MCM1003U・MCM3004U 再起動時の検索初期化

2026-10-21受領srcを基準にした修正版。対象は「取引先見積・契約一覧（1003U）」と「作業予定検索（3004U）」。受領srcは変更していない。

## 原因と修正

1003Uは検索条件・結果の破棄処理があるが、共通JavaScriptがそれを呼ばずタブだけ閉じる経路があった。3004Uはセッション破棄処理自体がなく、閉じるリンクもメニューを指していた。

- 画面の「閉じる」：自画面の検索情報を破棄してからタブを閉じる。
- タブの「×」：閉じる瞬間の通信へ依存せず、次のメニュー起動時に初期化する。
- 詳細画面から戻る／3005Uから3004Uへ戻る：通常URLを使い、従来どおり検索結果を保持。
- 3004Uの再起動：全9タブの条件・一覧・選択タブを初期化。基準月・日付は再表示時点、対象期間は通常4／不足製番13、取引先条件は空欄。
- 1003Uの再起動：検索条件・一覧・一覧出力用データを初期化。検索結果をDB登録する処理ではない。

## 副作用を避けるための扱い

タブ終了前の`/reset`は204応答で完結し、メニューへリダイレクトしない。これにより裏側のfetchがメニュー処理まで実行して、別画面の編集中情報を消すことを避ける。通常表示URLで毎回初期化する方式にはしていない。既存の権限インターセプターは追加URLでも同じ画面IDを判定する。

初期化する新規起動経路はメニューの`/open`。ブックマーク等でも新規起動にしたい場合は`/mcm1003u/open`又は`/mcm3004u/open`を使う。通常URLは詳細からの戻りを兼ねるため、直接再アクセスでは保持する。

## 反映後の確認手順

1. メニューから1003Uを開き、任意の条件で検索。画面の「閉じる」で終了し、メニューから再度開く。条件は初期値、結果は0行となること。
2. 1003Uで再検索し、契約NO等のリンクから詳細を開いて戻る。検索条件・結果が残ること。
3. 3004Uの複数タブで条件を変えて検索。画面の「閉じる」後、メニューから再度開く。1番目のタブ・各初期値・全タブ0行となること。
4. 3004U「予定登録検索」から登録IDを押して3005Uを開き、閉じて3004Uへ戻る。検索条件・結果を保持していること。
5. 両画面でそれぞれ検索後、ブラウザーのタブの「×」で閉じる。メニューから開き直して初期化されること。
6. メニュー経由でない直接起動でも画面の「閉じる」で初期化されること、別の業務画面の未保存入力を今回の裏側のresetで消さないことを確認する。
