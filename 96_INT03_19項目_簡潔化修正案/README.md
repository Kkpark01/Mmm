# INT03 全19項目の簡潔化修正案

2026-10-16。[修正案全文](INT03_パック店舗直_簡潔化修正案.md)。[95の承認済み3件](../95_INT03_3項目_簡潔化修正案/INT03_01_02_05_修正案.md)をそのまま収録し、残り16件を同じ形式・簡潔さで作成した。Excelへの反映前の本文案である。

## 対象・変更理由

基準は[94のExcel](../94_INT05_修正反映Excel/README.md)にある `INT03_パック店舗直`。全19件の項番・分類を維持し、02～04・INT05と同じ8項目の構造に合わせた。実績は変更していない。

| 項番 | 整理内容 |
|---|---|
| 01・09 | 01は見積1件の参照。09は正常な入口で別見積Bを開き、そのまま店舗直の見積Aを開いて、前回見積の取り違えを確認する。全機器・価格・DB前後比較は省いた。 |
| 02・10 | 見積・構成・明細・個体を各1件に絞り、作成・登録・元一覧の再検索と元見積の関連を確認する。除外機器の組合せと3007Uでの再確認は省いた。 |
| 03・11 | 対象契約1件の備考の保存・再表示に絞った。DBも対象のBIKOだけを確認する。 |
| 04・12 | 未来月の支払明細を持つ契約1件を使い、破棄後の契約3・元見積1を確認する。 |
| 05・13 | 過去月の支払明細を持つ契約1件の拒否と状態維持に絞った。支払帳票の前後出力は省いた。 |
| 06・14 | 当月だけの支払明細を持つ契約1件へ縮小。未来月は04・12へ分担し、当月との境界を残した。 |
| 07・15 | 対象T・比較Bの2契約で、並べ替え後の参照と破棄を確認する。表示位置が変わる条件は維持した。 |
| 08・16 | 2担当者・契約1件で先行／後行の操作を確認する。状態と更新者・日時に絞り、移行期待Q-INT03-CONFLICTは保留として残した。 |
| 17・18 | キャンセルと同画面の再検索、対象契約・元見積の状態だけを確認する。支払月判定より前の取消なので、特別な支払月の準備は省いた。 |
| 19 | 両方の一覧に出る同じ1契約を、一方から備考更新し、他方から確認する。全期間・機器・価格・添付の比較は省いた。 |

通常の破棄を未来月データへ揃えたため、支払明細なしの条件は個別には実施しない。全子テーブル・全監査情報・別画面での重複確認も省いている。これらを別工程で確認済みとしたものではない。

## 反映方法

本文確認後、94のExcelのINT03のC（テスト観点）・D（前提条件）・E（操作手順）・F（期待結果）・G（期待メッセージ）・P（備考／根拠）へ反映する。項番・分類・実績欄・INT02／INT05の修正・他シートは維持する。

今回はExcel・95の承認済み本文・既存MD・アプリsrcを変更していない。

## 検証と残る制約

[検証結果](検証結果.json)。19項番の欠落・重複、分類・8項目の構造、手順番号と入力値、承認済み3件の一致、VBメッセージ、画面項目・ボタン名、DBの対象と期待値を静的確認した。

- 01・09：受領Webのキー引継ぎ・別タブ表示に差異候補がある。共通仕様に基づく期待と、現状の差異を分けて記載した。09の準備は正常な1003Uの入口を使い、Bのタブを閉じない。
- 07・15：VBの並べ替え可否は未確定。受領1010Uに1009Uと同じ並べ替え処理が見当たらないため、15は未確認・保留を明記した。並べ替えなしで合格にはしない。
- 08・16：後行者を拒否するか、先行者の更新者・日時を保護するかはQ-INT03-CONFLICTの合意待ち。観測記録と状態確認を残し、勝手に合格基準を確定していない。
- 02・10のVB通常登録は新規確認→登録確認の2回。既存登録は登録確認のみ。VBの登録完了通知なし、1009Uの追加破棄完了通知、1010Uの破棄完了通知なしを区別した。

VB・Web実機、実DB・配備ビュー、登録・破棄の実行、別担当者によるレビューは未実施。文書だけの変更のためアプリのビルド・テストは行っていない。
