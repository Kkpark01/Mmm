# 77：チケット533 添付保存構造（2026-10-10改訂）

## 原因・VBの根拠
旧77には「取引先」の先頭階層が不足し、期間テーブルの名称を使っていました。VBのSettings.settings／app.configの3種類は「取引先」「店舗」「作業予定」。CPFileManager.GetRootPathは共通ルートの下に種類別フォルダを作ります。
VBの1003U検索行→Mcm1005uDelivery.TorihikisakiNK→FileUpButton_Clickを確認。名前の取得元は検索ビューMCM_1003_Vです。

## 保存構造
```text
既存設定 mcm.file.upload-path
├─ 取引先
│  └─ {取引先契約ID}_{取引先名}
│     └─ {取引先契約期間ID}_{開始日yyyyMMdd}
│        └─ {契約No}_{元のファイル名（拡張子含む）}
├─ 店舗      ← 最新受領srcで対応済み
└─ 作業予定  ← 本修正版で先頭フォルダ名を修正
```
検証環境の受領設定は `\\ILCM-SYSDEV\uploadfolder\MCM`。設定のルート自体は変更していません。階層はコード側で振り分けます。存在するフォルダへ追加し、存在しなければ作成します。

## 修正ファイル・内容
- `src/main/java/com/daifuku/mcm/service/Mcm1005uAttachmentService.java`：取引先階層を追加。UUID方式を廃止。契約・指定期間・名称・開始日・契約Noで生成。失敗取消時は自分が新規作成したファイルだけを削除し、他の添付を保持。
- `src/main/java/com/daifuku/mcm/repository/Mcm1005uRepository.java`：findAttachmentSupplierNameを追加。VBの検索元と同じMCM.MCM_1003_VからTK_KEIYAKU_IDで名前を特定。未取得・空・複数名の場合は中止。
- `src/main/java/com/daifuku/mcm/service/Mcm3005uAttachmentService.java`：「sagyoyotei」を「作業予定」へ変更。先頭フォルダ定数と説明だけの変更で、下位構造は維持。

2003Uの店舗添付は既に「店舗」を使用しているため変更しません。店舗・作業予定の下位構造を今回一括で改修するものではありません。

## 各項目の取得元
|項目|取得元|
|---|---|
|ルート|環境別の既存mcm.file.upload-path|
|契約ID|受付contractId、契約DBを取得・ロック|
|取引先名|MCM_1003_V.TORIHIKISAKI_NKを契約IDで取得（VBの引継ぎ元と同じ）。クライアント送信名は直接使わない|
|期間ID|受付periodId。対象契約の期間一覧内の一致行に限定|
|開始日|その期間行のMCM_TK_KIKAN.KAISI_DT。8桁へ変換。別期間・保存日時ではない|
|契約No|MCM_TK_KEIYAKU.KEIYAKU_NO|
|元名|MultipartFile.getOriginalFilename()。拡張子を維持|
|参照パス|MCM_TK_TENPU.DIRECTORYに新しい実ファイルのフルパスを登録|

取引先名は保存時に再取得します。VBは画面へ引き継いだ時点の値を保持するため、画面を開いてからマスタ名が変更される特殊な場合のタイミング差は残ります。

## 保持した動作・制約
- 複数の異なる添付を同じ期間フォルダへ保存。
- 同名は既存Webの追加拒否を維持。既存実ファイルもCREATE_NEWで上書きせず拒否。VB共通の上書き処理には合わせず、チケットの「無断で上書き方式に変更しない」を優先。
- 必須欠落・不正なパス要素・Windows使用不可文字は案内して中止。GUID・現在日付・代替名で補完しない。文字を勝手に置換しない。
- ファイル内容、画面の元ファイル名表示、権限・承認状態判定は維持。
- 既存添付は移動・改名しない。DBのDIRECTORYを利用する1005U取得・削除と1011U捺印、3005Uの旧資料参照は引き続き既存パスを使用。ルート外・実体なしの場合は従来どおり参照不可。
