# TL07-004 点検データ作成

**要確認：34列の模擬入力では数量集約とファイル保存を確認できましたが、M列を追加した模擬入力では処理が長時間終了せず、試験を中断しました。**

131版の点検データ作成VBAを隔離Excelで実行し、ブック内原紙のセルと書式をコピーして使用しました。機器Aの数量2・3を5へ集約し、機器Bの数量1とともに出力したこと、サポートID・契約番号など12項目は、保存ファイルの再読込で一致しています。完了メッセージは文字の記録に置き換えています。

仕様書には、①の取得後にM列が追加される一方、②の出力が固定列を参照する可能性が記載されています。そこで同じ模擬データにM列を挿入して②を実行したところ、約1分後も処理が続き、出力ファイルがないため、試験用Excelを停止しました。**実際の①の取得結果を使った試験ではないため、会社版で同じ現象が起きるとは断定できません。** 実際の運用順・入力データ・会社編集版の確認が必要です。

実DB・①から②までの一連操作・実ボタンやダイアログは未確認です。観察用のExcelは架空データであり、運用には使用しないでください。

## M列追加時の集約処理の切り分け

同じ模擬データに空のM列を挿入し、131版の数量集約処理だけを実行しました。処理は終了しましたが、固定列の参照位置がずれ、模擬納入先がN列に移動し、品名欄が空、型式欄に品名、数量欄が0となりました。数量2・3の2行は1行にまとめられていますが、期待した数量5にはなっていません。これは前述の出力全体が終了しなかった原因を確定するものではありません。実際の①取得後の列構成と会社編集版でも再確認が必要です。

## 実際の列追加処理を使った追加確認

131版の取得処理末尾にある `Crate_ChkData` と、出力側の数量集約 `marge` を、架空データに対してこの順に実行した。照合用M列には「2026/03/01 / 0000123 / SIM-CONTRACT」が入り、納入先・品名・数量の参照位置がずれ、数量は0となった。取得処理全体、DB参照、途中の他の加工および会社編集版は実行していないため、実際の一連操作全体の結果と断定しない。

## 実際の列追加処理から出力全体までの追加確認

131版の `Crate_ChkData` で照合値を作成した架空データに、131版 `Grouping` 全体を実行した。約40秒間処理が続き、出力xlsが作られなかったため、試験専用Excelを停止した。通常の34列データでは同じ出力処理が完了している。停止位置や実際の取得データでの再現は未確認。①取得全体と会社編集版は未実行のため、この結果だけで実運用全体を断定しない。試験用Excel停止時の後処理エラーは強制停止の結果であり、元マクロのエラーとは扱わない。

## 取得から出力までの処理順の確認

131版のコードでは、取得処理の終盤に `Crate_ChkData` が呼ばれ、「取込データ」のM列に照合用の列が挿入されます。その後、出力側の `Grouping` は `marge` を呼び、`DataCopy` は「取込データ」の先頭34列をそのまま「点検データ」へコピーします。該当する処理の中にM列を取り除く操作はありませんでした。

既存の架空SQL試験では取得結果が34列でした。このため、取得完了後の列追加が、前述の模擬試験で使った列ずれに結びつく可能性を示しています。ただし、取得全体を実DBから実行した結果や、利用者による中間操作は確認していません。
