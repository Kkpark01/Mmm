# TL08-004 点検依頼書の作成

**要確認：依頼書作成マクロに構文上の不整合があり、実際にコンパイル・実行できるか確認が必要です。**

131版および139版の実ブックを読み取り専用で開き、`依頼書作成_Excel` の132行目を確認しました。「ブランド③」の処理にある右辺 `ActiveCell.Offset(3, 0).Value) + "台"` は、余分な閉じ括弧を含んでいます。VBAの構文エラーとなり、依頼書作成の実行を妨げる可能性があります。

今回は実際のVBAプロジェクトのコンパイルやボタン操作を行っていないため、表示されるエラーや影響範囲は未確定です。会社編集版が同じ内容かも未確認です。TSSA住所取得、原紙への転記・保存・再読込は未実施です。元ブックは変更していません。

## 原紙への転記を試験用コピーで確認

131版のVBAを試験専用ブックに取り込み、構文の余分な括弧だけを試験用に除いて実行しました。配布されているNEC原紙のコピーに架空の客先名・契約No・サポートID・日程・1機器を入力した結果、機器の4項目は転記され、保存後も保持されました。一方、客先名・契約No・サポートID・日程は、マクロがG列へ書き込むものの、原紙の該当箇所はF列が先頭の結合セルであり、F列の表示値は空欄でした。通常の空ブックに結合セルを作った単独確認でも、先頭以外のG列への書込みではF列に値が入りませんでした。

住所も試験出力では空欄でしたが、この試験ではTSSA住所取得と正式な入力形式を再現していないため、住所機能全体の不具合とは断定できません。会社編集版・実際の入力形式・実DBは未確認です。元マクロと原紙のハッシュは変わっていません。

## 住所取得の追加確認

131版の住所取得処理を、同じシート名と列構成を持つ架空TSSAファイルで直接実行しました。ID「0000123」が一致すると住所が入力され、存在しないIDでは「住所が見つかりませんでした。」の処理が実行されました（通知は記録に置換）。直接呼出しでは不一致時に前の住所が残りますが、通常の「データ表示」処理は対象行が見つかった際、住所欄を空にしてから住所取得を呼び出します。したがって今回の直接呼出しだけで通常操作に旧住所が残るとは判定できません。実TSSA・データ表示からの一連操作・会社編集版は未確認です。
