# TL31-002 既存の付替先への更新

**部分確認：既存の付替先がある場合の更新処理を、架空のローカルDBで確認しました。**

133版EXEの更新処理を試験用プログラムから呼び出し、元 `OLD0001` を、既存行がある先 `KEEP001` に変更しました。ローカルSQL Server上に今回限り作成した架空の6表を使っています。

- 5表で元の行が先IDに変わり、元から先IDだった各表の1行は更新日時・更新者を含めて保持されました。
- 5表の総件数と、元・既存先・対象外の代表行の主キー、PLANT_ID、サポートID、更新日時・更新者を照合し、統合・削除や対象外行の変更がないことを確認しました。
- 元の納入先のDTS連携フラグは0、別の既存先納入先は1のままでした。
- コミット完了ログを確認しました。試験用DBは終了時に削除しました。

[実施した試験](../../../検証記録/20261029_VBツール受領資料/133_検証/TL31-002.ps1)／[試験ログ（Shift-JIS）](../../../検証記録/20261029_VBツール受領資料/133_検証/runtime_tl31_002/log.txt)

**未確認：** 実画面での既存先納入先表示・開始操作・完了表示、対象外Uの全列照合、実DB・会社編集版は確認していません。今回は模擬表に用意した列のみを照合しました。スクリーンショットはなく、ケース全体は部分確認です。



## 同じ納入先を共有する場合

元と既存先のプラントが同じ納入先を参照する架空データでも、更新処理を実行しました。元・既存先の行が別々に残り、共有する納入先のDTS連携フラグが0、更新者が試験用の値になることを確認しました。試験DBは終了時に削除しています。
