# TL01（取引先見積依頼書発行） 単体テスト仕様書

準備方針：[共通方針と準備記録](../00_試験準備の共通方針.md)。このケースで使う既存入力値・期待件数・対象版を準備担当者が記入する。DBの試験データ新規登録は行わない。

対象：取引先見積依頼書発行ver2.6.xlsm（改修版）。操作シート「取引先見積依頼書発行」に見積依頼Noを入力して「実行」を押すと、新MCM（SQL Server）から取引先見積の機器明細を取り出し、取引先向けの見積依頼書（Excel）を、ツールと同じフォルダーに保存する。DBは読むだけで、更新しない。

凡例：
- 実施者：試験を行う人。Excelでツールを実行し、操作シートと見積依頼書を確認する。
- 準備担当者：検証DBの既存データを選び、入力値と期待値を試験データ表に書いて実施者へ渡す人。
- 試験データ表：準備担当者が、選定した既存取引先見積の入力値・期待値を書く表。各ケースの前提条件にある。
- 見積依頼書：このツールが作るExcelファイル（シート名「保守見積依頼」）。
- 各ケースの「前提条件」「操作内容」「期待結果」は、そのケースだけを読んで実施できるように書いてある。他のケースは参照しない。
- 準備未完なら実施を開始しない。条件がない分岐は未確認と記録し、合格へ読み替えない。
- このツールにはメッセージIDがないため、期待メッセージの「メッセージID」は「－」とする。
- 実施区分：通常／要確認／開発者テスト／実施不可／除外候補（test-spec-common-rules.md 14.7章）

項番の欠番：

| 項番 | 理由 |
|---|---|
| 003 | 見積依頼Noが空欄のときのメッセージ。DBに接続する前に止まり、処理が元のツールと同じため、作らない（作成者の判断 2026/11/02） |
| 005 | 接続エラー。共通部品が TL11（店舗見積実績検索）と同じため、TL11-007 で確認する |

## TL01-001

### 項番
TL01-001

### テスト項目
TL01(取引先見積依頼書発行)：見積依頼Noを指定すると、見積依頼書がツールと同じフォルダーに決まった名前で保存され、ヘッダと操作シートに見積の情報が表示されること

### 前提条件
```
実施区分＝通常（既存データと期待表の準備後）。

【この試験で確認すること】
既存見積依頼Noで保存され、ヘッダと操作シートの値・保守条件の表示が期待値と一致すること。

【実施する人】
・実施者（操作・表示と期待値を照合する人）。
・準備担当者（検証DBの既存データを読み取り、入力値・期待表を用意する人。試験データは新規登録しない）。

【実施者に必要なもの】

・MSOLEDBSQL19等、対象版が指定するドライバーと、会社で確認した検証DB接続設定。

【開始時の状態】
同じ名前の出力がない試験コピーを使用する。
```

### 操作内容
```
1. エクスプローラーで、コピーしたフォルダー「04_取引先見積依頼書」を開く。「Mcm移行部品」フォルダーの McmMacroSettings.ini をメモ帳で開き、サーバー名・DB名が準備記録の検証接続先と一致することを確認する。変更せずにメモ帳を閉じる。
```

### 備考
```
【実施区分】通常
【根拠】改修版 取引先見積依頼書発行ver2.6.xlsm。内蔵SQL queries/T12_00_default_01.sql は個体明細ごとに1行を返す（25列目は機器明細ID）。cnt_volume：数量＝機器明細の数量÷同じ機器明細IDの行数。Merge_Serial／Serial_Convert：結合キー（機器構成名 / 品名 / 型式）が同じ行のシリアル番号を「S/N： 」＋「 / 」区切りで結合（個体管理フラグが1の機器だけ）。Merge_item：結合キーが同じ行の数量を合計し、重複を削除して元の順に並べる。MachineGroup：機器構成名が変わる行の上に「◆機器構成名」の行を入れる。Edit_Form：明細を8行目から貼り付け、明細の行（G列に値がある行）だけに罫線を引く。どれも列の位置で処理するため、取得結果の列の順（25列）が元のツールと同じであることが前提。
【確認していないこと】同じ機器構成に、別の機器明細として同じ品名・型式が2件ある場合（同じ結合キーで同じようにまとまるため）。
```
