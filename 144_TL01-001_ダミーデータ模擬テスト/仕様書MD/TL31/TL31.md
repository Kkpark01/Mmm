# TL31（サポートID付替プログラム） 単体テスト仕様書

準備方針：[共通方針と準備記録](../00_試験準備の共通方針.md)。このケースで使う既存入力値・期待件数・対象版を準備担当者が記入する。DBの試験データ新規登録は行わない。

対象：133の実行用「保守契約管理システムサポートID付け替え.exe」。主要8ケース。起動経路は実行用フォルダーからEXEを開く。Excel・Webの画面ではない。

凡例：
- 実施者：ツールを操作し、画面・ログ・読み取り専用DB照会で判定する人。
- 準備担当者：更新を許可された既存対象、期待値、実行前後の記録と復元方法を用意する人。試験用の新規登録は行わない。
- A＝付替元、B＝付替先、U＝対象外のサポートID。値は試験データ表に記入する。サポートIDだけでなく実行前の主キーで照合する。
- 各ケースは独立した既存対象を使うか、準備担当者が合意した方法で実行前の状態へ復元してから行う。BからAへの逆方向付替えを復元方法にしない。
- [用語表](用語表.md)にDB照会SQL・対象6表・画面名称、[骨子](骨子.md)に確認範囲と結合候補を記載する。会社編集版・検証DBでの一連動作は未確認。
- 全ケースとも共有データの並行更新を停止した検証枠で実施する。メールや本番DBは使用しない。メッセージIDは「－」。

---

## TL31-001

### 項番
TL31-001

### テスト項目
TL31（サポートID付替プログラム）：未使用の付替先へ変更すると、元IDに該当する既存行だけが更新され、完了表示と確定ログを残すこと。

### 前提条件
```
実施区分＝通常（更新許可・設定・既存データ確保後）。

【この試験で確認すること】
付替元AのサポートIDとDTS連携フラグ、更新日時・更新者の更新範囲。

【実施する人】
・実施者（ツール操作とDB照会をする人）。
・準備担当者（更新してよい対象と復元方法を決める人）。

【実施者に必要なもの】
・133の実行用EXEと同名の.exe.config、設定済みの検証DB接続・更新者、書き込み可能な実行用フォルダー。
・対象6表を読み取り照会できるSSMS等。Excel原紙は不要。

【準備担当者が用意するデータ】
付替元Aは、プラントと納入先が結合して表示できる既存の7桁IDとする。
付替先BはAと異なる7桁とし、SUPPORT_IDを持つ5表すべてに未使用であることを確認する。
対象外UはA・Bと異なる既存IDとし、対象プラントと納入先を共有しないものを選ぶ。
用語表のDB照会SQLで、5表のA対象主キー、対象プラントの納入先ID、各表の件数と更新前値を控える。
PLANT以外の表が0件でも開始できるが、その表の更新分岐は未確認として記録する。
可能ならDTSRENKEI_FLGが0以外の対象を含める。全対象が初めから0なら、0以外から0への変化は未確認とする。

試験データ表：
| A／画面に表示する元納入先ID：名 | |
| B／5表で未使用と確認した日時 | |
| U／対象外の主キーと共有しない納入先ID | |
| 5表それぞれのA対象主キー・期待更新件数 | |
| 対象納入先ID（重複を除いた件数）／DTS連携フラグ | |
| 更新前DB結果の保存先／設定した更新者名 | |
| 実行前のlog.txtの有無・最終行／復元方法 | |

【開始時の状態】
ツールは未起動。設定先が検証DBであることを確認し、対象データの他者更新を停止する。
```

### 操作内容
```
1. 用語表のDB照会SQLへA・B・Uを入れ、6結果を「実行前」として保存する。log.txtがあれば最終行を控える。
2. 実行用EXEを開き、画面タイトル「保守契約管理システムサポートID付け替え」を確認する。
3. 「付け替え元サポートID」へAを入力してTabを押す。「付け替え元納入先」を試験データ表と照合する。
4. 「付け替え先サポートID」へBを入力してTabを押す。「付け替え先納入先」が空欄であることを確認する。
5. 「開始」を押す。「開始確認」の「開始してよろしいですか？」に「OK」を押す。
6. 画面下部に「【開始】処理を終了しました」が出たら、画面を記録する。入力欄を移動して再照会する前に記録する。
7. 手順1と同じSQLを実行して「実行後」として保存し、実行前の主キーごとに期待結果と照合する。
8. EXEと同じフォルダーのlog.txtを開き、手順1で控えた位置より後の今回の実行分を確認する。

【入力値】
付け替え元サポートID＝A、付け替え先サポートID＝B、開始確認＝OK。
```

### 期待結果
```
【画面確認】
・元納入先は準備値と一致し、未使用Bの先納入先は空欄。
・画面下部に「【開始】処理を終了しました」が表示される。完了ダイアログを待たない。

【ファイル確認】
・log.txtの今回分に「 START 」「以降の更新記録はコミット完了まで確定前です」、対象表の更新記録がある。
・「コミット完了：更新を確定しました」の後に「  END  」を含む行がある。0件の表は「更新対象なし」の記録となる。

【DB確認】
・実行前にAだった5表の対象行は、同じ主キーのままSUPPORT_ID＝Bとなる。各表の行数は変わらず、行の追加・削除はない。
・対象PLANTのDTSRENKEI_FLGと、同プラントが参照する納入先のDTSRENKEI_FLGは0。
・更新した行のLASTUPDATE_DTは更新前がNULLなら非NULL、非NULLなら更新前より後。LASTUPDATE_BYは設定した更新者名。
・記録したPLANT_ID・NONYUSAKI_IDの関連付けは変わらない。対象外Uの照会列は更新前と一致する。
・0件だった表に行が追加されない。その表の更新分岐を合格済みにはしない。
```

### 期待メッセージ
```
1. 表示タイミング＝「開始」押下時。
表示形式＝確認ダイアログ（タイトル「開始確認」、OK／キャンセル）。
メッセージID＝－。
表示文言＝開始してよろしいですか？
作業者操作＝入力した元・先を確認してOKを押す。

2. 表示タイミング＝更新を確定し、終了ログ出力後。
表示形式＝画面下部のメッセージ欄。
メッセージID＝－。
表示文言＝【開始】処理を終了しました
作業者操作＝画面を記録し、DBとログを照合する。
```

### 備考
旧仕様の対象5表と納入先のDTS連携フラグ更新を維持する。133の更新日時・更新者とコミット明示ログは移行版の追加確認。正常表示だけで更新結果を判定しない。Web再表示・DTS連携先での反映は結合テストで確認する。

## TL31-002

### 項番
TL31-002

### テスト項目
TL31（サポートID付替プログラム）：既存の付替先IDを指定でき、先IDの既存行を削除・統合せず、元IDの対象だけを付け替えること。

### 前提条件
```
実施区分＝通常（既存の元・先と更新許可確保後）。

【この試験で確認すること】
付替先に既存データがある場合の表示と更新範囲。

【実施する人】
・実施者（操作とDB・ログ照合をする人）。
・準備担当者（元・先の対象行と更新前値を準備する人）。

【実施者に必要なもの】
・設定済みの133の実行用一式、SSMS等の読み取り照会、復元方法。

【準備担当者が用意するデータ】
別の試験で付替済みでない7桁の元Aと、Aと異なる既存7桁の先Bを選ぶ。両方が納入先表示できること。
用語表のSQLでA・Bと対象外Uを照会し、各表の実行前主キー・値・件数を保存する。
AとBが同じ納入先IDを参照する場合、その納入先はフラグ・更新日時・更新者の更新対象として区別する。
「同じBになるから行をまとめる」という期待値を作らない。

試験データ表：
| A／元納入先ID：名 | |
| B／既存先納入先ID：名 | |
| U／対象外の主キーと納入先ID | |
| 各表の元Aの主キー・件数／元からBへ変わる期待値 | |
| 各表の既存Bの主キー・件数／Aと共有する納入先ID | |
| 実行前DB結果・ログ位置／更新者名／復元方法 | |

【開始時の状態】
検証用の対象データへの並行更新を停止し、実行前値を保存済み。
```

### 操作内容
```
1. 実行用EXEを開く。「付け替え元サポートID」へAを入力してTabを押し、元納入先を照合する。
2. 「付け替え先サポートID」へBを入力してTabを押す。先納入先が試験データ表の既存Bの表示と一致することを確認する。
3. 「開始」を押し、「開始してよろしいですか？」に「OK」を押す。
4. 下部に「【開始】処理を終了しました」が出たら画面を記録する。
5. 用語表のDB照会SQLで実行後値を保存し、元Aだった行と初めからBだった行を主キーで分けて照合する。
6. log.txtの今回分に、元A・先Bの更新記録と確定・終了の記録があることを確認する。

【入力値】
付け替え元サポートID＝A、付け替え先サポートID＝既存B、開始確認＝OK。
```

### 期待結果
```
【画面確認】
・既存Bの先納入先が納入先ID：名で表示され、Bが登録済みという理由だけで付替えを拒否しない。
・画面下部に「【開始】処理を終了しました」が表示される。

【ファイル確認】
・今回のlog.txtに旧SUPPORT_ID＝A・新SUPPORT_ID＝Bの更新記録、および「コミット完了：更新を確定しました」「  END  」がある。

【DB確認】
・5表の元Aの対象行は同じ主キーのままBへ変わり、全体の行数は変わらない。元AのPLANTと参照先納入先のDTSRENKEI_FLGは0。
・初めからBだった5表の行は、SUPPORT_ID・PLANT_ID・更新日時・更新者等、用語表の照会列が実行前と同じ。主キーの統合・削除はない。
・AとBが共有する納入先行のDTSRENKEI_FLG＝0と更新日時・更新者の変更は正当な更新として扱う。Aの対象外の納入先行は変わらない。
・更新対象の日時は進み、更新者は設定値。対象外Uの照会列と、既存Bの各表の件数は実行前と一致する。
```

### 期待メッセージ
```
1. 表示タイミング＝「開始」押下時。
表示形式＝確認ダイアログ（タイトル「開始確認」、OK／キャンセル）。
メッセージID＝－。
表示文言＝開始してよろしいですか？
作業者操作＝OKを押す。

2. 表示タイミング＝更新確定・終了ログ出力後。
表示形式＝画面下部のメッセージ欄。
メッセージID＝－。
表示文言＝【開始】処理を終了しました
作業者操作＝画面・DB・ログを確認する。
```

### 備考
001は未使用先、002は既存先の保持を目的とする。プラント・契約の関連付けをB側へまとめる機能ではない。既存Bの納入先を一律に対象外として、正当な共有納入先更新を不合格にしない。

納入先表示できる既存Aと、Aと異なる既存B、対象外Uを選ぶ。
未登録Zは5つのSUPPORT_ID保有表に存在しない7桁と確認する。DBへZを登録しない。
用語表のSQLでA・B・Uの実行前値と、log.txtの最終行を控える。

試験データ表：
| A／B／U／未登録Z | |

5. 「終了」を押し、終了確認で「OK」を押して閉じる。次の条件は手順1から別に実施する。4行それぞれの結果を記録する。

【入力値】
条件表の各行の元・先を使用する。開始確認＝OK。
