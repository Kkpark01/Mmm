# 試験準備の共通方針

対象16ツール・76ケースを、**検証DBの既存データから選ぶ**方式で準備する。DBへ試験用の見積・契約・品名等を新規登録せず、試験条件に合わせて既存値を改名・変更しない。

## 準備から実施まで

1. **対象版と接続先を確かめる。** 使用するファイル・会社編集版の識別情報・設定先を記入する。仕様書が想定するSQL修正を含むかも記録する。パスワードは書かない。
2. **既存データを選ぶ。** 各ケースの条件を満たす見積No・契約番号・支払月・検索語等を、画面または読み取り専用SQLで確認する。語を入力できる検索では、数件～数十件程度へ絞れる語を優先する。全件取得しかない機能へ架空の絞込みを追加しない。
3. **入力値と期待値を記入する。** 入力文字列をそのまま貼れる形で控える。必要な結合・状態・期間・GROUP BY・並びを反映した全件数を求め、判定に使う全行または代表値をケースの表へ記す。マクロの実行結果から期待値を逆算しない。
4. **開始時点を整える。** 原紙・対応表・参照ファイル・前回結果・出力先を試験コピーに用意する。前回表示が必要なら、既存データの正常取得をコピーに保存して確認する。配布ファイルに結果が残っているとは仮定しない。
5. **実施者へ渡す。** 準備記録とケースの試験データ表が埋まった後、本文の操作を進める。準備未完なら開始しない。

## 固定値を使わない判定

- A・B・X等は、各ケースの中で選んだ実在対象に付ける呼び名。全ツールで同じ対象を指すものではない。
- Q・K・P等は既存データから選んだ入力文字列。文字の大小・全角半角を確認するときは、変換後の入力も表へ記入する。
- Nはその入力に対する全期待件数。同じ検索語で代表以外の行が一致するなら、その行も期待集合へ含める。代表を3件選んだから出力も3件、とはしない。
- 数量・金額・日付・保守条件は選んだ対象の既存値を維持する。2・1・1や8／24等の見本に合わせてDB値を変更しない。入力欄で選べる時間は、既存対象に合わせて選ぶ。
- 出力の行番号が変動する場合は、準備した出力期待表や契約番号・品名・型式等で確認先を特定する。固定の架空名を探さない。

## 条件が見つからない場合

| 状態 | 扱い |
|---|---|
| 基本の取得対象や期待値が用意できない | 準備未完。試験を開始しない |
| 複数構成・先頭0・別状態の除外候補など一部だけない | 確認できる部分と未確認の分岐を分けて記録。同じケースを別の既存入力で補完してよい |
| 必須の確認観点を補完できない | ケース全体を無条件に合格にしない。未確認範囲を残して試験管理者へ示す |
| 旧版と同時点のデータを揃えられない | 現行比較は実施不可。空結果同士の一致で代替しない |
| 境界値・全体0件・取得失敗等を共有DBで作れない | 本文／確認観点対応の割当てに従い、開発者の独立テストまたは未確認として扱う |

新規登録やDBの直接変更で不足条件を埋めない。原紙を退避・加工して作るエラーは、本文が指示する専用コピーだけで行う。

TL31の付替え機能によるDB更新は試験対象そのもの。準備のための改名・新規登録とは区別し、更新許可・実行前値・復元方法を先に確保する。
