# TL12（見積実績検索） 単体テスト仕様書

準備方針：[共通方針と準備記録](../00_試験準備の共通方針.md)。このケースで使う既存入力値・期待件数・対象版を準備担当者が記入する。DBの試験データ新規登録は行わない。

対象：見積実績検索ver1.2.xlsm（改修版）。シート「問合せ」で機器型式・機器品名・製造メーカ・見積時間を入力して「問合せ実行」を押すと、新MCM（SQL Server）から状態が見積の取引先見積を探し、10行目から下に12列で表示する。DBは読むだけで、更新しない。

凡例：
- 実施者：試験を行う人。Excelでツールを実行し、シートの表示を確認する。
- 準備担当者：検証DBの既存見積から選び、入力値と期待結果を記入する人。
- 試験データ表：準備担当者が、選定した既存の取引先見積の12列の値を書く表。各ケースの前提条件にある。
- 各ケースの「前提条件」「操作内容」「期待結果」は、そのケースだけを読んで実施できるように書いてある。他のケースは参照しない。
- 準備未完なら開始しない。見つからない分岐は未確認と記録し、合格へ読み替えない。
- このツールにはメッセージIDがないため、期待メッセージの「メッセージID」は「－」とする。
- 実施区分：通常／要確認／開発者テスト／実施不可／除外候補（test-spec-common-rules.md 14.7章）

項番の欠番：

## TL12-001

### 項番
TL12-001

### テスト項目
TL12(見積実績検索)：機器型式1に型式の一部を小文字で入力すると、大文字・小文字を区別せずに部分一致で探し、状態が見積の取引先見積だけが12列で、決まった順に表示されること

### 前提条件
```
実施区分＝通常（既存データと期待表の準備後）。

【この試験で確認すること】
既存文字列の小文字・大文字で同じ見積結果を得て、状態・12列・並び順を確認すること。

【実施する人】
・実施者（操作・表示と期待値を照合する人）。
・準備担当者（検証DBの既存データを読み取り、入力値・期待表を用意する人。試験データは新規登録しない）。

【実施者に必要なもの】
・Excelでマクロを実行できるPCと、「12_見積実績検索」の試験用コピー一式（見積実績検索ver1.2.xlsm・Mcm移行部品・原紙を含む）。
・MSOLEDBSQL19等、対象版が指定するドライバーと、会社で確認した検証DB接続設定。
・SQL認証の場合はMCM_MACRO_DB_USER・MCM_MACRO_DB_PASSWORDを準備する。パスワードは記録しない。
・準備記録の対象版・サーバー・DBが試験コピーの設定と一致すること。

【準備担当者が用意するデータ】
既存の型式から半角英字を含む検索語Qを選び、小文字形Q小と大文字形Q大をそのまま試験表に記す。LIKEの特殊文字（%・_・[等）を含まない語を使い、少数の結果に絞れる語を優先する。
条件は契約時間の状態＝見積、必要な結合先あり、型式にQを含むもの。出力される全行を12列の組で集約した期待表を作り、件数Nと並びを求める。選んだ代表以外にも一致する行は期待件数から除かない。
ﾊﾟｯｸ契約の昇順（NULLは最後）、同じ値では作成日の降順（NULLは先頭）。同順位内の順序は固定しない。正常検索用のNは1件以上とし、必要な状態・結合先を満たす対象がない場合は準備未完とする。
可能なら、同じ語に一致する契約状態の除外候補、異なるﾊﾟｯｸ値、同じﾊﾟｯｸで異なる作成日、先頭0のサポートIDを含める。なければ該当分岐を未確認とする。別の既存検索語で補ってもよい。
試験データ表：
| Q小／Q大／検索対象の型式／期待件数N | |
| 期待する全N行の12列と並びを記録した表 | |
| 除外候補のDB識別子・表示で区別する値・除外理由 | |
| 各並び・先頭0を確認できる既存対象／確認できない分岐 | |
全行の12列：サポートID・出荷先名・見積作成日・取引先見積依頼No・保守契約時間帯・取引先名・製造メーカ・品名・型式・ﾊﾟｯｸ契約・標準価格・仕切金。

【開始時の状態】
試験用コピーを使用し、Excelを起動していなくてよい。
```

### 操作内容
```
1. 試験コピーの設定ファイルを開き、準備記録の検証接続先と一致することを確認する。
2. 見積実績検索ver1.2.xlsmを開き、「問合せ」を選ぶ。マクロは会社の実行ルールに従う。
3. C2:C7をDeleteで空にする。
4. C2（機器型式1）へ試験データ表のQ小を入力する。
5. 「問合せ実行」を押し、取得中の表示が終わるまで待つ。
6. B10:M10と11行目以降をN件の期待表に照合する。数値列は数式バーの値、日付は日付値と表示を確認する。
7. 同じ欄だけQ大に置き換えて再実行し、件数・12列の行集合・並びの基準がQ小の時と同じであることを確認する。
8. 保存せず閉じる。

【入力値】
C2＝Q小、次にQ大。ほかのC2:C7はすべて空欄。
```

### 期待結果
```
【画面確認】
1. B10:M10に12見出し（サポートID・出荷先名・見積作成日・取引先見積依頼No・保守契約時間帯・取引先名・製造メーカ・品名・型式・ﾊﾟｯｸ契約・標準価格・仕切金）が表示され、11行目からN件。N件より下に旧結果を残さない。
2. Q小・Q大のどちらでも期待する全N行の12列が一致する。固定の3件・指定の架空品名順では判定しない。
3. ﾊﾟｯｸ契約の昇順、同値では作成日の降順。同順位内の不定順を誤りにしない。
4. 準備した契約状態の除外候補は出ない。準備できなかった除外・並び分岐は未確認として記録する。
5. サポートIDは期待する文字列で、先頭0がある対象はその0を維持する。作成日表示はyyyy/mm/ddで、日付値も期待表と一致する。
6. 見出しは灰色、B10から最終結果行までのB:Mに格子罫線がある。Q大へ再検索しても前回の結果を追加表示しない。

【DB確認】
実施不要（参照のみ。期待集合の準備には読み取り照会を使う）。
```

### 備考
```

【根拠】改修版 見積実績検索ver1.2.xlsm。取引先見積検索モジュール SimpleQuery → McmNewDb.McmExportSqlServer "T09"。見積時間が空欄のため、内蔵SQL queries/T09_00_1_01.sql を使う（Jobs1）。たどるテーブル：MCM_TM_MITSUMORI → MCM_TM_KEIYAKUJIKAN（TM_IRAI_ID）、MCM_TM_KIKIKOSEI（TM_IRAI_ID）→ MCM_TM_KIKIMEISAI、単価は MCM_TM_KIKAN（契約時間）と MCM_TM_TANKA（期間と機器明細）。抽出条件：MCM_TM_KEIYAKUJIKAN.JOTAI＝1、UPPER(型式) COLLATE Latin1_General_BIN2 LIKE UPPER('%入力値%')。並び順：PACK_FLG の小さい順（空は最後）→ MITSUMORI_DT の新しい順。列の型：Array(2,2,5,2,1,2,2,2,2,1,1,1)。
```

## TL12-002

### 項番
TL12-002

### テスト項目
TL12(見積実績検索)：複数の欄に入力すると、どれかに当たる取引先見積が表示され、見積時間を入れると、その保守契約時間帯の行だけに絞り込まれること

### 前提条件
```
実施区分＝通常（既存データと期待表の準備後）。

【この試験で確認すること】
型式と品名のOR、見積時間のANDで、対象集合と除外行を判定すること。

【実施する人】
・実施者（操作・表示と期待値を照合する人）。
・準備担当者（検証DBの既存データを読み取り、入力値・期待表を用意する人。試験データは新規登録しない）。

【実施者に必要なもの】
・Excelでマクロを実行できるPCと、「12_見積実績検索」の試験用コピー一式（見積実績検索ver1.2.xlsm・Mcm移行部品・原紙を含む）。
・MSOLEDBSQL19等、対象版が指定するドライバーと、会社で確認した検証DB接続設定。
・SQL認証の場合はMCM_MACRO_DB_USER・MCM_MACRO_DB_PASSWORDを準備する。パスワードは記録しない。
・準備記録の対象版・サーバー・DBが試験コピーの設定と一致すること。

【準備担当者が用意するデータ】
既存データから型式検索語K・品名検索語P・時間H（8または24）を選ぶ。LIKEの特殊文字を含まない語を使う。
各実行セットは正常な対象が1件以上ある条件とする。状態＝見積と必要な結合条件を満たし、（型式にKを含む、または品名にPを含む）かつ時間＝Hの全行を12列でGROUP BYした期待表と件数Nを求める。

1回の検索で揃わなければ、別のK・P・Hの既存セットで不足分を再実施してよい。各実行の期待表を分ける。確保できない確認は未確認とし、架空の見積を作らない。
試験データ表（実行ごと）：
| K／P／H／全期待件数N・12列期待表の保存先 | |
| 型式だけに一致する表示識別値／品名だけに一致する表示識別値 | |
| 検索語には一致する別時間の除外行と時間 | |
| 確認済みにできるOR・ANDの条件／未確認理由 | |

【開始時の状態】
試験用コピーを使用し、Excelを起動していなくてよい。
```

### 操作内容
```
1. 試験コピーの見積実績検索ver1.2.xlsmを開き、「問合せ」を選ぶ。
2. C2:C7をDeleteで空にする。
3. C2（機器型式1）へK、C4（機器品名1）へPを入力し、C7の一覧でHを選ぶ。
4. 「問合せ実行」を押し、取得が終了するまで待つ。
5. N件の全期待行と、OR確認用2種類・時間による除外行を照合する。補完用の別セットがある場合は、手順2から独立して再実施する。
6. 保存せず閉じる。

【入力値】
C2＝K、C4＝P、C7＝H。C3・C5・C6＝空欄。
```

### 期待結果
```

1. B10:M10は12見出し、11行目からN件の全期待行が表示され、それより下に旧結果が残らない。
2. 型式だけに一致する行と品名だけに一致する行が両方表示される。両方に一致する行を重複して数えない。
3. 出力のF列（保守契約時間帯）は全行Hで、検索語に一致しても時間がH以外の準備した除外行は出ない。
4. 固定の2件・時間24を要求しない。別セットで補った場合も、実行ごとの期待表に一致する。確保できなかったOR・ANDの分岐は未確認と記録する。

【DB確認】
実施不要（参照のみ、DB更新なし）。
```

TL12-003

```
既存の半角検索語が全角と区別され、正常0件時に前回結果が消えること。

・実施者（操作・表示と期待値を照合する人）。
```
