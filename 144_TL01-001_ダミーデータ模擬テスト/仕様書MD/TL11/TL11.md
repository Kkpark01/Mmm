# TL11（店舗見積実績検索） 単体テスト仕様書

準備方針：[共通方針と準備記録](../00_試験準備の共通方針.md)。このケースで使う既存入力値・期待件数・対象版を準備担当者が記入する。DBの試験データ新規登録は行わない。

対象：店舗見積実績検索ver1.2.xlsm（改修版）。シート「問合せ」で機器型式・機器品名・製造メーカ・見積時間を入力して「問合せ実行」を押すと、新MCM（SQL Server）から状態が見積の店舗見積を探し、10行目から下に12列で表示する。DBは読むだけで、更新しない。

凡例：
- 実施者：試験を行う人。Excelでツールを実行し、シートの表示を確認する。
- 準備担当者：検証DBの既存見積から選び、入力値と期待結果を記入する人。
- 試験データ表：準備担当者が、選定した既存の店舗見積の12列の値を書く表。各ケースの前提条件にある。
- 各ケースの「前提条件」「操作内容」「期待結果」は、そのケースだけを読んで実施できるように書いてある。他のケースは参照しない。
- 準備未完なら開始しない。見つからない分岐は未確認と記録し、合格へ読み替えない。
- このツールにはメッセージIDがないため、期待メッセージの「メッセージID」は「－」とする。
- 実施区分：通常／要確認／開発者テスト／実施不可／除外候補（test-spec-common-rules.md 14.7章）

項番の欠番（旧→新）：

| 旧項番 | 新項番 | 内容 |
|---|---|---|
| 004 | 003 | 当たる見積が0件のときの表示を、TL11-003 に統合した（全角で入力して合格のとき、0件になるため）。004 は欠番 |

## TL11-001

### 項番
TL11-001

### テスト項目
TL11(店舗見積実績検索)：機器品名1に品名の一部を小文字で入力すると、大文字・小文字を区別せずに部分一致で探し、状態が見積の店舗見積だけが12列で、決まった順に表示されること

### 前提条件
```
実施区分＝通常（既存データと期待表の準備後）。

【この試験で確認すること】
既存文字列の小文字・大文字で同じ見積結果を得て、状態・12列・並び順を確認すること。

【実施する人】
・実施者（操作・表示と期待値を照合する人）。
・準備担当者（検証DBの既存データを読み取り、入力値・期待表を用意する人。試験データは新規登録しない）。

【実施者に必要なもの】
・Excelでマクロを実行できるPCと、「11_店舗見積実績検索」の試験用コピー一式（店舗見積実績検索ver1.2.xlsm・Mcm移行部品・原紙を含む）。
・MSOLEDBSQL19等、対象版が指定するドライバーと、会社で確認した検証DB接続設定。
・SQL認証の場合はMCM_MACRO_DB_USER・MCM_MACRO_DB_PASSWORDを準備する。パスワードは記録しない。
・準備記録の対象版・サーバー・DBが試験コピーの設定と一致すること。

【準備担当者が用意するデータ】
既存の品名から半角英字を含む検索語Qを選び、小文字形Q小と大文字形Q大をそのまま試験表に記す。LIKEの特殊文字（%・_・[等）を含まない語を使い、少数の結果に絞れる語を優先する。
条件は店舗基本見積の状態＝見積、必要な結合先あり、品名にQを含むもの。出力される全行を12列の組で集約した期待表を作り、件数Nと並びを求める。選んだ代表以外にも一致する行は期待件数から除かない。
ﾊﾟｯｸ契約の昇順（NULLは最後）、同じ値では作成日の降順（NULLは先頭）。同順位内の順序は固定しない。正常検索用のNは1件以上とし、必要な状態・結合先を満たす対象がない場合は準備未完とする。
可能なら、同じ語に一致する契約状態の除外候補、異なるﾊﾟｯｸ値、同じﾊﾟｯｸで異なる作成日、先頭0のサポートIDを含める。なければ該当分岐を未確認とする。別の既存検索語で補ってもよい。
試験データ表：
| Q小／Q大／検索対象の品名／期待件数N | |
| 期待する全N行の12列と並びを記録した表 | |
| 除外候補のDB識別子・表示で区別する値・除外理由 | |
| 各並び・先頭0を確認できる既存対象／確認できない分岐 | |
全行の12列：サポートID・出荷先名・見積作成日・取引先見積依頼No・保守契約時間帯・取引先名・製造メーカ・品名・型式・ﾊﾟｯｸ契約・標準価格・仕切金。

【開始時の状態】
試験用コピーを使用し、Excelを起動していなくてよい。
```

### 操作内容
```
1. 試験コピーの設定ファイルを開き、準備記録の検証接続先と一致することを確認する。
2. 店舗見積実績検索ver1.2.xlsmを開き、「問合せ」を選ぶ。マクロは会社の実行ルールに従う。
3. C2:C7をDeleteで空にする。
4. C4（機器品名1）へ試験データ表のQ小を入力する。
5. 「問合せ実行」を押し、取得中の表示が終わるまで待つ。
6. B10:M10と11行目以降をN件の期待表に照合する。数値列は数式バーの値、日付は日付値と表示を確認する。
7. 同じ欄だけQ大に置き換えて再実行し、件数・12列の行集合・並びの基準がQ小の時と同じであることを確認する。
8. 保存せず閉じる。

【入力値】
C4＝Q小、次にQ大。ほかのC2:C7はすべて空欄。
```

### 期待結果
```
【画面確認】
1. B10:M10に12見出し（サポートID・出荷先名・見積作成日・取引先見積依頼No・保守契約時間帯・取引先名・製造メーカ・品名・型式・ﾊﾟｯｸ契約・標準価格・仕切金）が表示され、11行目からN件。N件より下に旧結果を残さない。
2. Q小・Q大のどちらでも期待する全N行の12列が一致する。固定の3件・指定の架空品名順では判定しない。
3. ﾊﾟｯｸ契約の昇順、同値では作成日の降順。同順位内の不定順を誤りにしない。
4. 準備した契約状態の除外候補は出ない。準備できなかった除外・並び分岐は未確認として記録する。
5. サポートIDは期待する文字列で、先頭0がある対象はその0を維持する。作成日表示はyyyy/mm/ddで、日付値も期待表と一致する。
6. 見出しは灰色、B10から最終結果行までのB:Mに格子罫線がある。Q大へ再検索しても前回の結果を追加表示しない。

【DB確認】
実施不要（参照のみ。期待集合の準備には読み取り照会を使う）。
```

```

表示形式＝－
メッセージID＝－
表示文言＝－
作業者の操作＝－
```

### 備考
```
【実施区分】通常
【根拠】改修版 店舗見積実績検索ver1.2.xlsm。取引先見積検索モジュール SimpleQuery → McmNewDb.McmExportSqlServer "T07"。見積時間が空欄のため、内蔵SQL queries/T07_00_1_01.sql を使う（Jobs1）。抽出条件：MCM_UM_KIHON_MITSUMORI.JOTAI＝1、UPPER(品名) COLLATE Latin1_General_BIN2 LIKE UPPER('%入力値%')。並び順：PACK_FLG の小さい順（空は最後）→ MITSUMORI_DT の新しい順。列の型：Array(2,2,5,2,1,2,2,2,2,1,1,1)（McmWriteResult。5＝日付 yyyy/mm/dd、2＝文字列）。見出し：Jobs1 の AddHeaders。
【確認していないこと】絞り込みボタン（実行のたびに表示と非表示が切り替わるため）、列幅、数値の列の表示形式（マクロが設定せず、セルに残っている書式で表示されるため）、同じ内容の行が1行にまとまること（TL11-006で差が出れば分かる）。
【要確認】選定した既存の店舗見積について、ブランド、機器構成、機器明細、見積、単価がそろうか（どれかが欠けると表示されない）。ﾊﾟｯｸ契約に入る値の種類（0とそれ以外）。マクロを有効にする帯と、保存するかの確認のボタン名、画面左下の「準備完了」の表示（Excelの版で表示が異なる）。
【実施できないとき】先頭が「0」のサポートIDのプラントがない場合は、期待結果6を外して実施し、そのことを記録する。
【不合格のとき】10行目から下の表示をそのまま画面の写しで記録する。
```

準備統一：表示の12列が同じ行をGROUP BYする前提で全期待集合を作る。実装の結果件数をそのまま期待値へ転記しない。

## TL11-006

TL11-006

TL11(店舗見積実績検索)：同じ時点のデータで、元のツールと改修版の検索結果が一致すること
