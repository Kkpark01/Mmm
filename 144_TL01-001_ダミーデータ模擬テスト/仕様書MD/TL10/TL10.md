# TL10（納入機器登録確認） 単体テスト仕様書・本文案

準備方針：[共通方針と準備記録](../00_試験準備の共通方針.md)。このケースで使う既存入力値・期待件数・対象版を準備担当者が記入する。DBの試験データ新規登録は行わない。

対象：131の13「納入機器登録確認ver2.5.xlsm」。主要4ケース。3種類の取得結果の連結・検索・代表指摘・新規結果ブックと保存を確認する。会社編集版・実DB・業務マクロ実行は未確認。

凡例：
- 実施者：Excelを操作して、表示・結果ブックを確認する人。
- 準備担当者：検証DBの既存データと追加パーツ表から、試験データ表を記入する人。DBへ試験用登録を行わない。
- 試験データ表：実施前に期待値を記入し、結果を見て逆算しない。該当データや期待値が未準備なら「準備未完」とする。
- 各ケースは独立した試験用コピーで行う。結果は新しいブックへ移り、自動保存されない。
- メッセージIDはすべて「－」。実施区分は通常／要確認／開発者テスト／実施不可／除外候補。
- [用語表](用語表.md)に表示名・列・メッセージ、[骨子](骨子.md)に範囲と補助候補を記載する。003の入力チェック等は補助、005の保存は001へ含め、007は共通エラー範囲確認待ち。

## TL10-001

### 項番
TL10-001

### テスト項目
TL10（納入機器登録確認）：サポートIDを1件指定すると、3種類の取得結果が正しい位置に連結され、新しい結果ブックを保存・再読込できること。

### 前提条件
```
実施区分＝通常（既存データ確保後）。

【この試験で確認すること】
単一検索、31列の連結、B2からの表示、代表値・並び順と結果ブックの保存。

【実施する人】
・実施者（検索・照合・結果保存を行う人）。
・準備担当者（3種類が取得できる既存サポートIDと期待値を用意する人）。

【実施者に必要なもの】
・マクロを実行できるExcelと、検証DB接続・認証・ドライバーを準備した13_納入機器登録確認の試験用フォルダー一式。
・同梱の追加パーツ適用表.xlsx。単独適用パーツ表・複合適用パーツ表・延長パーツの3シートがあり、閉じていること。
・試験結果用の保存フォルダー。既存ファイルと重ならない保存名を使う。

【準備担当者が用意するデータ】
99で始まらない既存サポートID Sを選び、SQL3本すべてに1件以上あり、全体の照合が指摘なしで完了することを確認する。データが少ない対象を優先する。
N1・N2・N3は各SQLの件数とし、N＝N1＋N2＋N3を記入する。違う種類の行を同じ機器の重複として除去しない。
各種類の代表行を、サポートID・プラント名・出力後の構成No・機器側No・個体側Noで区別して控える。個体行の先頭0を含む製番も文字列で控える。

試験データ表：
| サポートID S／N1／N2／N3／合計N | |
| 代表の3行：プラント名／構成No／機器側No／個体側No | |
| 納入先コード・名／機器構成名／機器品名・型式／数量 | |
| 個体側の型式／シリアル番号／一次納入日／契約期限 | |
| 追加パーツ表のフルパス・版／指摘なしを確認した根拠 | |
| 結果の保存先フォルダー／保存名（例：TL10_001_確認結果.xlsx） | |

【開始時の状態】
Excelを起動していなくてよい。追加パーツ表は閉じておく。マクロ本体の試験用コピーを使う。
```

### 操作内容
```
1. 試験用の納入機器登録確認ver2.5.xlsmを開き、「操作シート」を選ぶ。
2. C2:C5の検索欄を空にし、C2（サポートID1）へSを入れる。E6（追加パーツ表保存場所）へ、準備した同梱コピーのフルパスを入力する。
3. 「納入機器 登録状態確認」（E2付近）を押す。終了通知を記録して「OK」を押す。
4. 新しく開かれた結果ブックの「納入機器」を選ぶ。B2:AF2が31列の見出し、3行目以降がN件であり、途中に同じ見出しがデータとして混ざっていないことを確認する。
5. D列サポートID・E列プラント名・F列構成No・J列機器側No・Q列個体側Noで、準備した3種類の代表行を探す。B・C・G・M・N・P、個体行のU・V・Y・AAを準備値と照合する。
6. B→D→E→F→J→Qの優先順で昇順になっていること、A列に×がなく、指摘なしの通知と一致することを確認する。
7. 結果ブックを選択した状態で「名前を付けて保存」を行い、準備した場所・名前でExcelブック（.xlsx）として保存する。マクロ本体を保存する操作と混同しない。
8. 結果ブックを閉じて保存ファイルを開き直し、「納入機器」の見出し・件数・代表値が保存されていることを確認する。
9. 結果を閉じる。元の試験用マクロは保存せずに閉じる。

【入力値】
C2＝S、C3:C5＝空欄。E6＝試験用追加パーツ適用表.xlsxのフルパス。
```

### 期待結果
```
【画面確認】
・指摘なしの終了通知が表示され、「納入機器」が新しいブックに移る。元のマクロに結果シートが残ることは期待しない。
・見出しは2行目、明細は3行目からN1＋N2＋N3件。31列のずれ・途中の見出し混入がない。
・B＝納入先コード、C＝納入先名、D＝サポートID、E＝プラント名、F＝構成No、G＝機器構成名が準備値と一致する。
・M＝機器品名、N＝機器型式、P＝数量、個体行のU＝型式、V＝シリアル番号、Y＝一次納入日、AA＝契約期限が一致する。先頭0が欠けない。
・最終並び順がB・D・E・F・J・Qの昇順で、A列に×がない。

【ファイル確認】
・手動保存したxlsxが指定先にあり、再読込後もシート・件数・代表値を保持する。自動保存されたと判断しない。

【DB確認】
実施不要（参照とブック内照合のみ。DBやパーツ表の原本は更新しない）。
```

### 期待メッセージ
```
表示タイミング＝照合が完了し、新しい結果ブックが作られた時。
表示形式＝Excelメッセージボックス（情報）。
タイトル＝納入機器確認終了
メッセージID＝－。
表示文言＝不正データは見つかりませんでした。
作業者操作＝通知を記録し「OK」を押す。その後、結果ブックを保存する。
```

### 備考
同じキー内の同順位行まで固定順とは保証しない。構成Noは出力時に先頭8文字が取り除かれるため、準備値は最終表示のNoで控える。指摘なしの実在対象が確保できなければ準備未完とし、指摘ありを合格へ読み替えない。

## TL10-002

### 項番
TL10-002

### テスト項目
TL10（納入機器登録確認）：サポートIDと納入先コードのOR条件で取得し、片方を消して再検索すると残した条件だけで取得すること。

### 前提条件
```
実施区分＝通常（既存データ確保後）。

【この試験で確認すること】
C2:C5の条件がANDでなくORで働き、空欄へ戻した条件を再利用しないこと。

【実施する人】
・実施者（複合条件と単独条件で取得する人）。
・準備担当者（片側だけで取得される行を特定する人）。

【実施者に必要なもの】
・検証DB接続を準備した13フォルダー一式、マクロを実行できるExcel。
・閉じた状態の同梱追加パーツ適用表と、そのフルパス。

【準備担当者が用意するデータ】
既存サポートID Sと、別の対象に一致する納入先コードCを選ぶ。部分一致と99始まり除外を考慮し、「Sだけに一致」「Cだけに一致」の行をそれぞれ1件以上確保する。
両回とも構成・機器明細・個体の3種類を含む小規模な既存対象を選び、0件・最小1行の境界確認とは分ける。
OR条件の3SQL合計件数N_ORと、S単独の合計N_S、代表行のキー・値を記入する。対象データに指摘があれば、用語表の5行のうち実際に期待する指摘文を準備しておく。

試験データ表：
| S／C／OR時の件数N_OR／S単独件数N_S | |
| Sだけに一致する代表行のD・E・F・J・Qと品名 | |
| Cだけに一致する代表行のD・E・F・J・Qと品名 | |
| 各回の終了通知：指摘なし、または期待する指摘文の一覧（表示順） | |
| パーツ表のフルパスと版 | |

【開始時の状態】
独立した試験用コピーを使い、取得中にDBとパーツ表を変更しない。
```

### 操作内容
```
1. 試験用ブックの「操作シート」を開く。C2:C5を空にし、C2にS、C4にCを入れる。E6にパーツ表のフルパスを入力する。
2. 「納入機器 登録状態確認」を押し、終了通知を記録して「OK」を押す。
3. 新しい結果ブックで件数N_ORと、Sだけ・Cだけに一致する両方の代表行を確認する。期待した指摘文とも照合する。エビデンスを控え、1回目の結果ブックを保存せずに閉じる。
4. 元のマクロの「操作シート」へ戻り、C4だけを空にする。C2のSとE6は維持して再度実行する。
5. 2回目の新しい結果ブックでN_S件となり、Cだけに一致する代表行が存在しないことを確認する。通知も準備値と照合する。
6. 結果を記録し、結果ブックと試験用マクロは保存せずに閉じる。

【入力値】
1回目：C2＝S、C4＝C、C3・C5＝空欄。
2回目：C2＝S、C3:C5＝空欄。
```

### 期待結果
```
【画面確認】
・1回目はOR条件のN_OR件となり、両方の代表行が含まれる。両条件に共通する行がある場合、同じSQL内で条件数分に重複しない。
・2回目はN_S件となり、Cだけの代表行が含まれない。
・各回で新しい納入機器ブックが作られ、終了通知の指摘内容が準備値と一致する。

【DB確認】
実施不要（2回とも参照とローカル照合のみ）。
```

### 期待メッセージ
```
表示タイミング＝各回の照合完了後。
表示形式＝Excelメッセージボックス。指摘なしは情報、ありは警告。
タイトル＝納入機器確認終了
メッセージID＝－。
指摘なしの文言＝不正データは見つかりませんでした。
指摘ありの文言＝「下記の問題点がありました。」、空行、試験データ表の指摘文を次の順に表示：
　・終息日の確認が必要な機器があります。
　・追加パーツの確認が必要な機器があります。
　・一次納入日の確認が必要な機器があります。
　・【延長】終息日の確認が必要な機器があります。
　・【延長】延長期間4年の機器があります。
上の5行のうち、準備値で該当するものだけを表示する。
作業者操作＝全文を記録して「OK」を押す。
```

### 備考
C4は完全一致専用ではないため、Cを含む他の納入先コードも取得対象になることがある。予想外に見える行を即不具合とせず、部分一致条件で準備した対象集合と照合する。

## TL10-004

### 項番
TL10-004

### テスト項目
TL10（納入機器登録確認）：確認対象の一次納入日が空欄の機器を取得すると、警告と日付欄の強調表示で指摘すること。

### 前提条件
```
実施区分＝通常（既存の指摘対象を確保後）。

【この試験で確認すること】
SQL移行後も、一次納入日の空欄と対象外条件を正しく受け取り、指摘対象の行へマークを付けること。

【実施する人】
・実施者（対象を検索し、通知と指摘欄を確認する人）。
・準備担当者（対象条件を満たす既存機器を選ぶ人）。

【実施者に必要なもの】
・検証DB接続を準備した13フォルダー一式、マクロを実行できるExcel。
・閉じた状態の同梱追加パーツ適用表と、そのフルパス。

【準備担当者が用意するデータ】
個体側Noがあり、ブランド詳細に「撤去」がなく、一次納入日が空欄の既存機器Xを選ぶ。同じプラント・構成・型式の納入区分による免除に該当しないことを確認する。
検索対象全体について、用語表の指摘5種類の該当・非該当を確認し、最終通知の全文を準備する。Xの指摘を出すためにDBの日付やパーツ表を変更しない。

試験データ表：
| 検索に使う既存サポートID S／パーツ表のフルパス・版 | |
| Xのプラント名E／構成No F／個体側No Q／型式U／シリアル番号V | |
| Y列一次納入日が空欄で、撤去・納入区分の免除対象でない確認根拠 | |
| 期待する指摘文の一覧（用語表の順） | |

【開始時の状態】
Excelを起動していなくてよい。試験専用コピーを使う。条件に合う既存機器がない場合は準備未完とする。
```

### 操作内容
```
1. 試験用ブックの「操作シート」でC2:C5を空にし、C2にS、E6にパーツ表のフルパスを入力する。
2. 「納入機器 登録状態確認」を押す。終了通知を記録し、準備した指摘文と照合して「OK」を押す。
3. 新しい結果ブックの「納入機器」で、D・E・F・Q・U・Vの値からXの行を探す。
4. XのY列が空欄のまま灰背景・赤字・太字・斜体となり、A列に×があることを確認する。Y1に▼があることも確認する。
5. 記録を残し、結果ブックと試験用マクロは保存せずに閉じる。

【入力値】
C2＝S、C3:C5＝空欄、E6＝試験用パーツ表のフルパス。
```

### 期待結果
```
【画面確認】
・タイトル「納入機器確認終了」の警告が表示され、「一次納入日の確認が必要な機器があります。」を含む。その他の指摘も準備した一覧と一致する。
・XのYが空欄であることは維持し、そのセルが灰背景・赤字・太字・斜体となる。Aは×、Y1は▼。
・「不正データは見つかりませんでした。」で終了しない。XのDB日付やパーツ表を自動修正しない。

【DB確認】
実施不要（参照結果へのローカル指摘のみ、DB更新なし）。
```

### 期待メッセージ
```
表示タイミング＝各チェックの完了後。
表示形式＝Excelメッセージボックス（警告）。
タイトル＝納入機器確認終了
メッセージID＝－。
表示文言＝「下記の問題点がありました。」、空行、準備した該当行を次の順に表示：
```

## TL10-006

### 項番
TL10-006

### テスト項目
TL10（納入機器登録確認）：同じ元データ・検索条件・追加パーツ表で現行版と改修版を実行し、件数・列位置・指摘内容を比較すること。

### 前提条件
```
実施区分＝要確認。元データ時点・パーツ表を揃えられなければ実施不可。

【この試験で確認すること】
3回のCSV追記から結果連結へ移行した後も、対象・列・日付・指摘が一致すること。

【実施する人】
・実施者（両版で検索して結果を比較する人）。
・準備担当者（両DBの元データとパーツ表の版を揃える人）。

【実施者に必要なもの】
・動作可能な現行版・改修版を別々に置いた試験用フォルダー、各接続・認証・Excel実行環境。
・同じ版の追加パーツ適用表。両版ともE6を実在する試験用コピーへ設定する。

【準備担当者が用意するデータ】
両DBの元データ時点が一致することを確認し、3種類の行を含む少数対象を選ぶ。日付判定に現在日付を使うため、同日中に実施する。

試験データ表：
| 両版の名前・接続先識別名／データ時点の一致根拠 | |
| C2:C5へ入れる検索値／同じパーツ表の版と各パス | |
| 比較する構成・機器明細・個体行のD・E・F・J・Q | |

【開始時の状態】
パーツ表と出力ブックは閉じておく。両版を同時に動かさず、順に実行する。
```

### 操作内容
```
1. 現行版の操作シートで準備したC2:C5とE6を設定し、「納入機器 登録状態確認」を押す。通知を記録して「OK」を押す。
2. 新しい結果ブックの件数、2行目の見出しと代表3種類の行、A・AH・AJ等の指摘を比較用ブックの「現行」へ値で控える。結果ブックと現行ツールを保存せずに閉じる。
3. 改修版で同じ検索値・同じパーツ表を使って実行する。件数・見出し・代表行・指摘を比較用ブックの「改修」へ値で控える。
4. 両結果のB2:AK2の見出し、件数、代表行の値・日付・指摘文を照合する。行位置だけでなくD・E・F・J・Qのキーと型式・製番で対応を取る。
5. 差があれば対象キー・項目名・両方の値を記録する。比較結果を保存し、結果ブックとツールは保存せずに閉じる。

【入力値】
両版でC2:C5は同じ検索値、E6は同じ版の試験用パーツ表を使う。
```

### 期待結果
```
【画面・比較用ブック確認】
・件数、2行目の見出し、31列の配置と代表3種類の行の値・日付・指摘が一致する。途中へ追加の見出しが混入しない。
・終了通知が示す指摘の有無と各指摘文が一致する。
```
