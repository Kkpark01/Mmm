# #316 動作確認手順

## 準備

- 3ファイルを反映し、ビルド・再起動後にブラウザーを再読み込みします。
- INSPECTION参照ユーザーと、UPDATE更新ユーザーを用意します。ユーザー切替時はログアウトして再ログインします。
- 参照確認には既存の納入先を使えます。登録・削除の確認にはテスト環境の専用データを使用してください。

## 1. チケットの確認（参照ユーザー）

1. INSPECTION参照ユーザーでログインします。
2. 納入先マスタ検索（10U）で既存納入先を検索します。
3. 検索結果の「納入先コード」をクリックします。
4. 納入先マスタ（11U）がエラーなく表示され、選んだ納入先の内容が表示されることを確認します。
5. 下表の入力欄がグレー表示となり、文字入力・削除・チェック変更ができないことを確認します。
6. 登録・プラント追加がグレー表示となり、クリックしても処理が始まらないことを確認します。
7. 「戻る」で10Uへ戻り、検索条件と結果が表示されることを確認します。
8. 再び同じコードから11Uを開き、「閉じる」でメニューへ戻れることを確認します。

| 範囲 | 確認対象 |
|---|---|
| 納入先 | コード、名前、旧名、カナ名、英名、工場名 |
| 連絡先 | 郵便番号、国名、住所1、住所2、電話、FAX |
| その他 | 備考、納入先削除、DTSマスタ連携 |
| 更新履歴 | 登録日時、登録者、更新日時、更新者 |
| ボタン | 登録、プラント追加 |

ここまでがチケットの主要な合格条件です。内容の閲覧・戻る・閉じるは可能で、編集・更新操作はできない状態が正解です。

## 2. 更新権限への影響確認

1. UPDATE更新ユーザーで再ログインし、同じ手順で11Uを開きます。
2. 通常の入力項目、登録、納入先削除、プラント追加が操作可能なことを確認します。DTSマスタ連携と更新履歴は従来通り編集不可です。
3. テスト用納入先の備考を変更して登録を押し、確認ダイアログでキャンセルします。保存されないことを確認します。
4. 再び登録を押し、OKを選びます。「登録が完了しました。」がポップアップで表示されることを確認します。
5. 再検索して変更が保存されていることを確認します。この実DB保存・再取得の確認は利用環境で行う必要があります。
6. 必須項目を空にした場合の入力エラー後も、修正して登録できることを確認します。
7. 新規画面では納入先削除・プラント追加が非活性で、登録は使用可能なことを確認します。
8. テスト用の既存納入先からプラント追加が正常に遷移することを確認します。必要に応じて、プラント未登録の専用データで納入先削除も確認します。

## 3. 開発者向けの確認（任意）

参照ユーザーからsave/plantAddへ直接POSTしても、登録・更新・削除SQLが実行されないことを確認します。認証済みセッションと有効なCSRFトークンを使い、画面上の非活性を迂回した場合も拒否されることを確認してください。

この場合は共通の権限エラー処理に従いメニューに戻ります。通常の参照操作で起きる動作ではありません。

ローカル検証では直接POSTの拒否を確認済みです。実認証・CSRFフィルターを含むテストは未実施です。
