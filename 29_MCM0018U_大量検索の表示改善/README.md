# MCM0018U 大量検索結果の表示改善

2026/09/18受領のsrc用。元のsrcは未変更です。
src内の既存3ファイルを同じ相対パスへ反映し、ビルド・再起動してください。追加ファイルは不要です。性能改善のJavaScriptは既存index.html内にまとめています。27・28とのファイル重複はありません。

## 原因と対応

既存テンプレートでは、取扱機器の全行に製造メーカー・機器分類の全候補を繰り返し出力していました。6,000行・候補各800件なら、親一覧だけで約961万個のoption要素となります。大量のHTML解析・DOM生成が必要になる構造です。実際の会社環境の候補数・OOM発生時のメモリは未取得です。

- 検索条件欄の候補を共用し、通常の一覧行には空欄と選択中の候補だけを出力。
- 編集するselectだけに全候補を展開し、フォーカスを離れたら選択値を残して縮小。
- 表示用の名称は候補IDから引く辞書を一度だけ作成。失敗後の再表示でも現在のIDに対応する名称を表示。
- 繰り返し行の不要なHTMLコメント・タグ間空白を減らし、ブラウザのノード数を削減。
- VB版に合わせて検索時の待機画面・処理中メッセージは表示しません。検索の二重送信防止は維持。

検索件数の上限・ページ分割は追加していません。全件が一覧に存在し、最後までスクロールできます。登録データの組立て・DB更新・検索条件・行インデックスは既存のままです。SQL Serverのパラメータ上限対策（既存の1,000件単位の子データ取得）も維持しています。

## 検証

- Java全386ファイルのコンパイル成功。
- 実Controller／Thymeleafに模擬データを与え、0件・1,300件・6,000件でHTML生成成功。
- Chromeで27項目成功。全件保持、末尾スクロール、候補展開、選択値保持、変更フラグ、下段連動、待機画面が表示されないこと、二重送信抑止、ブラウザエラーなしを確認。
- メーカー・分類各800件、各親に子1件の模擬データで計測：

|検索件数|HTML生成時間|ローカル配信後の表示完了|option数|
|---:|---:|---:|---:|
|1,300|約0.9秒|約2.7秒|6,812|
|6,000|約1.5秒|約12.6秒|25,612|

6,000件でOut of Memoryは発生せず、全件スクロール・編集を確認しました。上記は会社DBの検索時間・社内回線の転送時間を含みません。旧版を6,000件で動かしてOOMを再発させる試験は行っておらず、旧候補数はコード構造からの計算です。
