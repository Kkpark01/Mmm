## 調査結果
1009U/index.htmlの依頼NOリンクは、選択行のtmKeiyakujikanIdを/forward/mcm1004uへ渡しています。VBのMcm1009uScreenの依頼NO押下もTmKeiyakujikanIDとMcm1004uConstant.SENIMOTO_MITSUMORI_LINK（数値1）をDeliveryで渡しています。
WebのMcm1004uController.indexはURLパラメータtmKeiyakujikanId（BigDecimal）とseniMotoKbn（Integer）を受け取り、サービスで対象を読み込みます。

## 現象
1009Uから1004Uの画面には到達するものの、選択した見積のキーが渡らず、未選択案内または前回開いた見積が表示される構造です。実機再現は未実施で、コードから確認した動作です。

## 原因
Mcm1009uController.forwardMcm1004uがmcm1004u.tmKeiyakujikanIdとmcm1004u.seniMotoKbnをセッションへ格納して/ mcm1004uへリダイレクトしていました。しかし現在の1004Uはこれらの独自セッション項目を読みません。区分も1009U定数の文字列MITSUMORI_LINKと受取側Integerが不一致です。1004Uに以前のFormがある場合、キーなしの表示は前回IDを復元するため誤対象表示にもつながります。

## 引継ぎ対象情報

- returnTo：既存1004Uの既定戻り先/mcm1003uを明示。1004Uの既存処理で選択見積を新たに読み込み、前回Formを流用しないために使用。1009Uへの戻り機能の新設は含みません。
