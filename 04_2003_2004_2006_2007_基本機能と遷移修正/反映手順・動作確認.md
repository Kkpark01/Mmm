## 申請メール

申請では添付必須・更新可能状態を確認し、入力・申請状態・メール送信依頼を**同じDBトランザクション**で保存します。そのコミット後、申請リクエスト内でSMTP送信を試みます。定期送信ジョブは追加していません。

- 送信者・宛先は MCM_MO_TANTO の申請者と OYALOGIN_ID の直上担当者の MAILADDRESS を使用します。
- 件名・本文はVBの「店舗見積審査依頼」と同じ定数です。
- VB getShoninJoho の金額条件は「申請者の MITSUMORISHONIN_KIN（NULL時999999999999）＞開始日が最も早い期間の見積金額」です。この条件から外れる申請は SKIPPED と記録し、通知対象外であることを画面に明示します。金額条件自体の業務変更は行っていません。
- 通知対象なのに担当者・宛先・SMTP設定が不足している場合は、申請を確定させず修正を案内します。VBの未設定時の黙示的な送信省略を防ぎます。
- SMTP失敗時は申請状態を保持し、FAILEDを画面に表示します。申請者本人の「申請メールを再送」で再送できます。SENTは再送しません。
- コミット直後の中断はPENDINGとして残り、同じ画面で再送できます。SMTP受理後のDB更新失敗・プロセス停止などのSENDINGは、受信状況が不明なため自動再送しません。管理者がSMTPログと照合する必要があります。SMTPは配送のexactly-onceを保証しないため、通信失敗時の再送では重複の可能性を確認する案内を出します。

送信履歴は MCM_WEB_MAIL_OUTBOX に保存します。実メールアドレス・SMTPパスワードをソースへ埋め込まないでください。検証では example.invalid の宛先と送信しないスタブだけを使いました。

## SP整合処理

VBの MCM_CLEAN_PAC.SP_UM / SP_UK は、孤児レコードを全件削除する処理です。引数 al_id は元の実装では使われておらず、採番処理ではありません。

通常保存ではMcmCustomerIntegrityServiceを必ず同一トランザクション内で実行します。新規・再選定・契約変更では既存repositoryが解除対象を子から削除し、見積の期間を失った単価・ブランド期間を対象見積内で整理します。契約は親・期間の存在を確認します。他の編集中見積・契約への全件削除は行いません。

- 初期設定 integrity-mode=sql：アプリ内SQLで上記を実行。SPがなくても基本保存は動作します。
- integrity-mode=procedure：同じ対象限定処理を MCM.MCM_WEB_SP_UM / MCM.MCM_WEB_SP_UK に委譲し、対象IDを引数に渡します。
- VBと同じ**全件**孤児削除は別の保守用手続き MCM_WEB_CLEAN_UM_ALL / MCM_WEB_CLEAN_UK_ALL として提供します。画面から自動実行しません。旧孤児データの一括清掃が必要な場合に、停止時間を確保してDB管理者が実行するためのものです。

SQL Serverでの実プロシージャ作成・実行は未確認です。通常SQL・全件清掃の削除文はH2の独立した仮DBで動作確認し、procedureモードは呼出し名と引数を検証しています。

設定例は**STARTTLS/587を使用するSMTPの場合**です。実際のSMTP管理者が指定する方式・ポート・認証に合わせて調整します。

~~~yaml
mcm:
  customer:
    integrity-mode: sql # SPに委譲する場合はprocedure
    mail-enabled: true
spring:
  mail:
    host: ${MCM_SMTP_HOST}
    port: 587
    username: ${MCM_SMTP_USER}
    password: ${MCM_SMTP_PASSWORD}
    properties:
      mail.smtp.auth: true
      mail.smtp.starttls.enable: true
      mail.smtp.connectiontimeout: 5000
      mail.smtp.timeout: 10000
      mail.smtp.writetimeout: 10000
~~~

送信者には担当者マスタのアドレスを使うため、SMTPアカウントにそのアドレスでの送信許可が必要です。接続先・認証情報は環境変数で渡します。mail-enabledは未指定時falseです。メールを有効化するまで通知対象の申請は設定案内で停止します。

添付保存先は既存 mcm.file.upload-path 配下の estimates/見積ID/UUID/ファイル名です。複数サーバーでは共有ストレージを使います。
