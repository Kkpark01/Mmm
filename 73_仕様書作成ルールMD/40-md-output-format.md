# Markdown出力形式とExcel復元の仕様

結合テスト仕様書を、Excelではなく1つのMarkdownファイルとして出力し、後でExcel（基準ブック）へ復元するための形式を定める。
構成（シート、列、行レイアウト、項番体系）は、現行の結合テストブック（20シート構成）と同じにする。

本章のレイアウトは、現行ブックの構造説明（シート一覧、セル配置、集計式、書式）に基づく。実ファイルを直接読み取って検証したものではない。実ファイルと異なる点が見つかった場合は、実ファイルを優先し、本章を修正する。

## 1. 方針

- Markdownには、ケースデータと、人が書いた文字列（タイトル、作成根拠、説明文、課題）を持たせる。
- 数式、入力規則、条件付き書式、書式、Excelテーブル、ピボット、グラフ、管理シートは、基準ブック（テンプレート）側が持つ。Markdownには数式を書かない（復元時に再設定する数式は5章に示す）。
- 長文のセルは、省略記号で短縮せず、全文を原形のまま書く。
- セル内改行は構造の一部である。段落ごとに別のExcel行へ分割しない。
- 元の基準ブックは上書きしない。

## 2. 現行ブックのシート構成とMD出力の扱い

| 順 | シート名 | MD出力 | 扱い |
|---:|---|---|---|
| 1 | 結合テスト目次 | する（6章） | 文字列と手入力の値を出力。数式列はテンプレート |
| 2 | 仕様書課題一覧 | する（7章） | 全件出力 |
| 3〜9 | INT10〜INT16（業務フロー別、現行は7シート） | する（3〜4章） | ケースシート。機能ごとに数・名称が変わる |
| 10 | 結合テスト仕様書作成ルール | しない | 基準ブックのまま引き継ぐ（扱いは要確認。8章） |
| 11 | 管理用→ | しない | 区切りシート。テンプレートのまま |
| 12〜20 | 実施計画、進捗ログ、進捗ログピポット、画面別進捗推移、明細_統合、作業者別集計、分析メモ、ボトルネック分析、本日実績報告 | しない | 管理シート。テンプレートのまま。参照範囲は5章で更新 |

- シート名は一字一句維持する。業務フロー別シートの名称は `INT{連番2桁}_{業務フロー名}` とする。
- 進捗ログ（Excelテーブル「進捗ログ表」とグラフ）、進捗ログピポット（ピボットテーブル）、画面別進捗推移（グラフ）は、Markdownでは表現できない。テンプレートに残し、復元後に存在を確認する（9章）。
- 管理シートの既存エラー表示（`#N/A`、`#VALUE!` など）は、元の数式と表示結果を区別して扱う。根拠のない数値で埋めない。

## 3. MDファイルの構成

1つのMarkdownファイルに、出力対象のシートを、Excelのシート順で出力する。

```text
# {仕様書名}

<!-- spec-meta
基準ブック: {ファイル名}
対象機能: {機能名}
出力日: {YYYY-MM-DD}
出力シート数: {N}
-->

## [SHEET] 結合テスト目次
…

## [SHEET] 仕様書課題一覧
…

## [SHEET] INT10_{業務フロー名}

<!-- type: cases -->
<!-- 最終ケース行: {R} -->

### A1
（結合 A1:D1）
```text
INT10 {業務フロー名}グループ 結合テスト
```

### A2
```text
{作成根拠：対象ソース、単体テスト資料の扱い、Java版を参照しない旨など}
```

### A3
（結合 A3:O3）
```text
{起点画面、画面間フロー、重点確認事項、対象外範囲の説明}
```

### A4
```text
{原則空欄。到達経路を別途記載する場合のみ}
```

### CASES（ヘッダー行＝9行目、ケース＝10行目以降）

| 項番 | 分類 | … |
|---|---|---|
| INT10-001 | … |
```

- シートは `## [SHEET] {シート名}` の見出しで区切る。シート名は、Excelの制約（31文字以内、`[ ] : * ? / \` を含まない）を満たす。
- ケースシートのセル値は、`### A1`、`### A2`、`### A3`、`### A4`、`### CASES` の小見出しで区切る。長文は、フェンス付きテキストブロックで原文のまま書く。
- 結合セルは、見出しの直後に `（結合 A1:D1）` のように範囲を書く。
- 5〜8行目（進捗指標の見出し・数式、`TEST CASES` の帯、空白の区切り行）は、テンプレートが持つ。MDには出力しない。
- 読み取れない、確定できない属性は、推測せず「未取得」と書く。

## 4. ケースシートの行レイアウトと列定義

### 4.1 行レイアウト（現行ブック）

| 行・範囲 | 内容 | MD出力 |
|---|---|---|
| A1:D1（結合） | グループ別タイトル（例：`INT13 店舗見積作成グループ 結合テスト`） | する |
| A2 | 作成根拠（移行元VB.NETの対象ソース、単体テスト資料の扱い、Java版を参照しない旨。長文1セル） | する |
| A3:O3（結合） | 起点画面、画面間フロー、重点確認事項、対象外範囲の説明 | する |
| A4 | 原則空欄。INT14のみ、既存データへ見積NOリンク経由で到達する経路を記載 | する（空欄も明記） |
| A5:H5 | 8項目の進捗指標の見出し | しない |
| A6:H6 | 8項目の進捗指標（数式） | しない（5章で再設定） |
| A7 | `TEST CASES` | しない |
| 8行目 | 空白の区切り行 | しない |
| A9:O9 | ケース表の見出し（15項目） | する |
| 10行目以降 | テストケース（1行が1ケース） | する |

- ケース表の先頭は必ず10行目。余白や書式だけが残る行は、ケースと数えない。

### 4.2 列定義（A〜O、15列）

| 列 | 見出し | 出力時の内容 |
|---|---|---|
| A | 項番 | `INT13-001` などの固定ID |
| B | 分類 | 画面遷移、画面連携、正常系、異常系、権限連携、業務ルールなど |
| C | テスト項目 | 対象画面・遷移元→遷移先・検証観点を含む文 |
| D | 前提条件・操作／入力値 | 同一セル内の改行で `【前提】`、`【操作】`、`【入力値】` を構成 |
| E | 期待結果 | `【画面確認】` と `【DB確認】` を同一セル内に記載 |
| F | 期待メッセージ | 表示タイミング、表示形式、メッセージID、表示文言、作業者の操作 |
| G | テスト結果 | 初回結果。出力時は空欄 |
| H | 実施者 | 初回実施者。出力時は空欄 |
| I | 実施日 | 初回実施日。出力時は空欄 |
| J | 不具合内容 | 不具合や保留理由。空欄も保持 |
| K | 再テスト結果 | 再テストした場合のみ。出力時は空欄 |
| L | 再テスト実施者 | 同上 |
| M | 再テスト実施日 | 同上 |
| N | 最終判定 | 数式（テンプレート側）。集計に使用する列で、G列とは別物。MDには出力しない（空欄） |
| O | 備考／根拠 | 対象範囲、先行ケースへの依存、VB.NETソース上の根拠、実施区分 |

- 判定はテスト実施時に入力する。結果入力列（G〜M）は、空欄で出力する。N列は数式のため、MDには値を出力しない。列自体は省略しない。
- 集計はG列（初回結果）ではなく、N列（最終判定）を基準にする。
- 最終判定の値は、OK、NG、保留、対象外、未実施。初回NGでも再テストでOKになったケースは、G列はNGのまま、K列にOKを入力し、N列の結果をOKとする。G列を書き換えない。
- N列の数式は、現行ブックの数式をそのまま引き継ぐ。実物を確認できていない場合の基準形は次のとおり（lessons-learnedの基準ロジック。現行ブックの式との一致は未確認）。

```excel
=IF(G10="","未実施",IF(K10="",G10,K10))
```

  G＝初回結果、K＝再テスト結果。再テストがあればその結果を、なければ初回結果を最終判定とする。
- D、E、F、O列のセル内改行を、段落ごとに別のExcel行へ分割しない。

### 4.3 MDの表の書き方

- 1行が1ケース。行の順序は項番の昇順。最初のケースが10行目に対応する。
- セル内の改行は `<br>` で表す。セル内の `|` は `\|` にエスケープする。
- 箇条書きのマーカーは `・`、番号付き手順は `1.` の形式を使い、`<br>` で区切る。
- 見出し（`【前提】`、`【操作】`、`【入力値】`、`【画面確認】`、`【DB確認】`、`【対象】`、`【確認根拠】`、`【要確認】`）は、原文のとおり書く。
- 空欄は空のまま出力する。入力値なし・メッセージなしの `－` は文字として出力する。
- 全行の列数が、ヘッダーの列数（15）と一致していること。
- 最終ケース行 R は、`9＋ケース数` と一致していること。

記載例（概念図。実際は15列すべてを出力する）：

```text
| 項番 | 分類 | テスト項目 | 前提条件・操作／入力値 | 期待結果 | 期待メッセージ | … | 備考／根拠 |
|---|---|---|---|---|---|---|---|
| INT13-001 | 画面遷移 | MCM2004U(店舗見積・契約検索)→MCM2002U(店舗見積・ユーザー契約機器選定)：… | 【前提】<br>・ログインユーザー：更新権限のユーザー<br>・状態＝見積、承認状態＝未申請の店舗見積が1件以上登録されている<br>【操作】<br>1. …<br>【入力値】<br>検索条件＝－ | 【画面確認】<br>1. MCM2002U …<br>【DB確認】<br>実施不要（理由） | 表示タイミング＝…<br>… | … | 【対象】<br>MCM2004U → MCM2002U<br>【確認根拠】<br>・ソース：… |
```

## 5. Excelへの復元手順

Copilot in Excel等で復元する場合は、次の順で進める。

1. 基準ブックをコピーし、別名で保存する（基準ブックそのものを編集しない）。
2. MDの `## [SHEET]` ごとに、テンプレートの該当シート（または既存のINTシートの複製）へ、各セルの値を設定する。
3. `<br>` をセル内改行に変換する。`\|` を `|` に戻す。
4. ケース表の書式（Meiryo UI 11pt、上揃え・折返し、A列・判定列は中央、C列は左寄せ）、罫線、行高を、既存ケース行に合わせる。長文を収めるため行高はケースごとに異なる。標準の18に一律設定しない。
5. 全ケース行に、入力規則、条件付き書式、N列（最終判定）の数式を適用する。追加した行でも、数式の参照行（G列、K列）が同じ行を指していることを確認する。
6. 各INTシートの A6:H6 を、最終ケース行 R に合わせて再設定する。

```excel
A6 =COUNTA(A10:A{R})
B6 =COUNTIF($N$10:$N${R},"対象外")
C6 =A6-B6
D6 =COUNTIF($N$10:$N${R},"OK")
E6 =COUNTIF($N$10:$N${R},"NG")
F6 =COUNTIF($N$10:$N${R},"保留")
G6 =IFERROR((D6+E6+F6)/C6,0)
H6 =IF(C6=0,0,D6/C6)
```

   G・H列は数値をパーセント表示にする。

7. 結合テスト目次を更新する（6章）。
8. 管理シート（明細_統合、作業者別集計、実施計画、本日実績報告、分析メモなど）の、シート名・行範囲を参照する数式を更新する。旧機能のシート名やサンプル固有の文字列が残っていないこと。旧シートの合計行の行番号を参照している他の管理シートも、見落とさず更新する。
9. 復元後の検証（50-quality-assurance.md の「復元後の検証」）を実施する。

ケースシートの書式（現行ブックの基準）：

- A1：濃紺 `#1F4E78` 背景、白文字、18pt・太字（A1:D1結合）
- A3:O3：結合、淡青 `#EAF2F8`、上揃え・折返し
- A5:H5：淡青 `#D9EAF7`、太字・中央。A6:H6：淡色 `#F5F9FC`
- A7：青 `#2F75B5`、白文字・太字
- A9:O9：青 `#4472C4`、白文字・太字・折返し
- 列幅の例（INT13）：A54、B65、C184、D338、E304、F304、G65、H65、I79、J279、K77、L84、M84、N91、O308。INT10のD列は625など、シートごとの例外がある。

書式は、新規に設定するより、既存のINTシートを複製して引き継ぐ方が確実である。この場合も、条件付き書式・入力規則・オートフィルターは引き継がれないことがあるため、複製後に確認する。

## 6. 結合テスト目次

現行ブックのレイアウト：

- A1：`MCM 見積機能　結合テスト仕様書（VB.NET版仕様ベース）`、A2：`対象13画面｜画面間連携をグループ単位に集約し7シート構成`（機能に応じて書き換える）
- A4：作成根拠と結合テストの重点を説明する長文
- A7：`CONTENTS`
- 8行目：`シート／目的／テスト件数／対象外件数／実テスト件数／完了件数(OK)／NG件数／保留／実施率／合格率`（A〜J）、L8：`担当`（K列は区切りで空欄）
- 9行目以降：INTシートごとに1行。A列に正確なシート名、B列に目的、L列に担当
- 最終行：`合計`

| 列 | MD出力 | 内容 |
|---|---|---|
| A | する | 正確なシート名 |
| B | する | 目的 |
| C | しない（数式） | `=IFERROR(INDIRECT("'"&$A9&"'!A6"),0)`（行に応じて相対参照） |
| D〜H | する（値） | 現行ブックでは数式ではなく入力済みの値（対象外件数、実テスト件数、完了件数(OK)、NG件数、保留）。新規作成時の初期値は、対象外＝0、実テスト件数＝ケース数、OK・NG・保留＝0 |
| I | しない（数式） | `=IF(E9=0,0,(F9+G9+H9)/E9)` |
| J | しない（数式） | `=IF(E9=0,0,F9/E9)` |
| L | する | 担当 |
| M | する | 注記（例：テストケース追加の履歴） |

- 合計行：C〜H を `SUM` 等で集計する。I・J は次の式。
  - `=IF(E16=0,0,(F16+G16+H16)/E16)`
  - `=IF(E16=0,0,F16/E16)`
- D〜H が値である点は、ケースの最終判定を更新しても自動では変わらないことを意味する。更新方法は8章の確認事項。

## 7. 仕様書課題一覧

- 見出し（A1:F1）：`No／対象ルール・シート／内容／区分／対応方針／確認先`
- 2行目以降に課題を1件ずつ置く。
- 区分：「解消済み」「要確認」「情報共有のみ」を区別する。確定できていない課題（権限定数、戻り遷移、メッセージID、基準ブックの既存の名前定義エラーなど）を、解決済みと書き換えない。
- 書式：1行目は `#4472C4` 背景・白文字。C列（内容）とE列（対応方針）は折り返す。

## 8. 未確定事項（確認が必要）

1. 結合テスト仕様書作成ルール（A1:X207）シートを、新しい機能の仕様書でも、そのまま引き継ぐか、機能に合わせて作り直すか。
2. 画面到達経路の記載位置。共通ルールはタイトル直下の単一セルとしているが、現行ブックでは A2＝作成根拠、A3＝起点画面・フローの説明、A4＝INT14のみの経路記載。
3. D列の見出し語。現行ブックは `【前提】`／`【操作】`／`【入力値】`。従来の共通ルール文書は `【前提条件】`／`【操作手順】` と書いている。
4. 目次のD〜H列（値）を、復元後も値のまま運用するか、ケースシートを参照する数式に変えるか。
5. N列（最終判定）の現行ブックの実際の数式。基準形（4.2章）との一致。

確認済み：判定はテスト実施時に入力する。最終判定（N列）は数式である。対象外の判定は、実施時にG列またはK列へ入力する想定（要確認）。

## 9. 制約（未検証事項）

- Copilot in Excelが、Markdownから複数シート・入力規則・数式・条件付き書式を、ここに書いた水準で復元できるかは、確認していない。
- 復元が難しい場合の代替案：ケース表をCSV相当に変換して貼り付ける。Power Query、VBA、Pythonなどで取り込む。
- openpyxlを使う場合の注意：
  - 保存によって、グラフ、ピボットテーブル、Excelテーブル（進捗ログ表）が欠落・変化することがある。保存後に、存在と参照先を確認する。
  - `copy_worksheet` は、条件付き書式・入力規則・オートフィルターを引き継がない。複製後に確認する。
  - 動的配列数式は `ArrayFormula` として明示的に作成する。文字列として代入しない。
  - 保存前に、対象ファイルがExcelで開かれていないことを確認し、バックアップを取る。保存後は再読込できることを確認する。
