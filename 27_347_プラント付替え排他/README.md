# #347 プラント付替えの排他制御

2026/09/17受領の最新版srcを基にした修正版です。元のsrcは変更していません。
このフォルダのsrc内の3ファイルを、同じ相対パスへ上書きしてビルド・再起動してください。DBのテーブル・ビュー追加は不要です。

## 変更点

- 付替え元設定時と外部画面からの起動時に、構成・明細・個体の表示時点の比較情報をセッションに保存します。
- 保存直前に比較し、変更・追加・削除があれば書込み前に中止します。更新日時を含むDB行のハッシュを使用するため、日時の精度だけに依存しません。
- 比較から更新完了まで既存のSERIALIZABLEトランザクション内で処理し、途中の競合・失敗はロールバックします。
- 排他時はFWM_0009「他のユーザがデータを変更した可能性があります。処理をやり直してください。」を表示します。古い画面の比較情報を自動的に最新化せず、付替え元の再設定を必要とします。
- 比較情報がない旧セッションも保存を拒否します。

比較の単位は付替え元プラント全体です。選択していない構成への変更でも再設定が必要になります。保存時に構成・明細・個体を読み直すため、大量データでは応答時間とSQL Serverのロック待ちも会社環境で確認してください。

## 会社環境での受入確認

1. 別ブラウザ／別ユーザーA・Bで同じ付替え元を設定する。
2. Aが付替え保存後、Bが再設定せず保存する。FWM_0009となり、Aの内容が保持されること。
3. Bが付替え元を再設定すると最新内容になり、正常に保存できること。
4. 全件付替えと一部付替えの双方で繰り返す。
5. Aが数量・明細・個体のみを変更した場合も、Bの古い画面からの保存が拒否されること。
6. 保存途中のDBエラー時に、構成移動・新規構成／明細・個体移動・数量変更が部分的に残らないこと。
7. 同時に保存した際も上書きされず、競合側にFWM_0009が表示されること。
