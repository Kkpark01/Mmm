# 61の使い方：ローカル開発・devでの共有確認・検証サーバー

## 1．local・devは「接続先と保存先を選ぶ設定」です

**devを指定しても、アプリ自体が検証サーバーへ移動するわけではありません。** Eclipseで起動すれば、アプリは自分のPCで動きます。検証サーバーで動かすには、作成したJARをサーバーへ配置して起動します。

現在の設定では、次の使い分けになります。

| 使い方 | アプリが動く場所 | 使用するDB | 添付ファイルの保存先 |
|---|---|---|---|
| 個人PCでlocal | 自分のPC | 検証DB | 自分のPC |
| 個人PCでdev | 自分のPC | 検証DB | サーバーの共有フォルダ |
| 検証サーバーでdev | 検証サーバー | 検証DB | サーバーの共有フォルダ |
| 本番サーバーでprod | 本番サーバー | 本番DB | 本番用に指定した保存先 |

**localも検証DBを使うため、登録・変更したデータはチームの共有データに反映されます。** localは「データも完全に自分専用」という意味ではありません。

## 2．最初に61を反映します

61フォルダの`src`内にある5ファイルを、開発プロジェクトの同じ場所へ上書きして、ビルド・再起動します。対象ファイルは[README](README.md)を参照してください。

61では既定のlocalや保存先の値は変更していません。追加したのは、起動時の確認ログと、設定ファイル内の説明です。

## 3．普段の個人開発ではlocalを使います

Eclipseで環境を指定せずに起動すると、既定のlocalになります。

```text
DB：検証DB（ILCM-SYSDEV / SYSDEV）
添付保存先：C:/opt/mcm/upload
```

通常の画面修正や、自分のPC内で完結する添付操作の確認に使えます。添付の確認前に、保存先フォルダを用意してください。

ただし、localで添付を登録すると、次のようになります。

```text
ファイル本体 → 自分のPCに保存
ファイルの保存場所を示す情報 → 検証DBに登録
```

他の人にも添付リンクが表示される場合がありますが、あなたのPCに保存したファイルは取得できない場合があります。

検証DBは共有しているので、チームで決めたテスト用データを使って作業します。

## 4．自分のPCから共有添付を確認するときはdevを使います

ソース修正は引き続き自分のPCで行い、DBと添付保存先をチーム共通にする使い方です。

Eclipseの「実行構成」で、使用している起動設定を開き、「引数」タブの「VM引数」に次を追加します。

```text
-Dspring.profiles.active=dev
```

起動中のアプリを停止してから、再起動してください。

```text
DB：検証DB（ILCM-SYSDEV / SYSDEV）
添付保存先：\\ILCM-SYSDEV\uploadfolder\MCM
```

この状態で新しく登録した添付は、共有フォルダに保存されます。同じDB・保存先を使う他のPCや検証サーバーからも、権限があれば取得できます。

共有フォルダには、**Javaを実行するWindowsアカウントの読み書き・削除権限**が必要です。

localへ戻す場合は、追加したVM引数を削除して再起動します。ただし、環境変数などでdevを指定している場合は、その指定も解除する必要があります。

## 5．検証サーバーでの確認は、JARを配備して行います

基本的な流れは以下です。

1. 自分のPCでコードを修正する。
2. Eclipseなどで動作を確認する。
3. ビルドしてJARを作成する。
4. 検証サーバーへJARを配置する。
5. サーバー側ではdevを指定して起動する。
6. チーム共通の検証URLをブラウザーで開く。

JARを直接起動する場合の指定例です。JAR名は実際のものに置き換えます。

```powershell
java -jar "mcm-web.jar" --spring.profiles.active=dev
```

サービスや起動用batなどで動かしている場合は、**その起動設定にdevを指定**します。自分のEclipseで設定したdevは、配備先のサーバーには引き継がれません。

検証サーバーでも、指定がなければ既定のlocalになります。そのため、サーバー側の指定と起動ログを確認してください。

## 6．結合・排他テストは、同じ検証サーバーのURLで行います

正式な結合テストでは、各自のPCで異なる修正版を動かすのではなく、検証サーバーに配備した同じ版を確認します。

排他テストでは、別PC・別ユーザーで同じ対象データを開きます。例えば、更新時に他者の変更を検知する画面では、次の手順です。

```text
Aさん・Bさんが同じデータを開く
    ↓
Aさんが変更して登録する
    ↓
Bさんは再読込せず、変更して登録する
    ↓
排他メッセージが表示され、
Aさんの変更が上書きされないことを確認する
```

具体的な期待動作は、対象画面の仕様に合わせて確認します。

## 7．起動ログで、実際に使われる設定を確認します

Eclipseのコンソールやサーバーログで、次の文字を検索します。

```text
[MCM起動設定]
```

localの場合の表示例です。

```text
[MCM起動設定] 使用環境=local
[MCM起動設定] DB接続先（設定）=サーバー=ILCM-SYSDEV / インスタンス=未指定 / ポート=1433 / DB=SYSDEV
[MCM起動設定] 添付保存先=C:/opt/mcm/upload
```

devでは、使用環境がdev、添付保存先が共有フォルダになっていることを確認します。

パスワードや接続URL全体は表示しません。また、これは**設定の確認ログ**です。DBへの接続成功や、共有フォルダへアクセスできることを証明する表示ではありません。

外部の`config/application.yml`、VM引数、環境変数で設定が上書きされる場合もあるため、起動ログで確認することが大切です。INFOログを無効にしている場合は表示されません。

## 8．環境を切り替えても、添付ファイルは自動移動されません

localで自分のPCに保存した添付が、devへの切替だけで共有フォルダへ移ることはありません。DBに記録された保存場所も、自動では変更されません。

共有添付の動作確認は、**devで起動してからテスト用ファイルを新しく登録する**と分かりやすいです。既存資料を移す場合は、実ファイルの移動とDBの保存場所の更新を別途行います。

本番ではprodを明示し、本番DB・認証情報・添付保存先の環境変数を用意します。本番の値は現在未確定なので、確定後に設定します。

この説明は61と現在のsrcに基づくものです。配備先の実際の起動方法や共有フォルダの権限は、現地での確認が必要です。
