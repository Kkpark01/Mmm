# 78：チケット542・543 添付削除（MCM1005U）

## 調査結果
VBのMcm1005uTabControl.FileDelButton_Clickは、行選択→添付承認状態検査→FWM_0013G確認→削除→MSG_0073G完了の順です。審査中1・承認中2・承認済3は確認より先にMSG_0106Eで中止します。作成中0・差戻し4は通常の削除対象です。
VBのCPMessage.xmlは、FWM_0013G「行を削除します。よろしいですか？」、MSG_0073G「ファイルの削除を完了しました。」、MSG_0106E「承認済みのファイルの為、削除できません。」。
Webの共通通知はIDの末尾G/Eを省いたFWM_0013、MSG_0073、MSG_0106を持ちます。確認は汎用の「{0}を削除します。よろしいですか？」で、既存の1005U呼出しが「添付ファイル」を指定した文章を渡していました。

## 現象・原因
#542：画面deleteTenpuに「添付ファイルを削除します…」が直接記載され、Controllerも削除完了に「ファイルを削除しました。」を返していました。VB／チケットと異なる画面側の呼出し文言が原因です。
#543：ファイル削除ボタンのdisabledがperiodEditableに依存しており、承認状態や期間の編集不可条件で押せなくなっていました。押下時の添付状態チェックも画面にはありませんでした。Serviceは既に削除制限がありますが、状態エラーの文言と判定の優先順位が異なっていました。
チケットタイトルは「期間の変更ができる」ですが、依頼された具体的な対象は添付削除です。期間の変更機能は変更しません。

## 修正対象・修正方針
- src/main/resources/templates/mcm1005u/index.html
  - 削除ボタンはcanDeleteAttachment（既存の作成権限）と登録済み期間の条件で活性化。periodEditableから分離。追加ボタンの既存条件は維持。
  - 添付の状態1/2/3は確認ダイアログより先にMSG_0106Eと同じ文言を表示し、送信しない。
  - 削除確認をFWM_0013Gの「行を削除します。よろしいですか？」へ変更。
  - 76の不要な離脱確認修正も含む。
- src/main/java/com/daifuku/mcm/controller/Mcm1005uController.java
  - canDeleteAttachmentモデル属性を既存のcanUpdate()から設定。参照ユーザーを許可しない。
  - operation=deleteAttachmentと既存deleteTenpuエンドポイントの成功通知をMSG_0073Gの文言へ統一。
- src/main/java/com/daifuku/mcm/service/Mcm1005uService.java
  - deleteTenpuで、権限と契約所属を確認した後、状態1/2/3をMSG_0106Eの文言で拒否。
  - 作成中・差戻しの契約／期間編集検査、その他の状態拒否、実削除は維持。

## 影響範囲
MCM1005Uの添付削除だけです。共通メッセージ定義・共通通知JS・共通権限処理・他画面は変更しません。ファイル追加ボタン、ダウンロード、保存パス、削除時の契約ロック・DB削除・実ファイル後処理は維持します。削除ボタンが押せても、不可状態ではデータを削除しません。参照権限・未登録の期間まで「常に押下可能」にするものではありません。

## 確認観点（未実施）
1. 作成権限で作成中0・差戻し4の添付を選択：確認文言がFWM_0013Gどおり。OKで削除され、MSG_0073Gの完了文言と一覧再表示。
2. 同条件でキャンセル：送信・削除・完了通知なし。

6. 通常の添付追加、削除後の一覧、他画面の確認文言に変化がないこと。
7. 76・78を反映し、添付追加時の不要な離脱確認が戻らないこと。
