# 添付保存先・環境切替の確認観点

2026-10-01更新：利用者の指示により自動判定を廃止し、検証用を有効・本番用をコメントアウトする方式へ整理。保存処理の確認観点は維持する。

同日追加：共通保存処理を既存`FileStorageService`へ統合し、例外を既存`McmBusinessException`へ変更。反映対象は既存9、新規0ファイル。

同日共有パス受領：検証用を`//ILCM-SYSDEV/uploadfolder/MCM`へ変更。現段階の対象は新規添付で、旧ルートの既定値は空。DBと本番コメントアウトは維持し、個人PC・稼働ユーザーからの共有アクセスは現地確認する。既存資料の移行は後日、DBのパスを見て判断する。

対象は保存設定と直接の参照先。1005・2003・3005の登録、3001・2008の参照、2008のExcel捺印、53の1011捺印との互換を確認する。

| 観点 | 修正前の問題／期待結果 |
|---|---|
| 環境 | 検証用を有効、本番用文書をコメントアウトで用意。文書全体のコメント解除でDB・保存先を一緒に切り替える。外部YAML・環境変数の上書きを確認 |
| 未定情報 | 本番接続先・保存先を推測しない。本番必須項目が空なら通常Bean（DB接続を含む）の生成前に停止 |
| 検証 | 保存先は//ILCM-SYSDEV/uploadfolder/MCM。共有の下に画像のMCM/取引先があり、サーバー内Fルートと同じ相対構成であることを確認 |
| 開発 | 共通YAMLの共有UNCを使う。Eclipseの環境変数・外部YAML・起動引数による古い指定に注意。Java実行ユーザーでの共有アクセスを確認 |
| 保存形式 | 新規は日本語業務フォルダ＋相対パス。旧英語フォルダ・旧絶対パスの構造を維持して読める |
| 既存資料 | DIRECTORYがファイル／フォルダ両形式。取引先ファイル名の二重連結を解消。旧ルート読み替えは登録したものだけ |
| 失敗 | ルート未設定・未存在・アクセス不可・実ファイルなしを業務エラーへ変換し、ログで区別。共通仕様4.3に従い既存共通ハンドラーで案内 |
| 保護 | 権限、親子ID照合、同名禁止、排他、ロールバック、コミット後削除を維持。ルート外・..・リンク経由の逸脱を拒否 |
| 互換／競合 | 最新srcに直接変更しない。55との対象重複確認。最新の承認件数・trim判定を維持。旧56反映済みなら旧追加5ファイルを削除してクリーンビルド。相対パスは参照・捺印側も同時対応 |
| 共通処理統合 | Springによる既存保存クラスの生成・注入、共通アップロード／移動／削除の互換、専用例外なしで同じ文言・原因が共通ハンドラーへ届くことを確認 |
| 検証限界 | ローカル実ファイルと設定読込を検証。実DB、サーバーF、UNC、Windowsサービス実行ユーザー、Office起動は配備環境で確認 |
