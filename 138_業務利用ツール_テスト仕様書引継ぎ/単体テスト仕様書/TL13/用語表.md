# TL13（簡易終息リストデータ取得） 用語表・根拠

2026-11-02。131の14「簡易終息リストデータ取得.xlsm」を基準とする。VBA7モジュール、チェック状態別のSQL4本、Excelの読み取り専用表示を確認。会社編集版・実DB・業務マクロ実行は未確認。

根拠：[TL13調査記録](../../../../検証記録/20261102_業務利用ツール引継ぎ/TL13_調査)。source.jsonに元ブックのSHA-256、native_ui.jsonに表示名・セル・ボタン割当を記録した。

## 問合せシート

| 表示名 | セル・意味 |
|---|---|
| サポートID1／2 | C2／C3。7桁に整形して前後に%を付ける |
| 納入先コード1／2 | C4／C5 |
| 機器品名1／2 | C6／C7 |
| 機器型式1／2 | C8／C9 |
| 取引先名1／2 | C10／C11 |
| 取引先契約番号1／2 | C12／C13 |
| 客先契約の「契約中のみ検索」 | 上側。C14にリンク |
| 取引先契約の「契約中のみ検索」 | 下側。C15にリンク |
| 問合せ実行 | D1付近。表示名の後ろに装飾文字がある。割当はSimpleQuery |

C2:C13のうち1つ以上が必要。12欄はOR条件で部分一致し、未入力欄をNULLへ変換する。別欄を追加してANDで絞るという手順は作らない。型式・取引先契約番号にはUPPERを使う。他の項目まで一律に文字大小・全角半角の扱いを同じと判断しない。

客先・取引先の契約チェックは、検索文字列のOR条件に加えるAND条件。チェックだけ選んで検索文字欄が全空欄の場合は未入力で中止する。

## チェック状態と取得

| 客先C14 | 取引先C15 | SQL | 状態の条件 |
|---|---|---|---|
| 解除 | 解除 | T08_00_00_01.sql | 契約状態の追加制限なし |
| 解除 | 選択 | T08_00_01_01.sql | 取引先契約状態＝契約 |
| 選択 | 解除 | T08_00_10_01.sql | 客先契約状態＝契約 |
| 選択 | 選択 | T08_00_11_01.sql | 両方とも契約 |

取得元はMCM_KEIYAKU_EXTRACT5_V。サポートIDの先頭2桁が99の対象は除外する。チェック状態で選ぶSQLは、契約状態条件を除いて同じ投影列・検索条件・順序。

SQLは35列。末尾の内部キーは「個体管理ID / 機器明細ID」。取得後にこのキーで後ろの行を残して重複を除去し、キーと作業列を削除する。**チェックによる絞り込みは重複除去より先。** チェックなしの表示結果を後からExcelで状態フィルターしただけでは、チェックありの期待値にならない場合がある。準備はビュー候補からチェック条件・SQL順・重複除去を反映する。

## 表示・結果

同じ「問合せ」シートのB20:AI20が34列の見出し、B21から下が明細。新しいブックへの移動、CSVのファイル出力、自動保存は行わない。コード内の「簡易問合せ.csv」は取得結果の識別名で、実際のCSV作成はしない。

| 列 | 見出し |
|---|---|
| B・C・D・E・F・G | サポートID・納入先コード・納入先名・納入先工場名・住所・システム名 |
| H・I・J・K | 客先契約状態・契約時間帯（ユーザ）・ブランド詳細名・機器構成名 |
| L・M・N・O・P・Q | 取引先契約状態・製造メーカ名・機器品名・機器型式・シリアル番号・数量 |
| R・S・T・U・V | 一次納入日・二次納入日・契約期限・延長契約期限・撤去日 |
| W・X・Y・Z・AA・AB | 取引先名・取引先契約番号・契約日（取引先）・契約満了日（取引先）・延長契約満了日（取引先）・解約日（取引先） |

キー列は最終表示に残らないため、表示全列が同じという理由で異なる内部キーの行を勝手に重複と判定しない。代表行はサポートID・構成名・型式・製番・契約番号等で特定できるデータを選ぶ。

大きな並び順は納入先コード、サポートID、取引先状態（契約→途中解約→解約→その他）。その先にはパック区分や各ID・表示順等がある。同順位行の固定順を創作せず、必要な順序はSQLと控えた期待値で確認する。

## メッセージと0件

正常終了・0件に対する完了メッセージボックスはない。結果の更新・表示と、取得中ステータスが終わり操作可能になったことを確認する。0件はB20:AI20の見出しだけが残り、明細がない状態。

全空欄の入力チェックは警告で、メッセージIDは「－」。文言は次のとおり。

```
検索条件が指定されていません。

問合せを終了します。
```

旧結果のクリアが入力チェックより先にあるため、未入力で中止しても前の表示は消える。試験用コピーで扱う。未入力・片側だけの契約チェック・文字表記差・全エラー経路は主要ケースを増やさず補助候補とする。
