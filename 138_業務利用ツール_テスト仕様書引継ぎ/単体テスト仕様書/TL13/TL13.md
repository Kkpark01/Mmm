# TL13（簡易終息リストデータ取得） 単体テスト仕様書・本文案

対象：131の14「簡易終息リストデータ取得.xlsm」。必要最低限の主要4ケースで、取得条件・状態絞り込み・重複除去後の表示・0件・現行比較を確認する。会社編集版・実DB・業務マクロ実行は未確認。

凡例：
- 実施者：問合せシートを操作し、表示を照合する人。
- 準備担当者：検証DBの既存データから対象を選び、期待値を試験データ表へ記入する人。DBへ試験用登録しない。
- 試験データ表：検索条件・状態条件・SQL順序・内部キーによる末尾保持を反映した期待値。実行結果から逆算せず、未準備なら「準備未完」とする。
- 各ケースは独立した試験用コピーを使う。結果は同じ問合せシートに表示され、ファイルの自動出力はない。
- メッセージIDは「－」。実施区分は通常／要確認／開発者テスト／実施不可／除外候補。
- [用語表](用語表.md)に表示名・セル・実装根拠、[骨子](骨子.md)に範囲と補助候補を記載する。004・005のファイル出力は機能がなく、007は共通エラー範囲の確認待ちで本文なし。

## TL13-001

### 項番
TL13-001

### テスト項目
TL13（簡易終息リストデータ取得）：サポートIDを1件指定すると対象だけを取得し、重複除去後の34列を問合せシートへ表示すること。

### 前提条件
```
実施区分＝通常（既存データ確保後）。

【この試験で確認すること】
他の11検索欄が空でも全件一致にならず、指定サポートIDの機器がB20:AIへ表示されること。

【実施する人】
・実施者（検索と表示確認をする人）。
・準備担当者（元ビューから既存対象と重複除去後の期待値を用意する人）。

【実施者に必要なもの】
・マクロを実行できるExcel、検証DB接続・認証・ドライバーを準備した14フォルダー一式。
・外部テンプレート、追加パーツ表、TSSAファイルは不要。

【準備担当者が用意するデータ】
99で始まらない7桁の既存サポートID Sを選び、少数の機器が取得できることを確認する。両契約チェックは解除した条件で準備する。
元ビューの候補をSQL順に並べ、「個体管理ID / 機器明細ID」の同じキーは後ろを保持して件数Nを求める。異なる内部キーの行を、表示内容が似ているという理由で除かない。
そのうち1～3行を代表に選ぶ。可能なら内部キーに複数の候補があり、表示では他のキーと区別できるものを含める。なければ取得・表示は実施し、重複候補をまとめる分岐は未確認と記録する。先頭0のある製番等があれば含める。

試験データ表：
| サポートID S／重複除去後の期待件数N | |
| 代表行の内部キー（準備用）／表示で区別する構成名・型式・製番等 | |
| 納入先コード・名／システム名／客先契約状態／取引先契約状態 | |
| 品名／型式／シリアル番号／数量 | |
| 一次納入日／契約期限／取引先名／取引先契約番号 | |
| 同一内部キーの複数候補から保持される代表行の値と根拠 | |

【開始時の状態】
Excelを起動していなくてよい。試験用コピーを使用する。
```

### 操作内容
```
1. 試験用の簡易終息リストデータ取得.xlsmを開き、「問合せ」シートを選ぶ。
2. C2:C13をDeleteキーで空にし、C2（サポートID1）へSを入力する。先頭0がある場合も7桁を保持する。
3. 客先契約に対応する上側の「契約中のみ検索」（C14連動）、取引先契約に対応する下側の同チェック（C15連動）を両方解除する。
4. 「問合せ実行」（D1付近、後ろに装飾文字あり）を押す。取得中表示が終わり、新しい結果が表示され操作できるようになるまで待つ。完了メッセージは待たない。
5. B20:AI20が見出し、21行目以降がN件であることを確認する。B列にS以外のサポートIDがないことを確認する。
6. 準備した代表行を構成名・型式・製番等で探し、B・C・D・G・H・L・N～R・T・W・Xを試験データ表と照合する。複数候補を持つ代表キーを用意した場合、その行が準備した値で1行にまとまっていることを確認する。
7. 見出し・件数・代表行をエビデンスとして控え、試験用ブックは保存せずに閉じる。

【入力値】
C2＝S、C3:C13＝空欄、C14・C15のチェック＝両方解除。
```

### 期待結果
```
【画面確認】
・同じ問合せシートの20行目が34列の見出し、21行目から重複除去後のN件が表示される。
・B列サポートIDはSだけとなる。未入力欄が全件一致を引き起こさない。
・C＝納入先コード、D＝納入先名、G＝システム名、H＝客先契約状態、L＝取引先契約状態が準備値に一致する。
・N＝品名、O＝型式、P＝シリアル番号、Q＝数量、R＝一次納入日、T＝契約期限、W＝取引先名、X＝取引先契約番号が一致する。
・複数候補を持つ代表キーを用意した場合、SQL順で後ろにある準備済みの値を1行だけ表示する。先頭0を含む識別値が欠けない。
・新しいブックやCSVを作成せず、正常完了のメッセージボックスも表示しない。

【DB確認】
実施不要（参照とシート内加工のみ、DB更新なし）。
```

### 期待メッセージ
```
表示タイミング＝正常取得・表示完了時。
表示形式＝なし。
メッセージID＝－。
表示文言＝なし。完了メッセージボックスは実装されていない。
作業者操作＝取得中表示が終わって結果が更新された後、件数と内容を確認する。
```

### 備考
内部キー列は最終表示から削除される。画面上の機器管理ID列を探す手順にはしない。全内部キーの全項目照合ではなく、全件数と特定できる代表行で確認する。複数候補を持つ既存データが未準備なら、重複除去の当該確認は未確認として残す。

## TL13-002

### 項番
TL13-002

### テスト項目
TL13（簡易終息リストデータ取得）：客先・取引先の契約中のみ検索を両方選ぶと、両方が契約状態の機器だけを表示すること。

### 前提条件
```
実施区分＝通常（状態の異なる既存データ確保後）。

【この試験で確認すること】
2つのチェック条件がANDで働き、片側だけ契約の機器を両方契約の結果へ含めないこと。

【実施する人】
・実施者（両チェックを選択して検索する人）。
・準備担当者（元ビューの契約候補を確認して期待値を用意する人）。

【実施者に必要なもの】
・マクロを実行できるExcelと、検証DB接続・認証・ドライバーが準備済みの14フォルダー一式。

【準備担当者が用意するデータ】
同じ7桁サポートID Sについて、両契約状態が「契約」の代表機器Xと、少なくとも片側が契約以外の代表機器Yを既存データから選ぶ。
X・Yは異なる内部キーとし、Yの内部キーに両方契約の別候補がないことも確認する。検索・両契約状態で絞り込んだ後にSQL順で重複除去し、期待件数Nを求める。
チェックなしの最終表示だけを後から状態で間引いて期待値にしない。

試験データ表：
| S／両方契約での期待件数N（1件以上） | |
| Xの構成名・型式・製番・契約番号／両契約状態 | |
| Yの構成名・型式・製番・契約番号／両契約状態 | |
| Yに両方契約の別候補がない確認根拠 | |

【開始時の状態】
独立した試験用コピーから開始する。他のケースの取得結果は前提としない。
```

### 操作内容
```
1. 試験用ブックの「問合せ」でC2:C13を空にし、C2へSを入力する。
2. 上側の客先契約「契約中のみ検索」（C14連動）、下側の取引先契約「契約中のみ検索」（C15連動）を両方選択する。
3. 「問合せ実行」を押し、取得中表示が終わって新しい結果へ更新されるまで待つ。
4. 21行目以降がN件で、H列客先契約状態とL列取引先契約状態が全行「契約」であることを確認する。
5. Xが準備した値で存在し、Yに対応する行が存在しないことを、構成名・型式・製番・契約番号で確認する。
6. 結果を記録し、試験用ブックを保存せずに閉じる。

【入力値】
C2＝S、C3:C13＝空欄。C14・C15のチェック＝両方選択。
```

### 期待結果
```
【画面確認】
・重複除去後のN件となり、H・Lがともに「契約」の行だけを表示する。
・Xは存在し、片側非契約のYは存在しない。代表値が準備表と一致する。
・完了のメッセージボックスは表示しない。

【DB確認】
実施不要（参照とシート内加工のみ）。
```

### 期待メッセージ
```
表示タイミング＝正常取得・表示完了時。
表示形式＝なし。
メッセージID＝－。
表示文言＝なし。
作業者操作＝結果更新後に件数・状態・対象機器を照合する。
```

### 備考
片側チェックの2モードもSQLとリンク先を静的に確認しているが、主要実行ケースには増やさない。会社版でチェック連携・条件を変更した場合は補助確認を追加する。

## TL13-003

### 項番
TL13-003

### テスト項目
TL13（簡易終息リストデータ取得）：一致しない契約番号で検索すると明細が0件となり、前回の検索結果が残らないこと。

### 前提条件
```
実施区分＝通常（検索文字列の不一致確認後）。

【この試験で確認すること】
未入力の他検索欄が全件一致にならず、0件時には旧明細が消え、見出しだけが残ること。

【実施する人】
・実施者（0件になる条件で検索する人）。
・準備担当者（旧結果のある試験用コピーと、不一致の文字列を用意する人）。

【実施者に必要なもの】
・検証DB接続・認証・ドライバーが準備済みの14フォルダー一式、マクロを実行できるExcel。

【準備担当者が用意するデータ】
既存の表示結果がある試験用コピーを用意し、旧件数と代表の製番・契約番号を控える。
検索文字列Zは、元ビューの既存取引先契約番号に部分一致しないことを確認する。完全一致の契約がないだけでは不十分。LIKEのワイルドカード（%・_・角括弧）は含めない。
Zは試験入力として用意するだけで、DBへ登録しない。

試験データ表：
| 検索文字列Z／部分一致しないことの確認日時・根拠 | |
| 旧件数／代表の製番・契約番号／旧表示の最終行 | |

【開始時の状態】
旧結果のある独立した試験用ブックを使用する。
```

### 操作内容
```
1. 試験用ブックの「問合せ」でC2:C13を空にし、C12（取引先契約番号1）へZを入力する。2つの契約中のみ検索を両方解除する。
2. 「問合せ実行」を押し、取得中表示が終わり操作可能になるまで待つ。
3. B20:AI20の見出しは残り、B21以降に明細がなく、控えた旧最終行まで前回の製番・契約番号等が残っていないことを確認する。
4. 0件のメッセージボックスを待つ操作はせず、結果を記録してブックを保存せずに閉じる。

【入力値】
C12＝Z、C2:C11・C13＝空欄、C14・C15のチェック＝両方解除。
```

### 期待結果
```
【画面確認】
・B20:AI20の34列見出しだけが残り、21行目以降の旧明細は消える。
・未入力欄による全件取得が起きず、0件のまま表示が終わる。
・検索条件未指定の警告は出ない（C12には検索文字列が入っている）。「対象データがありません。」等の0件通知も実装されていないため表示しない。

【DB確認】
実施不要（参照と旧表示のクリアのみ）。
```

### 期待メッセージ
```
表示タイミング＝0件の表示完了時。
表示形式＝なし。
メッセージID＝－。
表示文言＝なし。0件用の通知は実装されていない。
作業者操作＝見出しと明細なしの状態を確認する。
```

### 備考
このケースは全空欄の入力チェックではない。旧データがある状態から検索し、見出しだけの表示を取得結果として確認する。

## TL13-006

### 項番
TL13-006

### テスト項目
TL13（簡易終息リストデータ取得）：同じ元データ・検索条件・契約チェックで現行版と改修版を実行し、件数と代表値を比較すること。

### 前提条件
```
実施区分＝要確認。同時点の元データを揃えられなければ実施不可。

【この試験で確認すること】
SQL Serverへ移行した後も、取得・状態絞り込み・重複除去後の表示が現行と一致すること。

【実施する人】
・実施者（両版を別々に実行して表示を控える人）。
・準備担当者（元データ時点・検索値・チェック状態を揃える人）。

【実施者に必要なもの】
・実行できる現行版と改修版、各接続・認証・Excel実行環境。別の試験用フォルダーへ置く。

【準備担当者が用意するデータ】
両DBの元データ時点が一致することを確認し、少量取得できる既存サポートIDを選ぶ。契約チェックの状態も事前に決める。
比較する1～3行は、構成名・型式・製番・契約番号等で特定できるものとする。内部キーは画面から削除されるため、表示に存在しないキー列を作業者へ探させない。

試験データ表：
| 両版のファイル名・接続先識別名／データ時点の一致根拠 | |
| C2:C13へ入れる検索値／客先・取引先のチェック状態 | |
| 比較代表行のサポートID・構成名・型式・製番・契約番号 | |

【開始時の状態】
両版の検索欄に保存済みの値があっても使わず、準備した条件へ揃える。
```

### 操作内容
```
1. 現行版を開き「問合せ」でC2:C13を空にして準備値を入れ、両契約チェックを準備した状態へ合わせる。「問合せ実行」を押し、結果更新まで待つ。
2. B20:AI20の見出し、明細件数、代表行の各値を比較用ブックの「現行」へ値で控える。ツールは保存せずに閉じる。
3. 改修版で同じ条件・チェックを設定して実行し、見出し・件数・代表行を比較用ブックの「改修」へ値で控える。
4. 列名で対応を合わせ、件数と代表行の値・状態・日付を照合する。日付は年月日、識別値は先頭0も含む文字、数量は数値で確認する。
5. 差があれば、対象行を特定する値・項目名・両値を記録する。比較結果を保存し、ツールは保存せずに閉じる。

【入力値】
両版で同じ検索値、同じ客先・取引先のチェック状態を使う。
```

### 期待結果
```
【画面・比較用ブック確認】
・34列の見出しと件数が一致し、代表行の状態・型式・製番・数量・契約日付等が一致する。
・差があれば、元データ時点、状態条件、SQL順と重複除去で保持される候補を確認する。理由が確定するまで合格にしない。

【DB確認】
更新結果の確認は不要。同時点の元データかは準備時に確認する。
```

### 期待メッセージ
```
表示タイミング＝正常取得・表示完了時。
表示形式＝なし。
メッセージID＝－。
表示文言＝なし。正常完了のメッセージボックスは実装されていない。
作業者操作＝両版の結果更新後、表示を比較する。
```

### 備考
全行の全列比較ではなく、全件数と代表値を比較する。現行版実行不可や元データ時点不一致は、実施不可の理由として記録する。取得中のステータス表示まで同じ文言にする期待は含めない。
