# TL10（納入機器登録確認） 用語表・根拠

2026-11-02。131の13「納入機器登録確認ver2.5.xlsm」を基準とする。VBA7モジュール、実際に取得するSQL3本、Excelの読み取り専用表示を確認。会社編集版・実DB・業務マクロ・生成結果は未確認。

根拠：[TL10調査記録](../../../../検証記録/20261102_業務利用ツール引継ぎ/TL10_調査)。source.jsonに元ブックのSHA-256、native_ui.jsonにボタン割当、parts_metadata.jsonに同梱パーツ表のシート構成とハッシュを保存した。

## 入力・操作

| 画面表示 | 場所・内容 |
|---|---|
| サポートID1／サポートID2 | 操作シートC2／C3。7桁形式へ整形し前後に%を付けて部分一致 |
| 納入先コード1／納入先コード2 | C4／C5。前後に%を付けて部分一致 |
| 追加パーツ表保存場所 | E6。同梱の追加パーツ適用表.xlsxの、利用PCでのフルパスを指定 |
| 納入機器 登録状態確認 | E2付近。Create_MachinList。4検索欄のうち1つ以上を入力して実行 |

4つの検索条件はOR。複数欄を使ってAND条件で絞るという期待値にはしない。空欄はNULLとして渡す。サポートIDに短い数値を入れると7桁へ0埋めされるため、試験では確認済みの7桁を使う。

追加パーツ表は、このフォルダーの同梱コピーを参照する。PCや配置先が変わればE6も変える。INIとは別の設定場所であり、DB接続先を変えてもE6の旧パスは自動修正されない。

パーツ表には「単独適用パーツ表」「複合適用パーツ表」「延長パーツ」が必要。実行前に閉じておく。元ブック・会社の共有原本を試験目的で書き換えない。

## 取得と表示位置

T31_00_default_01～03.sqlの結果を、31列を保って連結する。01は個体側、02は機器明細側、03は構成側の情報。各SQLの実データ件数をN1・N2・N3として、連結件数はN1＋N2＋N3。同じキーがあるという理由で重複除去しない。見出しは最初の取得だけに付ける。

SUPPORT_IDが99で始まる対象はSQLで除外される。存在するサポートIDなら必ず取得できるという前提にしない。

書込開始は**B2**。2行目が見出し、3行目以降がデータ。A列とAG～AKは照合用に使う。機器管理IDの列がある他ツールの手順を流用しない。

| 出力列 | 表示・意味 |
|---|---|
| A | 日付chk。確認対象の日付に問題があれば× |
| B・C・D・E | 納入先ｺｰﾄﾞ・納入先名・ｻﾎﾟｰﾄID・ﾌﾟﾗﾝﾄ名 |
| F・G・H・I | 構成側No・機器構成名・ｾｯﾄ数・手配製番。追加パーツ不足時はGへ説明追記、Hへ× |
| J・K・L・M・N・O・P | 機器明細側No・納入区分・製造ﾒｰｶ・品名・型式・機器分類・数量 |
| Q・R・S・T・U・V・W・X | 個体側No・取引先名・ﾌﾞﾗﾝﾄﾞ詳細名・取扱機器名・型式・ｼﾘｱﾙ番号・個体名・設置場所 |
| Y・Z・AA・AB・AC | 一次納入日・撤去日・契約期限・延長契約期限・備考 |
| AD・AE・AF | メーカ保守終息日・契約可能期限・終息備考 |
| AG・AH | 比較終息日・比較結果 |
| AI・AJ・AK | 延長期間・延長比較結果・延長パーツ期間 |

機器構成Noは出力最後に先頭8文字のプラント識別部を取り除く。最終結果はB・D・E・F・J・Qの順に昇順。キーが同じ行の順序まで一意とは保証しない。

## 照合内容

- 終息日：固定のメーカ保守終息日、または一次納入日＋契約可能年数と終息備考の補正からAGを作り、AAの契約期限と比較する。日付の不一致はAH、A列とAAの強調表示等で確認。
- 追加パーツ：同じプラント・構成に必要な単独／複合パーツがあるか、同梱表の機器ID・機器分類等で確認する。指摘時はGに不足内容、Hに×。
- 一次納入日：個体側Noがあり、ブランド詳細に撤去がなく、納入区分による免除対象でない行を確認する。空欄・日付以外、実行日との月差が過去240月超または未来2月超なら指摘。Yを灰背景・赤字・太字・斜体、Aを×とする。
- 延長：AAとABの月数をAI、パーツ側の月数をAKに置いてAJで照合する。【長期保守】や48か月の確認もある。

代表ケース004では一次納入日空欄の指摘を確認する。全パーツ・全日付補正・延長分岐を網羅するケースではない。

## 結果ブックと保存

最後に「納入機器」シートを新しいブックへ移す。**元マクロに結果シートが残る期待にしない。自動保存も行わない。** 新しい結果ブックで「名前を付けて保存」を行い、マクロなしのxlsxとして保存し、閉じて再読込して確認する。DBや機器マスタを修正する機能ではない。

## メッセージ

メッセージIDはすべて「－」。

| 条件 | タイトル・文言 |
|---|---|
| 検索欄が全空欄 | 検索キーが入力されていません。／検索キーを入力して実行してください。／空行／処理を中止します。 |
| パーツ表が開いている | タイトル：ファイルオープンエラー。「すでに追加パーツ適用表.xlsxが開いています。」／空行／「追加パーツ適用表.xlsxファイルを閉じて再実行してください。」 |
| パーツ表が存在しない | タイトル：ファイルチェックエラー。「追加パーツ適用表.xlsxが見つかりません。」／空行／「ファイルの参照先を確認して再実行してください。」。名前はE6の実ファイル名 |
| 指摘なしで終了 | タイトル：納入機器確認終了。文言：不正データは見つかりませんでした。 |
| 指摘ありで終了 | 同タイトル。文言：下記の問題点がありました。／空行／以下の該当行を順に連結 |

指摘行の文言と順序：
1. 「　・終息日の確認が必要な機器があります。」
2. 「　・追加パーツの確認が必要な機器があります。」
3. 「　・一次納入日の確認が必要な機器があります。」
4. 「　・【延長】終息日の確認が必要な機器があります。」
5. 「　・【延長】延長期間4年の機器があります。」

0件専用の正常終了メッセージは該当コードに見当たらない。「対象データがありません。」などを創作しない。0件・1行などの最小件数と全エラー経路は追加の確認候補として残す。
