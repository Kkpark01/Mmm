# TL01（取引先見積依頼書発行） 単体テスト仕様書

対象：取引先見積依頼書発行ver2.6.xlsm（改修版）。操作シート「取引先見積依頼書発行」に見積依頼Noを入力して「実行」を押すと、新MCM（SQL Server）から取引先見積の機器明細を取り出し、取引先向けの見積依頼書（Excel）を、ツールと同じフォルダーに保存する。DBは読むだけで、更新しない。

凡例：
- 実施者：試験を行う人。Excelでツールを実行し、操作シートと見積依頼書を確認する。
- 準備担当者：試験データを新MCMに登録し、試験データ表に値を書いて実施者に渡す人。
- 試験データ表：準備担当者が、登録した取引先見積の値を書く表。各ケースの前提条件にある。
- 見積依頼書：このツールが作るExcelファイル（シート名「保守見積依頼」）。
- 各ケースの「前提条件」「操作内容」「期待結果」は、そのケースだけを読んで実施できるように書いてある。他のケースは参照しない。
- 試験データの準備は準備担当者の役割とし、実施区分の判定には含めない。
- このツールにはメッセージIDがないため、期待メッセージの「メッセージID」は「－」とする。
- 実施区分：通常／要確認／開発者テスト／実施不可／除外候補（test-spec-common-rules.md 14.7章）

項番の欠番：

| 項番 | 理由 |
|---|---|
| 003 | 見積依頼Noが空欄のときのメッセージ。DBに接続する前に止まり、処理が元のツールと同じため、作らない（作成者の判断 2026/11/02） |
| 005 | 接続エラー。共通部品が TL11（店舗見積実績検索）と同じため、TL11-007 で確認する |

## TL01-001

### 項番
TL01-001

### テスト項目
TL01(取引先見積依頼書発行)：見積依頼Noを指定すると、見積依頼書がツールと同じフォルダーに決まった名前で保存され、ヘッダと操作シートに見積の情報が表示されること

### 前提条件
```
【この試験で確認すること】
操作シートに見積依頼Noを入れて「実行」を押すと、見積依頼書（Excel）が、ツールと同じフォルダーに「見積依頼書_納入先名 工場名＋日時」の名前で保存されること。見積依頼書の上部（ヘッダ）に、取引先名、見積依頼No、納入先、日付、保守の条件が表示され、コードが日本語の表示に置き換わっていること。操作シートの「出力データ情報」に、見積の情報とファイル名が表示されること。

【実施する人】
・実施者（試験を行う人）
・準備担当者（試験データを新MCMに登録する人）

【実施者に必要なもの】
・Excel（マクロを有効にできること）が入ったPC。
・改修版のフォルダー「04_取引先見積依頼書」一式を、PCにコピーしてあること。フォルダーの中の「Mcm移行部品」フォルダーも、同じ位置関係のままコピーする。
・OLE DB ドライバー（MSOLEDBSQL19）が、PCに入っていること。
・環境変数 MCM_MACRO_DB_USER、MCM_MACRO_DB_PASSWORD が、実施者のアカウントに設定されていること（設定は依頼元に聞く。値はこの仕様書に書かない）。
・接続先が本番ではないこと（依頼元に確認済みであること）。

【準備担当者が用意するデータ】
新MCMに、取引先見積を1件用意する（以下、見積X）。
・契約時間は1つ。
・機器構成を2つ（以下、構成1、構成2）。機器構成マスタの表示順は、構成1を構成2より前にする。
・構成1に機器明細を2件（以下、明細P、明細Q）。明細Pは数量2で、個体を2つ（シリアル番号あり）。明細Qは数量1で、個体を1つ（シリアル番号あり）。機器明細マスタの表示順は、明細Pを明細Qより前にする。明細P、Qの機器は、個体管理する機器分類のもの。
・構成2に機器明細を1件（以下、明細R）。数量1で、個体を1つ。明細Rの機器は、個体管理しない機器分類のもの。
・保守方法＝オンサイト（F）、点検有無＝あり、点検可能曜日＝月～土（2）、夜間対応有無＝なし。
・見積日付（依頼日）は、月か日が1桁の日付にする（例：2026/09/05）。回答期日にも日付を入れる。時間帯（保守契約時間帯）に値を入れる。
・納入先は、工場名と住所2に値があるもの。サポートIDは、先頭が「0」のもの。
登録が終わったら、見積Xの値を下の「試験データ表」に書いて実施者に渡す。値は、新MCMの画面かDBで確かめた値を書く。

試験データ表（準備担当者が記入する）：
| 項目 | 値 |
| 見積依頼No | |
| 納入先コード | |
| サポートID | |
| 納入先名 | |
| 納入先の住所1 | |
| 納入先の住所2 | |
| 納入先の工場名 | |
| プラント名 | |
| 見積日付（依頼日） | |
| 回答期日 | |
| 時間帯 | |
| 取引先名 | |

【開始時の状態】
Excelを起動していなくてよい。コピーしたフォルダー「04_取引先見積依頼書」に、「見積依頼書_」で始まるファイルがないこと（あれば別の場所へ移す）。
```

### 操作内容
```
1. エクスプローラーで、コピーしたフォルダー「04_取引先見積依頼書」を開く。「Mcm移行部品」フォルダーの McmMacroSettings.ini をメモ帳で開き、「Server=ILCM-SYSDEV」「Database=SYSDEV」と書かれていることを確認する。変更せずにメモ帳を閉じる。

5. 作られた見積依頼書が、別のウィンドウで開いている。そのシート名と、上部のセルを確認する。

TL01(取引先見積依頼書発行)：同じ見積依頼Noで、元のツールと改修版が作る見積依頼書の内容が一致すること

### 前提条件
```
【この試験で確認すること】
旧DB（Oracle）と新MCM（SQL Server）が同じ時点のデータを持っているとき、元のツールと改修版で同じ見積依頼Noの見積依頼書を作ると、シートのすべてのセルの値が一致すること。違ってよいのは、ファイル名の日時と、日付の表示の形だけ。

【実施する人】
・実施者（試験を行う人）

【実施者に必要なもの】
・改修版の試験（TL01-001など）が行えるPC。
・元のツールが動く環境（旧DBに接続できること。準備は依頼元に聞く）。
・元のツールのフォルダー一式を、PCにコピーしてあること（元のフォルダーでは実行しない。元のツールは、実行したフォルダーにファイルを作るため）。
・改修版のフォルダー「04_取引先見積依頼書」一式を、PCにコピーしてあること。
・旧DBと新MCMのデータが、同じ時点のものであること（移行のリハーサルの直後など）。依頼元に確認済みであること。

【準備担当者が用意するデータ】
なし（同じ時点の実データを使う。見積依頼Noは「SC202404278」）。

【開始時の状態】
Excelを起動していなくてよい。

```

```
