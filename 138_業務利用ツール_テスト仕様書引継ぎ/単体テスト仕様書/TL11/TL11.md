# TL11（店舗見積実績検索） 単体テスト仕様書

対象：店舗見積実績検索ver1.2.xlsm（改修版）。シート「問合せ」で機器型式・機器品名・製造メーカ・見積時間を入力して「問合せ実行」を押すと、新MCM（SQL Server）から状態が見積の店舗見積を探し、10行目から下に12列で表示する。DBは読むだけで、更新しない。

凡例：
- 実施者：試験を行う人。Excelでツールを実行し、シートの表示を確認する。
- 準備担当者：試験データを新MCMに登録し、試験データ表に値を書いて実施者に渡す人。
- 試験データ表：準備担当者が、登録した店舗見積の12列の値を書く表。各ケースの前提条件にある。
- 各ケースの「前提条件」「操作内容」「期待結果」は、そのケースだけを読んで実施できるように書いてある。他のケースは参照しない。
- 試験データの準備は準備担当者の役割とし、実施区分の判定には含めない。
- このツールにはメッセージIDがないため、期待メッセージの「メッセージID」は「－」とする。
- 実施区分：通常／要確認／開発者テスト／実施不可／除外候補（test-spec-common-rules.md 14.7章）

項番の欠番（旧→新）：

| 旧項番 | 新項番 | 内容 |
|---|---|---|
| 004 | 003 | 当たる見積が0件のときの表示を、TL11-003 に統合した（全角で入力して合格のとき、0件になるため）。004 は欠番 |

## TL11-001

### 項番
TL11-001

### テスト項目
TL11(店舗見積実績検索)：機器品名1に品名の一部を小文字で入力すると、大文字・小文字を区別せずに部分一致で探し、状態が見積の店舗見積だけが12列で、決まった順に表示されること

### 前提条件
```
【この試験で確認すること】
機器品名1に品名の途中の文字を小文字で入力して「問合せ実行」を押すと、その文字を含む品名の店舗見積が、大文字・小文字を区別せずに表示されること。状態が「見積」の店舗見積だけが表示され、「契約」の店舗見積は表示されないこと。12列の値が試験データと一致し、ﾊﾟｯｸ契約の小さい順、同じﾊﾟｯｸ契約の中では見積作成日の新しい順に並ぶこと。

【実施する人】
・実施者（試験を行う人）
・準備担当者（試験データを新MCMに登録する人）

【実施者に必要なもの】
・Excel（マクロを有効にできること）が入ったPC。
・改修版のフォルダー「11_店舗見積実績検索」一式を、PCにコピーしてあること。フォルダーの中の「Mcm移行部品」フォルダーも、同じ位置関係のままコピーする。
・OLE DB ドライバー（MSOLEDBSQL19）が、PCに入っていること。
・環境変数 MCM_MACRO_DB_USER、MCM_MACRO_DB_PASSWORD が、実施者のアカウントに設定されていること（設定は依頼元に聞く。値はこの仕様書に書かない）。
・接続先が本番ではないこと（依頼元に確認済みであること）。

【準備担当者が用意するデータ】
新MCMに、店舗見積を4件用意する（以下、見積A、B、C、D）。各見積には機器明細が1件ずつあり、その機器明細に単価が登録されている。
・品名：ほかの店舗見積に出てこない半角の英数字を含める。見積Aは「TL11TEST-A」、見積Bは「TL11TEST-B」、見積Cは「TL11TEST-C」、見積Dは「TL11TEST-D」とする（大文字で登録する）。登録前に、DBの既存データにこの文字を含む品名がないことを確認する。
・状態：見積A、B、Dは「見積」。見積Cは「契約」。
・ﾊﾟｯｸ契約：見積A、Bは0。見積Dは0以外の値（例：1）。
・見積作成日：見積Aは見積Bより古い日付にする。見積Dは見積A、Bのどちらよりも新しい日付にする。月と日の少なくとも一方は1桁にする（例：見積A＝2026/09/01、見積B＝2026/09/15、見積D＝2026/10/05）。
・サポートID：見積Aは、先頭が「0」のサポートIDのプラントの店舗見積にする。
・標準価格、仕切金：見積ごとに違う値にする。
・見積時間（保守契約時間帯）：指定しない（どの値でもよい）。
登録が終わったら、見積A〜Dの12列の値を、下の「試験データ表」に書いて実施者に渡す。値は、新MCMの画面かDBで確かめた値を書く。

試験データ表（準備担当者が記入する）：
| 見積 | サポートID | 出荷先名 | 見積作成日 | 取引先見積依頼No | 保守契約時間帯 | 取引先名 | 製造メーカ | 品名 | 型式 | ﾊﾟｯｸ契約 | 標準価格 | 仕切金 |
| A | | | | | | | | TL11TEST-A | | 0 | | |
| B | | | | | | | | TL11TEST-B | | 0 | | |
| C | | | | | | | | TL11TEST-C | | | | |
| D | | | | | | | | TL11TEST-D | | | | |

【開始時の状態】
Excelを起動していなくてよい。
```

### 操作内容
```
1. エクスプローラーで、コピーしたフォルダー「11_店舗見積実績検索」を開く。「Mcm移行部品」フォルダーの McmMacroSettings.ini をメモ帳で開き、「Server=ILCM-SYSDEV」「Database=SYSDEV」と書かれていることを確認する。変更せずにメモ帳を閉じる。

2. 「店舗見積実績検索ver1.2.xlsm」をダブルクリックで開く。画面上部に、マクロを有効にするかを尋ねる黄色の帯が出た場合は、帯のボタンを押下して有効にする。

3. シート「問合せ」を選ぶ。C2〜C7（機器型式1〜見積時間の入力欄）を選び、Deleteキーを押して、すべて空にする。（保存されたブックでは、C4に「EP8000」が入っている。）

4. C4（機器品名1）を選び、「l11test」（すべて小文字）と入力して、Enterキーを押す。

5. 「問合せ実行」ボタンを押下する。画面左下の表示が「準備完了」に戻るまで待つ。

6. 10行目から下の表示を、試験データ表と照合する。保守契約時間帯、ﾊﾟｯｸ契約、標準価格、仕切金の列は、セルを選んで、数式バーに出る値で照合する。見積作成日の列は、セルの表示と、数式バーに出る値の両方を見る。

7. Excelを閉じる。保存するかを尋ねられた場合は、保存しない方のボタンを押下する（ツールのブックを変えないため）。

【入力値】
・機器品名1（C4）＝l11test
・機器型式1、機器型式2、機器品名2、製造メーカ、見積時間（C2、C3、C5、C6、C7）＝空欄
```

### 期待結果
```
【画面確認】（手順5、6）
1. 10行目のB〜M列に、左から次の12個の見出しが表示される。
　サポートID、出荷先名、見積作成日、取引先見積依頼No、保守契約時間帯、取引先名、製造メーカ、品名、型式、ﾊﾟｯｸ契約、標準価格、仕切金
　（G列の見出しは「取引先名」。保存されたブックでは「サービス店舗」だが、実行すると置き換わる。）
2. 11〜13行目に、3行だけが表示される。14行目から下のB〜M列は空。
3. 3行の品名が、上から「TL11TEST-B」「TL11TEST-A」「TL11TEST-D」の順である（見積B → 見積A → 見積D）。
4. 品名が「TL11TEST-C」の行（状態が契約の見積C）は表示されない。
5. 3行とも、12列の値が試験データ表のその見積の行と一致する。
6. 見積Aの行のサポートIDが、先頭の「0」を含めて試験データ表と一致する。
7. 見積作成日が、月と日を2桁にした形で表示される（例：2026/09/01）。数式バーには日付の形（例：2026/9/1）で表示される。
8. 10〜13行目のB〜M列に格子の罫線があり、10行目の背景が灰色である。

【DB確認】
実施不要（このツールはDBを読むだけで、更新しないため）。
```

### 備考
```

【根拠】改修版 店舗見積実績検索ver1.2.xlsm。取引先見積検索モジュール SimpleQuery → McmNewDb.McmExportSqlServer "T07"。見積時間が空欄のため、内蔵SQL queries/T07_00_1_01.sql を使う（Jobs1）。抽出条件：MCM_UM_KIHON_MITSUMORI.JOTAI＝1、UPPER(品名) COLLATE Latin1_General_BIN2 LIKE UPPER('%入力値%')。並び順：PACK_FLG の小さい順（空は最後）→ MITSUMORI_DT の新しい順。列の型：Array(2,2,5,2,1,2,2,2,2,1,1,1)（McmWriteResult。5＝日付 yyyy/mm/dd、2＝文字列）。見出し：Jobs1 の AddHeaders。
```
