マクロ実行後に書き込まれる見出し（Jobs1 の AddHeaders）。保存されているブックの G10 は「サービス店舗」だが、実行すると「取引先名」に置き換わる（元のツールも、SQLの見出し行が「取引先名」のため同じ）。

書式と表示：
- 文字列の列（B、C、E、G〜J）は、マクロが文字列の書式を設定する。
- 見積作成日（D）は、SQLが yyyy/mm/dd の文字で返し、マクロが日付に変換して表示形式 yyyy/mm/dd を設定する（例：2023/07/10）。
- 保守契約時間帯、ﾊﾟｯｸ契約、標準価格、仕切金（F、K、L、M）は、マクロが書式を設定しない。セルに残っている書式（保存済みのブックでは「#,##0」や「¥#,##0」）で表示されるため、表示ではなく値で判定する。
- 書き込み後、B〜M列の幅が自動調整される。10行目の背景が灰色になり、見出しと明細に格子の罫線が引かれる（Adjust_Form）。
- 絞り込みボタン（オートフィルター）は、実行のたびに表示と非表示が切り替わる（Adjust_Form の引数なしの AutoFilter）。期待結果には入れない。元のツールでも同じかは未照合。

前回の結果の消え方：「問合せ実行」を押すと、最初に10行目（見出し）から下のB〜M列の値と罫線が消える。10行目の灰色の背景は残る（List_Clear）。このあとで、検索条件の確認と取得を行う。

## 6. 抽出条件（改修版の内蔵SQL queries/T07_00_0_01.sql、T07_00_1_01.sql）

- 対象：MCM_UM_KIHON_MITSUMORI の JOTAI＝1 の店舗見積（状態コード 1＝見積。mcm-system-knowledge.md 4章）
- たどるテーブル：基本見積（MCM_UM_KIHON_MITSUMORI）→ ブランド（MCM_UM_KIHON_BRAND）→ 機器構成（MCM_UM_KIKIKOSEI）→ 機器明細（MCM_UM_KIKIMEISAI）。単価（MCM_UM_TANKA）は、見積（MCM_UM_MITSUMORI）と機器明細の両方で結び付ける。どれかが欠けた見積は表示されない
- 機器型式1・2は型式、機器品名1・2は品名、製造メーカは製造メーカを、部分一致で探す。入力した欄のどれか1つに当たれば対象（OR）。空欄の欄は条件に使わない
- 大文字・小文字は区別しない（UPPER で比較）
- 見積時間に値があるときは、保守契約時間帯がその値の行だけ（AND）。空欄なら絞らない
- 同じ内容の行は1行にまとめる（GROUP BY）
- 並び順：ﾊﾟｯｸ契約の小さい順（空は最後）→ 見積作成日の新しい順（空は先頭）。元のツール（Oracle）の並びと同じ
- 全角・半角、ひらがな・カタカナの区別は、DBの照合順序で決まる。元のツール（Oracle）は区別する。
- 検証DB（SYSDEV）の照合順序（2026/11/02 照会。SELECTのみ）：DB、サーバー、MCM_UM_KIKIMEISAI の品名・型式・製造メーカの列が、すべて SQL_Latin1_General_CP1_CI_AS。マクロと同じ比較（UPPER と LIKE）を固定の文字で試した結果、次の4つがすべて「一致する」になった。
  - 半角「EP8000」を、全角「ＥＰ８０００」で探す
  - 大文字「EP8000」を、小文字「ep8000」で探す
  - カタカナ「サーバ」を、ひらがな「さーば」で探す
  - 全角カナ「サーバ」を、半角カナ「ｻｰﾊﾞ」で探す
- このため、変更前の改修版は全角・半角、ひらがな・カタカナを区別しなかった。
- 2026/11/02、改修版の検索SQLの比較5か所に「COLLATE Latin1_General_BIN2」を追加した（00_進捗.md 2.1章）。大文字・小文字は、今までどおり UPPER で区別しない。全角・半角、ひらがな・カタカナは区別する（検証DBでの実行で、全角「ＥＰ８０００」は0行、半角・小文字は1956行）。TL11-003 は合格になる見込み
- 【要確認】見積時間を入力したときのSQL（T07_00_0_01.sql）が「Ambiguous column name 'keiyakujikantai'」で失敗する（00_進捗.md 2.1章）。直すまで、TL11-002 は不合格になる
