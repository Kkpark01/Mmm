# TL08（点検依頼書作成） 単体テスト仕様書・本文案

対象：131の10「点検依頼書作成マクロ Ver3.10-8（改良版）_20260209.xlsm」。移行した取得条件と代表帳票の確認を主要5ケースへ絞る。会社編集版・実データでの実行は未確認。

凡例：
- 実施者：Excelを操作し、表示と出力ファイルを確認する人。
- 準備担当者：検証DBの既存契約、正規の貼付データ・資料から試験データ表を作る人。DBへ新規登録しない。
- 試験データ表：実施前に取得元から期待値を記入する。実行後の結果から逆算しない。必要資料や値が揃わない場合は「準備未完」とする。
- 各ケースは独立した試験用コピーで行う。DB接続は検証用と確認済みの設定・認証・ドライバーを使う。認証情報や原紙のパスワードをエビデンスへ写さない。
- 住所・基本情報にはXLOOKUP、明細にはTEXTSPLIT等を使うため、対応するMicrosoft 365等のExcelを使用する。
- メッセージIDはすべて「－」。実施区分は通常／要確認／開発者テスト／実施不可／除外候補。
- 構成・セル位置は[用語表](用語表.md)、補助確認と範囲は[骨子](骨子.md)を参照する。005の住所確認は004へ含める。007は共通エラーの代表確認待ちで本文なし。

## TL08-001

### 項番
TL08-001

### テスト項目
TL08（点検依頼書作成）：契約Noを1件指定すると、点検対象機器が12列で表示され、機器管理IDの重複が除去されること。

### 前提条件
```
実施区分＝通常（既存データ確保後）。

【この試験で確認すること】
G14の契約NoでMCMデータを取得し、件数・12列の値と識別値を確認する。未使用の9契約分を空欄にしても取得できること。

【実施する人】
・実施者（入力・取得・照合をする人）。
・準備担当者（検証DBの既存契約と対象機器を選ぶ人）。

【実施者に必要なもの】
・マクロを実行できるExcelと、検証DB接続を準備した10_点検依頼書作成の試験用コピー一式。
・今回はMCM取得だけなので、TSSA・NotesのCSV・原紙は使用しない。

【準備担当者が用意するデータ】
T22のSQLで取得できる既存契約Aを選ぶ。採用契約期間・点検回数・機器分類を確認し、機器管理IDで重複除去した後の全件数Nと各機器の値を記入する。少量の契約を優先する。
メーカー相違通知は、取得するメーカー名のいずれかに「NECフィールディング」が含まれない場合に「あり」、すべて含む場合に「なし」とする。

試験データ表：
| 契約No A／入力するサポートID（7桁）／期待件数N | |
| 機器管理ID一覧（重複除去後） | |
| 各機器の取引先契約状態／サポートID／製造メーカー名 | |
| 納入先名／納入先住所／ブランド詳細名／機器構成名 | |
| 機器品名／機器型式／シリアル番号／個体名／メーカ契約No | |
| メーカー相違通知（あり／なし） | |
先頭0のあるサポートIDやシリアル番号がある場合、文字列のまま記入する。

【開始時の状態】
Excelを起動していなくてよい。試験用コピーのG14・G16へ試験値を直接入れてよいが、マクロ本体は保存しない。
```

### 操作内容
```
1. 試験用ブックを開き、「EXCEL作成(NEC)」を選ぶ。
2. G14（契約No）へA、G16（サポートID）へ準備値を入力する。先頭0がある場合は文字列として入力する。
3. 「MCMデータ抽出」（J3付近）を押す。メーカー相違の通知が出た場合は全文を記録して「OK」を押す。抽出完了通知も記録して「OK」を押す。
4. 同じシートのK2:V2の見出しと、K3から下のデータを試験データ表と照合する。件数はV列のデータ行で数える。
5. 「点検依頼対象」を選ぶ。M列（機器管理ID）を完全一致で検索し、各IDが1行ずつ存在することを確認する。対象が少数のため、全IDを試験データ表と照合する。
6. 結果を記録し、試験用ブックは保存せずに閉じる。

【入力値】
G14＝契約No A、G16＝準備したサポートID。複数契約の区切りは入れない。
```

### 期待結果
```
【画面確認】
・抽出完了通知が表示され、メーカー相違通知の有無が準備値と一致する。
・K2:V2は、取引先契約状態、サポートID、製造メーカー名、納入先名、納入先住所、ブランド詳細名、機器構成名、機器品名、機器型式、シリアル番号、個体名、メーカ契約Noの順。
・明細は3行目からN件で、全機器の各値が準備値と一致する。サポートID等の先頭0が欠けない。
・「点検依頼対象」M列のID一覧が準備値と一致し、同じ機器管理IDの重複行がない。

【DB確認】
実施不要（参照のみ、DB更新なし）。期待値は準備時に取得元で確認する。
```

### 期待メッセージ
```
表示タイミング＝取得結果の転記後。
表示形式＝Excelメッセージボックス。
メッセージID＝－。
メーカー相違通知ありの場合は、先に次を表示：
製造メーカー名 と 依頼書作成先メーカーが異なっている可能性があります。

依頼書作成先メーカーが誤っていないか確認して下さい。
抽出完了の表示文言＝(*ﾟДﾟ)σデータ抽出よしっ！
作業者操作＝通知を記録し、それぞれ「OK」を押す。
```

### 備考
サポートIDは入力必須だが、取得SQLの絞り込み条件には使わない。期待件数をサポートIDだけで数えない。MCMの表示一覧を、そのまま帳票に自動転記するという期待は含めない。

## TL08-002

### 項番
TL08-002

### テスト項目
TL08（点検依頼書作成）：複数の契約Noを取得でき、1件に戻して再検索すると前の契約の結果や条件が残らないこと。

### 前提条件
```
実施区分＝通常（既存データ確保後）。

【この試験で確認すること】
「 / 」で区切った契約Noの分割、複数条件の取得、未使用条件と前回結果のクリア。

【実施する人】
・実施者（複数取得後に単一取得する人）。
・準備担当者（対象機器を区別できる2契約を選ぶ人）。

【実施者に必要なもの】
・マクロを実行できるExcelと、検証DB接続・認証・ドライバーが準備済みの10フォルダー一式。

【準備担当者が用意するデータ】
取得SQLに該当する既存契約A・Bを選ぶ。両者は異なる機器管理IDを持ち、各1件以上取得できること。単独時と同じIDで照合できるよう、データ更新を行わない時間帯に試す。

試験データ表：
| A／B／入力用サポートID | |
| Aの機器管理ID一覧・件数NA | |
| Bの機器管理ID一覧・件数NB | |
| 各契約で照合する機器品名・型式・シリアル番号 | |
| A＋B取得時／Aだけの時のメーカー相違通知有無 | |

【開始時の状態】
Excelを起動していなくてよい。独立した試験用コピーを使う。
```

### 操作内容
```
1. 試験用ブックの「EXCEL作成(NEC)」を開く。G14に「A / B」の形で準備値を入れ、G16にサポートIDを入れる。
2. 「MCMデータ抽出」を押す。表示された通知を記録し「OK」を押す。
3. 作成シートK3:Vの件数がNA＋NBであることを確認する。「点検依頼対象」M列でA・Bの全機器管理IDと重複の有無を確認し、同じ行のL列メーカ契約No・H列機器品名・I列機器型式を準備値と照合する。
4. 「EXCEL作成(NEC)」へ戻り、G14をAだけに変更して、もう一度「MCMデータ抽出」を押す。通知の「OK」を押す。
5. 一覧がNA件になり、V列にBが残っていないこと、「点検依頼対象」にBだけの機器管理IDが残っていないことを確認する。
6. 結果を記録し、試験用ブックは保存せずに閉じる。

【入力値】
1回目のG14＝A＋半角スペース＋/＋半角スペース＋B。2回目＝A。G16は準備値を維持する。
```

### 期待結果
```
【画面確認】
・1回目はA・Bの機器が揃ってNA＋NB件となり、契約Noと各機器の値が準備値に一致する。機器管理IDの重複はない。
・2回目はAのNA件だけとなり、Bの取得条件・明細は残らない。
・両回とも抽出完了通知が出る。メーカー相違通知の有無は各回の準備値に一致する。

【DB確認】
実施不要（2回とも参照のみ）。
```

### 期待メッセージ
```
表示タイミング＝各回の取得・転記後。
表示形式＝Excelメッセージボックス。
メッセージID＝－。
表示文言＝(*ﾟДﾟ)σデータ抽出よしっ！
準備値でメーカー相違通知ありの場合は、完了通知の前に次を表示：
製造メーカー名 と 依頼書作成先メーカーが異なっている可能性があります。

依頼書作成先メーカーが誤っていないか確認して下さい。
作業者操作＝通知を記録し、それぞれ「OK」を押す。
```

### 備考
通常の複数指定は最大10件。必要最低限の代表として2件を使う。全角区切り・最大10件の追加確認は骨子の補助候補とする。

## TL08-006

### 項番
TL08-006

### テスト項目
TL08（点検依頼書作成）：同じ元データ・契約Noで現行版と改修版を取得し、件数と対象機器の値を比較すること。

### 前提条件
```
実施区分＝要確認。データ時点を揃えられなければ実施不可。

【この試験で確認すること】
OracleからSQL Serverへの移行後も、契約Noで取得する対象・識別値・表示内容が一致すること。

【実施する人】
・実施者（両版で取得し比較する人）。
・準備担当者（元データと採用期間・取得条件を揃える人）。

【実施者に必要なもの】
・実行可能な現行版・改修版の試験用フォルダーと、各接続・認証・Excel実行環境。

【準備担当者が用意するデータ】
両DBの元データ時点・採用される契約期間が一致することを確認する。少数の対象機器がある同じ契約を選び、同じメーカー別シートで取得する。

試験データ表：
| 両版のファイル名・メーカー別シート・接続先識別名 | |
| 元データ時点・採用期間が一致する確認根拠 | |
| 契約No／サポートID／対象の機器管理ID | |

【開始時の状態】
Excelを起動していなくてよい。両版は別フォルダーに置く。データ時点が違うまま比較を開始しない。
```

### 操作内容
```
1. 現行版を開き、準備したメーカー別シートのG14・G16へ契約NoとサポートIDを入れ、「MCMデータ抽出」を押す。通知を記録して「OK」を押す。
2. 表示件数、K2:Vの見出しと全データ行を、別の比較用ブックの「現行」へ値でコピーする。「点検依頼対象」が参照できる場合は機器管理ID一覧も控える。ツールは保存せずに閉じる。
3. 改修版を開き、同じメーカー別シート・同じG14・G16で取得する。件数とK2:Vを比較用ブックの「改修」へ値でコピーし、機器管理ID一覧も控える。
4. 件数・対象機器と12列の値を照合する。同じ機器の契約No・型式・シリアル番号等で対応を取り、表示順が同じという理由だけで一致としない。差があれば対象機器・項目名・両値を記録する。
5. 比較結果を保存し、ツールは保存せずに閉じる。

【入力値】
両版で同じ契約No・サポートIDを使用する。
```

### 期待結果
```
【画面・比較用ブック確認】
・件数と対象機器が一致し、取引先契約状態からメーカ契約Noまで12列の値が一致する。先頭0・住所・シリアル番号が欠けない。
・差が出た場合は元データ時点・採用期間・重複除去・照合条件を確認する。原因が確定するまで合格としない。

【DB確認】
更新結果の確認は不要。同時点のデータかどうかは準備時に確認する。
```
