## 基準日と対象の選定

準備担当者は検証DBの `SELECT CONVERT(date, GETDATE()) AS 基準日;` で当日Dを確認する。実施中にDBの日付が変わった場合はD・期待表を取り直す。PC時計やファイル名だけでDを決めない。基準日は正常保存時のLog.csvにも記録される。

| 対象 | 条件 |
|---|---|
| ユーザ契約 | MCM.MCM_UK_KEIYAKUのJOTAI＝2。解約日がNULLまたはD以降 |
| 満了 | 延長契約満了日がNULLなら通常満了日がNULLまたはD以降。延長契約満了日ありなら延長満了日がD以降 |
| 契約期間 | MCM.MCM_UK_KIKANでYUKO_FLG＝0、Dを開始日～終了日に含む候補の最大UK_KIKAN_ID |
| 製番期間 | MCM.MCM_UK_SEIBANでDを開始日～終了日に含む候補の最大UK_SEIBAN_ID |
| 店舗 | 採用した契約期間のIRAITENPO_IDからMCM.MCM_MA_TENPOへ結合し、MEISHO4_NKで集計 |

比較は日単位で当日の境界を含む。期間・製番の終了日NULLを無期限にはしない。最大開始日ではなく最大IDを採る。製番確認区分等の追加条件は設けない。対象の期間・製番・店舗が欠ける契約は内部結合で除外される。

## 期待値の用意

出力済みの帳票から数値を写して期待値にしない。準備担当者が上記条件を満たす既存集合を照会し、店舗名ごとに次の期待表を用意する。参照SQLは137のソース/Report.sql、旧版の根拠は135の抽出SQL3本。SELECTと接続内一時表だけを使い、業務表を更新しない。

- E列：店舗名・ユーザ契約IDの組を重複除去した保守契約数。
- F列：店舗名・サポートIDの組を重複除去した契約サポートID数。NULLのサポートIDも1グループ。同じサポートIDの契約が複数でも1グループ。
- G列：採用した期間のHOSYU_GKINの合計。月額化・年額化しない。小数を四捨五入して整数にする期待値を作らない。

全抽出店舗について、DB上の店舗名、原紙D列の対応する店舗名・行番号、E/F/Gの3期待値を一覧化し、3列の合計と抽出店舗数Nも記入する。全抽出店舗が一意に原紙へ対応し、合計が整数かつ15桁以内であることを事前に確認する。対応できない実データは省略・改名せず、通常出力の準備未完として記録する。

代表の1～3契約は、採用する期間ID・製番ID・サポートID・店舗・金額も控え、3集計の根拠を確認する。重複サポートID、NULL、日付境界、期間の重なりは実在する条件があれば代表に含める。存在しなければ該当分岐を未確認とし、DBへ架空の契約を追加しない。

## 帳票の確認先

| セル・範囲 | 内容 |
|---|---|
| デフォルトフォーム | 対象シート |
| B2 | DB基準日Dの月。Excelの数式バーでは1～12の数値 |
| D4:D91 | 原紙の店舗名 |
| E3・F3・G3 | 保守契約数・契約サポートID数・保守金額（F3は改行を含む） |
| E4:G91 | 店舗別3値。抽出対象のない原紙店舗は空欄。対象があり集計値0の場合の0と区別する |
| E92・F92・G92 | 合計。式はそれぞれSUM(E4:E91)、SUM(F4:F91)、SUM(G4:G91) |

店舗名は「プロジェクトチーム」「カスタマーステーション」と半角空白を除いて照合し、英字大小文字・全角半角を区別しない。完全一致を優先し、なければ一意な部分一致を使う。複数候補・未一致・同じ行への複数店舗対応では保存しない。異なるDB店舗名が加工後に同じ行へ当たる場合、金額を勝手に合算しない。

原紙の値・列幅・行高・表示書式・印刷設定を維持する。過去のこのPCの確認では4ページに分割されたが、それを全PCの固定ページ数にはしない。会社PCで原紙と出力の印刷プレビューを比べ、1ページへの変更を期待しない。

## 同名ファイルの保持確認

既存帳票と原紙は、試験前後のSHA-256で不変を確認できる。PowerShellで次の「対象ファイルの絶対パス」を自分の試験コピー内の実ファイルへ置き換える。Hash欄を控え、Excelで開く前に再確認する。

```powershell
Get-FileHash -LiteralPath '対象ファイルの絶対パス' -Algorithm SHA256
```

上書き用の識別文字は原紙へ入れず、独立した試験コピー内の既存出力だけに入れる。原紙のハッシュが変わる、保存中止なのに既存帳票が変わる、処理終了後に作業用 `.mcm-report-*.xls` が残る場合は不合格とする。
