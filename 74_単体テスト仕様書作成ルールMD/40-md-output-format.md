# 単体仕様書：MDとExcelの出力

## 1. 基準Excelの実物を優先

作成前にシート一覧・順序・名前、画面情報・機能一覧・ケース表の見出し行、列名・幅、数式、入力規則、条件付き書式、集計範囲、管理シート、固定表示、印刷範囲・繰返し見出しを実物から確認する。

確認例：受領MCM契・解約単体261002版の1005Uと3004UはA～Pの16列だが、見出しはそれぞれ27行目・29行目だった。これは観測例であり、全画面の見出し行・ケース数・列数を固定する指定ではない。

## 2. 既存16列の対応例

| 列 | 役割 |
|---|---|
| A | 項番 |
| B | 分類 |
| C | テスト項目 |
| D | 前提条件 |
| E | 操作内容(入力値) |
| F | 期待結果 |
| G | 期待メッセージ |
| H | テスト結果 |
| I | 実施者 |
| J | 実施日 |
| K | 不具合内容 |
| L | 再テスト結果 |
| M | 再テスト実施者 |
| N | 再テスト実施日 |
| O | 最終判定（数式） |
| P | 備考／根拠 |

別の基準ブックがある場合はその構成を維持する。基準がない場合の案としてのみこの対応を使う。列の統合や管理シートの追加・削除は明示的な依頼がない限り行わない。

## 3. Markdown

対象画面ごとに画面ID・正式名称・到達経路・根拠版・機能一覧・ケース表・要確認事項を記載する。ケース表は基準の列に対応する。長文は省略せず、セル内改行は<br>、本文の区切り文字は\|等でエスケープする。必要なら段落形式の全文ケースからExcelへ転記してもよいが、列対応と項番を一意にする。

数式・入力規則・ピボット等のExcel機能は基準Excelを持つ実装へ復元する。MDのO列には式の代用となる固定「未実施」を書き込まない。対応関係を明記してExcel側に数式を設定する。

新規ケースの実績H～Nは空欄。新規仕様書でも例のOKや担当者・日付を残さない。改訂時は既存実績・証跡への参照を保持し、期待訂正と旧判定を区別する。対象外の実績欄への設定は基準の集計仕様に従い、意味を明記する。

## 4. Excel

既存の列・シート・書式・機能を保存し、必要な追加行へ数式・入力規則・書式を延長する。テスト行だけでなく集計・表範囲・印刷範囲も合わせる。シート別の見出し位置とケース範囲から更新し、「10行目開始」等を一括適用しない。

最終判定は初回／再テスト欄と基準の優先順に連動させ、集計がその列を参照することを確認する。初回OK→再テストNG等の代表値で計算確認し、検証用コピーを使う場合は納品版の実績を汚さない。集計の説明値・対象外件数・実施率も更新する。

書式付き長文の折返し、行高、結合セル、画面情報、最終行・長文行の表示と印刷を確認する。原本の出力時点で印刷範囲が不足している場合は、ケースの欠落を防ぐ必要な範囲を補正し記録する。

## 5. 成果物と保存

利用者が指定した数のExcelにまとめる。通常は仕様書全文のExcelと対応するMD、元項番の変更・分担対応、要確認事項、検証結果を保存する。細かなディレクトリやツールの固定は不要。原本を無断で上書きしない。

MDとExcelの項番・前提・操作・期待・メッセージ・根拠が一致することを確認する。内容が違う旧版を「最新版」として同時に案内しない。Excelを作っていない段階でExcel完成と報告しない。
