## VBと単純一致させていない点

- `.ng` は対象外。正式 `MCM.vbproj` に登録された `MCM1011U` を採用した。
- VBの承認履歴キーは12時間表記で衝突し得るため、Webでは24時間の秒単位日時を使用。未承認は日時と衝突しない固定キーにした。
- VBが同期間の表示済み承認履歴にも再捺印し得る処理は再現せず、未承認の審査/承認対象だけへ捺印する。契約と添付の承認状態が不一致の場合は承認を進めない。
- 担当外、限度額未設定・金額null等は、画面の非活性だけでなくサーバーでも拒否する。契約状態が既に承認済/差戻しの場合も、古い未処理添付を使って更新しない。
- 関連契約リンクの別タブ、共通通知、グレー配色、手動列幅調整はWeb共通方針を採用。ソートとページングは共通9章に従い追加しない。
- 固定列は通常プラント名まで。狭い画面・手動拡幅で右側の列を隠してしまう場合、契約NOまでの固定に縮退する。初期列幅の自動縮小はしない。
- 名前検索は正式VB SQLの `MAA.NONYUSAKI_NK` が根拠。「旧名・カナなど」というラベルだけを理由に旧名・カナ列のOR検索は追加していない。

## 配備環境で残る確認

SQL Server実接続・大量件数の性能・実ユーザー権限・多端末同時更新、保存先の実ファイル/アクセス権、Excelアプリでの印影/印刷、XLSMマクロ保持、実SMTP送信は未確認。H2ではSQL Serverのロック句を除き、日時CONVERTを同等の表示関数へ置換したため、実DBの排他性能の保証ではない。

捺印対象は1005Uと同じ `mcm.file.upload-path` 内の、DBの `DIRECTORY` が指す実ファイル。保存先未決定・ファイルなし・使用中なら承認を完了させずエラーとする。SMTPは既存Spring Mail設定を使用し、通知対象に送る設定がない場合は更新前に中止する。VB同様、上位担当者または送受信アドレスが空の場合・金額条件外はメール対象外。メール送信失敗は画面とサーバーログへ残すが、自動再送/永続メールキューは追加していない。

ファイルとDBは別の資源であり、プロセス強制終了まで完全に一体化する分散トランザクションではない。原本は同じ場所の `<ファイル名>.mcm1011.bak` に保持し、残っている場合は次の捺印を止める。異常終了・復元失敗時は管理者がDBのコミット状態とファイルを確認して復旧する。DB未確定のままバックアップを削除したり、承認済DBに古い帳票を戻したりしない。通常の成功/ロールバックでは自動後処理する。
