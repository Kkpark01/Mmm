# 保守契約状況データ取得：新MCM用・検証版

135で解析した「保守状況報告データ抽出」を、SQL Serverへ接続するWindows用ツールとして再作成しました。**使うのは137の「実行用」フォルダです。**

2026-10-30の再確認で、店舗名の英字大小文字・全角半角の照合を現行Excelに合わせて修正しました。実行ファイルは更新済みです。既に別PCへコピーしている場合は、実行用の.exeだけを差し替え、設定済みの.configは維持してください。[再確認結果](再確認結果.md)も参照してください。

現行のVBソースは未受領のため、実行ファイルから読み取った処理を根拠にC#で再作成しています。現行プログラムのソースをそのまま修正したものではありません。今回受領したExcel原紙をそのまま同梱しています。

## 使うもの

「実行用」フォルダの次の3ファイルを、まとめて会社PCの書き込み可能なフォルダへコピーします。

| ファイル | 役割 |
|---|---|
| 保守状況報告データ抽出.exe | 起動するプログラム |
| 保守状況報告データ抽出.exe.config | DB接続先等の設定 |
| 保守契約情報報告（月別）デフォルトフォーム.xls | 帳票の原紙。入力・加工せず同じフォルダに置く |

Microsoft Excelと.NET Framework 4系の実行環境が必要です。会社のWindows PCで実行します。Webアプリやjarへの組み込み、VBAの取り込みは不要です。「ソース」は保守・再ビルド用です。

## 最初の設定

`.exe.config` をメモ帳で開き、`value=""` 等の値を設定して保存します。**初期状態は接続先が空欄なので、DBへ接続しません。** 133と同じ接続先・認証を使用する場合は、対応する項目を転記できます。更新者の設定は不要です。

| 項目 | 設定内容 |
|---|---|
| Server | 検証DBのサーバー名。これまで伺った候補は `ILCM-SYSDEV,1433`。実際の接続先を確認して指定 |
| Database | 検証DB名。これまで伺った候補は `SYSDEV` |
| Authentication | 会社で利用している方式に合わせ、`Windows` または `SqlLogin` |
| TrustServerCertificate | 初期値false。会社の証明書・接続設定に合わせる |
| ConnectionTimeoutSeconds | 接続待ち秒数。初期値15 |
| CommandTimeoutSeconds | SQL実行の待ち秒数。初期値120 |

SQL認証の場合は、Windowsの環境変数 `MCM_TOOL_DB_USER` と `MCM_TOOL_DB_PASSWORD` に会社で確認した認証情報を設定し、ツールを開き直します。パスワードは設定ファイルへ書きません。131のマクロ用環境変数とは名前が違うので注意してください。

検証DBの認証方式・権限・証明書は今回未確認です。接続・取得に失敗した場合は、画面とLog.csvの内容を確認してください。

## 操作方法

1. `.exe` を開く。
2. 「開始」を押し、「処理を開始しますか？」に「はい」で進む。
3. 「データ取得処理中」から「エクセルデータ編集中」へ進み、「処理を終了しました。」と出るまで待つ。
4. 実行ファイルと同じフォルダの `MM月保守状況.xls` を開く。例：10月の実行なら `10月保守状況.xls`。
5. 店舗別の保守契約数・契約サポートID数・保守金額、および最下段の合計を確認する。

既に同じ名前の帳票がある場合は上書きの確認が出ます。「いいえ」なら既存帳票を変更しません。処理の開始・終了・対象店舗数・エラーは同じフォルダの `Log.csv` に記録します。

対象は **DBサーバーの実行日現在** の契約です。過去月を指定して検索するツールではありません。契約期間の金額を集計し、支払い月の月額計算へ変更する処理も追加していません。

処理中は開始・終了ボタンを押せません。DB取得とExcel編集は別スレッドで実行し、画面の日時・処理状況を表示します。SQL取得が失敗した場合はExcel出力へ進みません。対象0件の場合は、金額等が空欄の原紙に実行月を設定した帳票を保存し、Log.csvに0店舗と記録します。

## 現行から維持した内容

- 契約状態「2」、解約日、契約満了日・延長契約満了日の条件。
- 当日を含む有効フラグ0の契約期間のうち最大の期間IDを採用すること。
- 当日を含む製番期間のうち最大の製番IDを採用すること。終了日NULLを無期限へ変更しないこと。
- 契約数は店舗名・契約IDの組、契約サポートID数は店舗名・サポートIDの組で数えること。NULLのサポートIDのグループも1件として数えること。
- 保守金額は契約期間のHOSYU_GKINの合計。勝手な月額化・年額化をしないこと。小数の合計を丸めて整数扱いせず、現行の整数への変換と同様に確認すること。
- シート「デフォルトフォーム」、E列＝保守契約数、F列＝契約サポートID数、G列＝保守金額、B2＝実行月。
- 今回受領した原紙の列幅・行高・表示書式・合計式・印刷設定・XLS形式。

## 移行に合わせて変更した内容

- OracleClientと埋め込み接続情報を使わず、SQL Serverへ設定ファイルで接続する。
- TRUNC等をSQL Serverの式へ変換し、日付の時刻を切り捨てた場合と同じ抽出範囲を使う。
- 対象の契約集合を一度取得して接続内の一時テーブルへ保持し、3集計で共有する。業務テーブルの更新は行わない。
- 同じDB基準日を、抽出条件・帳票の月・出力名に使用する。現行のDB時計とPC時計の別参照を解消する。
- 3集計を配列の並び順で結び付けず、店舗名で照合する。
- 原紙の店舗名列D4:D91で対応を確認する。語句除去と半角空白除去の後、英字大小文字・全角半角の違いを区別せず、完全一致を優先し、なければ一意な部分一致を使用する。未一致・複数一致・同じ行への重複対応は保存前に中止する。
- 旧共有フォルダ・起動時のカレントフォルダに依存せず、同梱原紙と実行用フォルダを使用する。
- 原紙のコピーに書き込み、保存・Excel終了後に出力先へ配置する。原紙を直接変更しない。出力先が使用中の場合や店舗対応に失敗した場合は、既存帳票を保持する。
- Excelで正確に扱えない15桁超の値を、黙って丸めて保存しない。
- Excel保存後にログ出力だけ失敗した場合は、帳票が保存済みであることを通知する。

テンプレートの店舗と実DBの名称が一致するかは、実DBでの確認が必要です。見つからない店舗を省略したり、推測で別の店舗へ振り替えたりはしません。
