## 仕様書の誤りと分けるWeb実装差

### 18：同じ開始日での現在期間の変更

VBは元の期間を無効にして新しい期間を追加する。現行の期待はこのVBの処理と整合する。

Web `applyPendingKikan`は同じ開始日なら既存IDを新しいタブに引き継ぎ、元のタブを除く。元の期間を無効として保持し別IDを追加する処理になっていないため、タブ数・期間ID・有効値の期待との差が出る可能性がある。本文の期待をWebに合わせて縮めず、実装差として記録する。

### 19：未登録の変更案を再変更

VBは未登録タブを置き換える。現行の「タブが増えない」という期待と整合する。

Webは2回目の開始日が初回より後の場合も`previous.setSyuryoDt(...)`を行い、前の未登録タブを除かず次のタブを追加する。現行手順の翌日→2日後という操作では、未登録タブが増える可能性がある。これも仕様書の期待を変更して合格にしない。

根拠：VB `Mcm2006uScreen.vb:54–105,111–154`、`Mcm2006uTabControl.vb:640–663`。実際のWeb呼出経路は[Mcm2007uController.java:141](../../mcm-web/src/main/java/com/daifuku/mcm/controller/Mcm2007uController.java:141)→[Mcm2006uService.java:176](../../mcm-web/src/main/java/com/daifuku/mcm/service/Mcm2006uService.java:176)の`applyPendingKikan`。同メソッド183～189行と216行で分岐を確認した。実機で発生確認済みとはしていない。
