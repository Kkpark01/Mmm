# 点検マクロ2本の修正（TL07・TL08）

2026-11-02。131を基準に、テスト仕様書の確認で見つかった2点を修正した。131の本体と受領原本は変更していない。

## どちらを使うか

- **会社でExcelを編集している場合**：[会社編集版への反映手順](会社編集版への反映手順.md)に従い、3つの処理だけを変更する。修正版Excelを丸ごと上書きしない。
- **131から対象Excelを編集していない場合**：`修正版Excel/09_点検リスト作成` と `修正版Excel/10_点検依頼書作成` 内のExcelを、既存の同じ名前のExcelと差し替える。差し替え前に元ファイルをバックアップする。

この139は差し替え用の2本だけを含む。接続設定、原紙、参照資料は既存の配置をそのまま使う。139のExcelだけを別の場所へ置いて実行する構成ではない。両方の修正は別ファイルのため、反映順は問わない。

※仕様書のTL07は配布用フォルダーの「09」、TL08は「10」に対応する。

## 修正内容

| 対象 | モジュール／処理 | 変更 |
|---|---|---|
| 点検リスト作成ver1.53.xlsm | 点検データ抽出／Exclusion_ContList | 通常の点検対象に含まれる機器を解約一覧から除く際、フィルターで表示された削除対象行だけを削除。残す行と見出しを保持する |
| 同上 | 点検データ抽出／Edit_Duplication | 重複確認後も削除対象行だけを削除。確認キーE列と既存の並べ替え順を維持し、各キーの最後の行を残す |
| 点検依頼書作成マクロ Ver3.10-8（改良版）_20260209.xlsm | MCM情報取得／Start_UserInfo | 前回結果の最終行をT列だけでなくK～V列全体から求め、K2～V列の最終行までクリア。末尾シリアル番号が空欄でも旧結果を残さない |

TL07はデータ0行の場合の範囲逆転を防ぎ、削除対象0行の場合は削除せずに終了する。削除実行時のエラーを握りつぶす処理にはしていない。

## 検証結果

- 修正した3処理のVBAを、Excelの未保存ダミーブックで実行。SQL取得前で停止する代替処理を使い、実DB接続・メール送信は行っていない。
- 57項目に合格。行保持、削除対象なし／全件／見出しのみ、重複なし／全件重複／1件、末尾・全件シリアル番号空欄、空一覧、空文字を返す数式の末尾、結果欄外の値と入力欄の保持を確認。
- 追加で、離れた複数行の削除と、補助G列を非表示にした場合を確認。
- 修正版2本を保存後にExcelで再オープン。参照設定のリンク切れなし。VBA内は各1モジュールだけが変わり、変更は上記3処理に限定されることを照合。
- Excelファイル内部ではVBAプロジェクト以外の全構成ファイルが元と一致。シート、内蔵SQL、原紙、ボタン、入力値等を保持した。
- [検証記録](../../検証記録/20261102_点検マクロ修正)へ結果を保存。

## 残る確認

会社編集版との照合、反映後の業務ボタンからの一連動作、実DB取得は未確認。仕様書はTL07-005とTL08-003の正しい期待結果を維持し、139の反映確認後に実施する。

今回の修正に、TL07-004の出力前操作順や、TL08-004のTSSA・貼付形式の確認は含まない。移行前の原本にもあった2点の不具合を直したもので、全機能の試験完了を意味しない。
