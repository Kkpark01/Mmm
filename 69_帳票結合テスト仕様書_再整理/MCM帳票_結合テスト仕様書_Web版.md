# MCM帳票 結合テスト仕様書（Web版・第5版）

2026-10-07再整理。対象は従来どおり10帳票・9業務フロー。**51ケース、全件未実施**。67第3版52件から、同一観点3件を単体へ分担し、差戻し復旧・店舗見積排他の2件を追加した。既存項番は保持する。

[変更・重複整理記録](変更・重複整理記録.md)／[単体との対応・正誤表](単体との対応・正誤表.md)を併読する。単体65・66には未反映の誤記が残るため、この正誤表を適用して期待結果を統一する。67の旧Excelは第3版のままで、本第5版との同一成果物ではない。

## 手順と実施順の再確認（第5版）

51ケースを保持して、前提と操作の二重記載、出力前の内容照合、差戻し直後と再発行後の状態混同、復旧操作の省略を訂正。具体的な実施順とケース間の準備・復元は[実施順序と準備チェック](実施順序と準備チェック.md)に記載。ケース番号順に同じデータを使い回す前提にはしない。

## 実施準備

実環境に残るQ01〜Q06の確認先・操作・読み取りSQL・判定基準は[環境確認手順](環境確認手順_Q01-Q06.md)を参照。環境確認と各ケースの実績は分けて記録します。

専用検証DBと検証サーバーを用い、作成利用者・参照利用者・審査承認者・管理者を別セッションで用意。ローカル同士でも同じ検証DBへ接続していることを担当者が確認。実際の接続先と添付保存先はアプリ設定・起動ログから記録する。

各契約／見積の親ID・期間ID・機器キー・依頼NO・サポートIDを事前に採取。更新前後の画面と読取DB結果を証跡へ残す。例示A/Bは実際のテストデータへ置き換え、実在するIDや実績を作成済みと捏造しない。DB変更目的の直接編集は行わず、準備ができないものはQを確定するまで保留。

保存途中の異常は開発者が検証フックでRuntimeExceptionを1回発生させ、終了後に解除する。全ての帳票生成失敗で登録を戻すと仮定しない。1001Pの保存後生成と、2001Pのpublish内生成の境界を分ける。

単体合格を結合の実績として転記しない。共通の書式・計算確認は66に同梱正誤表を適用した実績を参照し、結合固有の登録値・親子所属・後続再検索・取得物との対応を別に判定する。Qがあるケースを未確認のまま合格にしない。

正常出力では生成→ファイル取得確認→必要ならZIP展開→Excelを開く→内容照合の順とする。出力・取得に失敗した場合はその段階を不合格として記録し、未取得の帳票内容を確認済みにしない。0件・拒否・異常系は新しい成功ファイルが返らないことを確認し、古いファイルで代用しない。

MDの最終判定は手動記入とする。初回・再テストの実績と証跡を残し、未実施・保留を合格に置き換えない。期待メッセージ「－」は通知不要を意味せず、固定文言を指定していない意味。拒否・失敗では理由と次の操作が分かる通知を確認する。
