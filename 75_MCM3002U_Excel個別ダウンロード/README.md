# 75：MCM3002U Excel個別ダウンロード

## 変更内容
出力ボタンで発注確認書（MCM3001P）、支払い明細（MCM3005P）の2つのExcelを、VBと同じ順序で個別に自動ダウンロードします。ZIP化と追加の選択ダイアログを廃止します。原紙の実体に合わせた.xls形式、帳票のレイアウト・計算・取引先別シート分割を維持しています。

対象は本体3ファイルと既存テスト1ファイルです。
- `src/main/java/com/daifuku/mcm/controller/Mcm3002uController.java`
- `src/main/java/com/daifuku/mcm/service/Mcm3002uExcelService.java`
- `src/main/resources/templates/mcm3002u/index.html`
- `src/test/java/com/daifuku/mcm/service/Mcm3002uExcelServiceTest.java`

検索は1回で、両帳票が生成できてからJSONのBase64データを返します。画面側で2つとも復号した後に保存を開始します。サーバーの一時ファイル・追加の保存先設定は不要。エラー通知、同じ画面への留まり、二重送信防止を維持。JavaScript無効時には案内して停止します。

## 反映方法
`src.zip`を展開して、最新プロジェクトのsrcへ同名ファイルを上書きし、クリーンビルド・再配備してください。本体3ファイルは一緒に反映してください。最新受領mcm-web/srcには未反映です。既存65～74のsrcと同名の変更ファイルはありません。

## 確認結果
- 最新本体405 Javaファイル＋差分のコンパイルに合格（ローカル依存を用いたjavac。正式Mavenビルドは未実施）。
- 帳票・検索サービスJUnit31件合格。通貨書式・数式・シート分割・6000明細の出力・入力境界を含みます。
- コントローラーのJSON→Excel復元、検索1回、順序、no-store、0件／入力／DBエラー、JavaScript無効時を確認。
- 実スクリプトの二重送信・ログイン切れ・不正な2番目の帳票・通信失敗・ボタン復帰を確認。
- Edge自動試験で実際に2つのExcelを取得し、ファイル名・順序・全バイトが生成結果と一致。HTTP応答は模擬環境、DBは使用していません。
- 最新受領src全546ファイルのハッシュ不変を確認。

## 反映後の操作確認・制約
1. MCM3002Uを開き、対象データが存在する支払い月と支払区分を指定して出力。
2. 発注確認書と支払い明細の.xlsが2つ取得され、ZIPが生成されないことを確認。
3. 各Excelを開き、指定年月・支払区分・取引先別シート・金額を確認。
4. 1つしか取得されない場合は、当該サイトの「複数ファイルの自動ダウンロード」をブラウザーで許可して再実行。ブラウザーの保存拒否をWebアプリから確実に判定することはできません。
5. 0件、不正な月、連打でも画面が操作可能に戻り、不要なファイルが出ないことを確認。

VBの保存先選択ダイアログ・Excel自動起動への完全準拠ではありません。今回は合意済みの自動ダウンロード方式です。保存先確認とExcel起動は利用者PC側の設定によります。
ZIP圧縮を外してBase64通信に変更するため、通信量は増えます（未圧縮Excelより約33%増）。6000明細の帳票生成は確認済みですが、検証サーバーの通信時間・ブラウザーの最大件数は未確認です。
