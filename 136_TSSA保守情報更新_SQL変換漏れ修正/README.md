# TSSA保守情報更新：SQL変換漏れの修正

## 原因

131のTSSA保守情報更新に内蔵したSQLに、Oracle用の `MONTHS_BETWEEN` が残っていた。SQL Serverに同名の組み込み関数がないため、取得時に「MONTHS_BETWEEN is not a recognized built-in function name」となっていた。こちらで作成した移行版の変換漏れ。

画面の「以前のデータは取り込みません」は、SQL取得が失敗した際に過去の取得結果を流用しないための通知。今回のSQLエラーの原因そのものではない。

## 使用するファイルと反映方法

修正版は [配布用のExcel](配布用/15_TSSA保守情報更新/TSSA保守情報更新ver2.0.xlsm)。SQLは組み込み済み。

1. 使用中のTSSA保守情報更新Excelを閉じる。
2. 現在使用しているExcelを、別の場所へバックアップする。
3. 136のExcelを、131の `配布用/MCM業務マクロ/15_TSSA保守情報更新` にある同名Excelへ上書きする。会社PCへコピー済みの場合は、その使用フォルダの同名Excelへ上書きする。
4. `Mcm移行部品/McmMacroSettings.ini` は上書きしない。現在の接続・認証設定をそのまま使用する。
5. Excelを開き直し、前回押した取得開始のボタンから実行する。失敗後の途中再開ではなく、最初から取得する。

バックアップに過去のサポートID対応表等を手修正していた場合、修正版へ必要な情報を引き継いでから実行する。この配布Excelは131に格納されている版を元にしており、会社PCで行った独自の編集内容までは含まない。

管理者用のSQLファイルは確認・保守用。通常の利用では、SQLファイルの配置やVBAの取り込みは不要。

## 変更内容と影響範囲

対象は `T05_00_default_07.sql`（取引先契約機器明細（TSSA連携用））だけ。

| 箇所 | 修正 |
|---|---|
| 年額換算C048 | MONTHS_BETWEENの2呼出を、SQL ServerのDATEADD・DATEDIFF等で計算する式へ変更。同一日・両月末は整数月、その他は31日基準の端数と時刻差を考慮 |
| 契約期間終了日の翌日 | 日付＋1をDATEADD(DAY,1,終了日)へ変更 |
| 初回契約日の前日 | 日付－1が残っていた6箇所をDATEADD(DAY,-1,初回契約日)へ変更。後続のDATETIME2型エラーを防ぐ |
| 支払回数の取引先分岐 | 同名列を持つ複数テーブルを結合しているため、TORIHIKISAKI_IDに契約期間側の別名TKBを明示。マスタ側と内部結合している同じキーを参照 |
| 時刻末尾2桁 | Oracleの負数開始位置に由来する2引数SUBSTRINGをRIGHTへ変更。時刻の末尾2桁を取得 |

12か月または支払回数1回なら仕切単価をそのまま採る分岐、その他は仕切単価÷契約月数×12という業務上の計算を維持。期間0か月等の不正データを勝手にゼロや別金額へ置き換える変更はしていない。

その他6本のSQL、出力51列の並び、抽出条件、VBA、表示シート、書式、ボタン、接続設定は変更していない。DB側への関数追加・定義変更は不要。132～135とは別ファイル。

## 検証結果

- ローカルSQL Serverだけに接続し、接続内の一時テーブルで7本のSQLを実行。列数は順に15・15・23・8・20・33・51で変更なし。一時テーブルは空のため、実データ抽出の一致や速度確認ではない。
- 日付・年額換算258パターンを、独立した期待値計算と比較。12か月・6か月・18か月、支払1回、月末、うるう年、日・時刻の端数、NULL、負額などを確認。
- 修正版をMicrosoft Excelでマクロ無効・リンク更新無効・読み取り専用で再オープン。内蔵SQLの分割数・文字数・本文が、検証したSQLと一致することを確認。
- Excel内部の差は `_MCM_SQL` の対象SQL本文・文字数を格納する6セルのみ。VBA、表示シート、他SQL、書式・ボタン等のファイル内部要素が同一であることを確認。表示と数式依存に変更がないため、画面の再描画検証は省略。
- 元の131のExcelは変更していない。今回のブックはVBAを保持するため、対象の内蔵SQLセルだけを限定的に更新している。

詳細は [検証記録](../../検証記録/20261030_TSSA_SQL修正) を参照。

## 実環境で残る確認

検証DBへの接続・実データでの取得開始からCSV出力までの一連動作は未実施。差し替え後、今回のエラーが出ないこと、7種類の取得後に後続処理へ進むこと、対応表・金額・出力件数を確認する。

既存の「新規プラントIDが追加されました。サポートIDを確認してください。」という確認停止や、対応表・IDの不整合時の中止処理は維持している。別の通知が出た場合は、その文言を確認する。

月数計算の根拠：[Oracle MONTHS_BETWEEN](https://docs.oracle.com/en/database/oracle/oracle-database/18/sqlrf/MONTHS_BETWEEN.html)、[Microsoft DATEADD](https://learn.microsoft.com/en-us/sql/t-sql/functions/dateadd-transact-sql?view=sql-server-ver15)、[Microsoft DATEDIFF](https://learn.microsoft.com/en-us/sql/t-sql/functions/datediff-transact-sql?view=sql-server-2017)。Oracle実機との照合は未実施であり、文書の仕様に基づく期待値との比較。
