# 62：MCM3001P 発注確認書

2026-10-02 19:45受領srcを基準に、VB版の発注確認書を照合して修正。出力元は **MCM3002U 支払い明細出力指示**。同時に生成するMCM3005P支払い明細にも、合計・通貨書式の修正を適用した。

## 変更内容

- 両帳票の金額合計を、VBと同じ `SUM` 数式へ変更。出力したExcelで明細金額を編集しても再計算できる。
- 支払い明細の合計欄に明細の「¥」書式を継承。原紙を超える件数でも維持し、件数欄は通常の文字表示とする。
- 印刷範囲を実際の出力行までに限定。発注確認書はA～J・合計行まで、支払い明細はA～I・件数行まで。原紙の用紙・向き・縮小率・列幅・余白・繰返し見出しを維持する。
- 不正な年月・null明細を事前に拒否。取引先コードが空ならシート名を「取引先」とし、.xlsの行数上限を実際の合計行に合わせる。
- 共通BaseExcelServiceを継承。原紙はこれまで通りJAR内から読み込む。
- 支払額計算テスト4件の条件をVB関数に合わせて修正し、年払いと初回繰越のテストを追加。**アプリの金額計算処理自体は変更していない。**

調査根拠と修正前の観点は[確認観点.md](確認観点.md)。画面、DB取得、権限判定、帳票原紙の変更はない。

## 出力確認の手順

1. メニューの「支払い明細出力指示」（MCM3002U）を開く。既にログインした同じアプリのURL末尾を `/mcm3002u` にする方法でも開ける。
2. 支払い予定が登録されている年月を `YYYYMM` で入力し、「年払い」または「月払い」を選ぶ。
3. 「出力」でZIPを取得し、展開した `YYYYMM_区分_発注確認書.xls` をExcelで開く。一緒に支払い明細.xlsも入る。
4. 取引先別シート、宛先、契約番号、年/月、種類、お客様名、金額、製番、灰色の合計行を確認する。金額を変更し、合計が再計算されることも確認する。
5. 印刷プレビューで原紙の見出し・列が収まり、合計行までが印刷対象となることを確認する。

「対象データが存在しません。」なら、その年月・支払区分の対象データがない。契約日だけでは判定できないため、支払予定月と区分を確認する。データを探すためのDB更新は不要。

VBではExcel保存・起動、Webでは2帳票をZIPダウンロードする既存方式を維持した。.xlsは受領原紙と同じ形式で、マクロ付きのファイルを新設していない。
