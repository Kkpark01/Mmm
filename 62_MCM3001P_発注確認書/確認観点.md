# MCM3001P 発注確認書：確認観点（修正前に整理）

基準：2026-10-02受領src。出力元は **MCM3002U 支払い明細出力指示**。発注確認書とMCM3005P支払い明細を同時出力する既存方式を維持する。

## 根拠

- `参照用/MCM_javaコンバート用/MCM_作業用/MCM_作業用/30_APPLICATION/40_ETC/MCM3001P/Mcm3001pExcel.vb`、同Constant・Data・Delivery、MCM3002U/Mcm3002uScreen.vb。
- CPExcelManager.vbのsetSumはSUM数式。MCM3005Pの合計も同じ方式。
- 最新srcの `templates/excel/MCM3001P_発注確認書テンプレート.xls` とMCM3005P原紙。実体は.xlsのため形式を保持する。
- 共通仕様1章の帳票実装基準、コーディング指針・テスト指針。

## 確認・修正範囲

| 観点 | 期待結果・修正前の状況 | 対応 |
|---|---|---|
| 出力導線・権限 | MCM3002Uから月・年払/月払を指定。共通Interceptorが出力URLも保護 | 既存経路を確認。画面・権限変更なし |
| 対象取得・金額 | 支払予定月・区分に該当する全件。サーバーで支払額を算出 | 既存取得・計算の回帰確認。0円・製番なしも除外しない |
| 取引先単位 | IDで分割、同じIDの小数尺度差は同一シート。安全なシート名 | 重複コード・禁止文字・空コードを検証 |
| 宛先・明細 | B2宛先＋様、D5年月、H5区分。16行目からB～JにVB通り出力 | セル位置、文字列コード・年/月・種類・金額を検証 |
| 合計 | VBはSUM数式。現状は両帳票の金額合計が固定値 | **優先1：数式に変更し、明細編集後も再計算可能にする** |
| 原紙・書式 | 列幅、字体、行高、通貨、外枠細線・内横極細、G:Hの内縦線なし、灰色合計 | 1件／原紙を超える件数で照合。原紙変更なし |
| 同時出力の退行 | 支払い明細はCInt相当の銀行丸め、実績合計・件数数式 | **優先1：合計金額セルの¥書式を明細から継承。件数セルは通貨にしない** |
| 印刷 | 発注確認書はA4縦・82%・横1ページ、1～15行を反復。原紙に印刷範囲なし | **優先2：実際の合計行まで、A～Jだけを印刷対象にする。支払い明細もA～I・件数行まで**。縮小率・余白等は維持 |
| 入力・件数上限 | 不正月・区分・0件・金額欠落は出力しない | 年0／月13／null行を事前拒否。行数上限コメントと制限を実際の合計行に合わせる |
| 保存・配布 | 2帳票完成後にZIP応答。Excel原紙をJAR内から読む | 共通BaseExcelServiceを継承しclasspath読込を維持。61との重複なし |

## 検証方針

実原紙から生成した.xlsをPOIで再読込し、合計数式を明細変更後に再評価する。複数取引先・0円・丸め・100件・6,000件・上限超過・入力不備、原紙との書式・印刷設定を確認。既存の支払額計算テストとJava全体コンパイルも実施する。

実DBで該当データを取得する操作、配備先、Excel実機の表示・印刷はローカル代替検証とは区別して記載する。
