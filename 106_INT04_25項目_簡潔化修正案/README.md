## 範囲・件数

基準は104の統合Excel。全25項番を維持し、実施対象を17件から15件、対象外を8件から10件へ整理する案。

- 07：旧期間の終了日を通常権限で補正して登録する分岐を外す。期間追加は05、未来期間の機器変更は06で代表確認する。現在期間の途中分割を確認済みとは扱わない。
- 16：重複する個体を2件の承認済み見積に含める通常の準備方法が未確定のため、通常の実施対象から外す。管理者・開発者向けの異常系として別途扱う。
- 既存対象外の03・09・11・20・22・23・24・25を維持する。今回の縮小後にどこまで確認するか、統合先の理由も更新した。

07・16を、あらゆる環境で絶対に実行不能と断定したものではない。07はVBの旧期間終了日自動変更が無効化され、通常権限では手入力できず、Webは自動調整するという差がある。管理者操作を追加してまで実施する条件を、今回の最小範囲から外した。16は準備方法が未確定であり、重複検出の処理がないという意味ではない。

## 残す項目の簡略化

- 01：2契約を画面で照合する。参照だけの全DB比較を省く。
- 02・04：セット数の確認に必要な構成1件・個体管理対象明細2件・各個体2件を明示。複数ブランド・見積の条件は持ち込まない。
- 05：元の終了日の翌日から新期間を追加する。元の機器と点検の保持、期間と次回更新日の保存に絞る。
- 06：採用個体を1件外し、期間内の備考を更新する。未採用候補への入替えをやめ、追加の候補個体を準備しなくてよい内容にした。
- 08：適用せず取り消し、親画面の未保存備考保持と再表示での保存値を確認する。
- 10：「ロック解除」権限がある担当者の通常の画面操作として、期間日付の連動だけを確認する。
- 12→13→17：HW01を追加、HW01を削除してHW02を残す、HW02を別人確認・月変更・再確認する流れを統一。17のBは更新権限、同時ログインは不要。
- 14：最新期間の点検1件削除と、残す点検・旧期間の点検の保持に絞る。
- 15：製番0件での保存と不足製番確認の表示を残す。基準年月＝当月・月数＝1を指定。実施者にビュー条件の判断を要求しない。
- 18・19：通常の画面で条件を用意できるため、VB／Web実装差の検出として残す。期限の延長をせず元の終了日を使い、18は同じ開始日、19は未登録案の置換を確認する。期待結果をWebの不一致に合わせて変更しない。
- 21：準備済みの満了日2項目を消して登録し、画面とNULLの保存を確認する。

全体で他契約・全機器・全監査値・ファイルハッシュの一律比較を省いた。画面で再表示できる項目は再表示で確認し、保存状態の判定に必要なID・日付・区分だけDB確認を残す。試験データはケース間で無条件に使い回さず、日付変更などが後続の前提を変える場合は同じ初期状態の別契約を割り当てる。

## 準備・表記

準備担当者が、契約NO・サポートID・開始日・機器や製番の識別情報・変更値を実施者へ渡す。日付はyyyy/MM/dd、製番の月と検索の年月はyyyy/MMで入力する。

本文は項番・分類・確認観点・前提条件・操作手順／入力値・期待結果・期待メッセージ・備考の8項目。ON／OFFではなく「チェックを入れる／外す」、編集画面は同じタブでの切替として記載した。DB作業は担当者の読取確認に分け、実施者によるDBの直接加工を要求しない。

15については、資料のMCM_ALERT6_Vと参照ビューで製番0件・解約日NULLの扱いを確認済み。配備DBとの同等性は未確認のため、準備時に対象行の表示を確認する。18・19で処理途中に期待外エラーが出た場合は記録して止め、後続を実施済みにしない。
