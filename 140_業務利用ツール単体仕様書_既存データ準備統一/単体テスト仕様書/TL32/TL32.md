# TL32（保守状況報告データ抽出） 単体テスト仕様書

準備方針：[共通方針と準備記録](../00_試験準備の共通方針.md)。このケースで使う既存入力値・期待件数・対象版を準備担当者が記入する。DBの試験データ新規登録は行わない。

対象：137の実行用「保守状況報告データ抽出.exe」。主要8ケース。実行用フォルダーからEXEを開く。年月や店舗の指定欄はなく、DBサーバーの当日を基準に全対象を店舗別集計する。

凡例：
- 実施者：ツールを操作し、コメント欄・出力Excel・Log.csvを照合する人。
- 準備担当者：検証DBの既存対象から、当日Dの店舗別3期待値と原紙の対応行を用意する人。DBへの試験用登録や既存契約の削除は行わない。
- T＝各ケース専用の試験フォルダー。137のEXE・設定・原紙をコピーし、検証DBへ接続する。配布用原本を編集しない。
- M＝Dの月2桁、N＝抽出されるDB店舗名の件数。「MM月保守状況.xls」のMMをMで置き換えて出力先を確認する。
- [用語表](用語表.md)に対象条件・集計方法・セル・ハッシュ確認方法、[骨子](骨子.md)に補助確認と結合候補を記載する。
- ケースごとにTを分ける。実行前データと当日期待値が揃うまで開始しない。メッセージIDはすべて「－」。会社版・実DBの一連動作は未確認。

## TL32-001

### 項番
TL32-001

### テスト項目
TL32（保守状況報告データ抽出）：当日有効な既存契約を店舗別に集計し、原紙を保持して新しいXLS帳票を保存すること。

### 前提条件
```
実施区分＝通常（当日期待値・原紙対応・検証接続の準備後）。

【この試験で確認すること】
店舗別の保守契約数・契約サポートID数・保守金額と、対象月・合計・保存先。

【実施する人】
・実施者（起動・帳票・ログを確認する人）。
・準備担当者（既存対象を照会して期待値表を作る人）。

【実施者に必要なもの】
・Microsoft Excel、.NET Framework 4系、検証DB接続を設定した137の実行用一式。
・書き込み可能な専用フォルダーT。当月の同名出力は置かない。

【準備担当者が用意するデータ】
用語表の条件・集計方法で、当日Dの全抽出店舗の3期待値と原紙D列の対応行を準備する。
対象1店舗以上とし、全抽出店舗が原紙へ一意に対応し、金額合計等が整数・15桁以内であることを確認する。
代表1～3契約の期間ID・製番ID・サポートID・金額で集計根拠を確認する。存在しない重複・NULL・境界条件は無理に作らない。
原紙のSHA-256、E92:G92の合計式、印刷設定を控える。

試験データ表：
| Tの絶対パス／検証DB基準日D／月2桁M | |
| 全店舗期待表の保存先／対象店舗数N | |
| 各店舗のDB名・原紙D列の名と行番号・E/F/G期待値 | |
| 3列の合計期待値／代表契約の根拠記録 | |
| 原紙のハッシュ／Log.csvの有無と最終行 | |

【開始時の状態】
同名出力がないTを用意し、原紙・出力をExcelで開いていない。
検証枠の対象データ変更を停止する。DB日付が変われば期待値を取り直す。
```

### 操作内容
```
1. Tの保守状況報告データ抽出.exeを開く。画面タイトルと「開始」「終了」を確認する。
2. 「開始」を押し、「処理を開始しますか？」で「はい」を押す。
3. コメント欄の取得・Excel編集の表示を確認する。処理中は開始・終了が非活性であることを確認し、完了まで待つ。
4. 「処理を終了しました。」と保存先が表示されたら記録する。完了ダイアログは待たない。開始・終了が再び押せることを確認する。
5. Tの「M月保守状況.xls」を開き、「デフォルトフォーム」のB2、D4:D91、E4:G91、E92:G92を試験データ表と照合する。
6. E92:G92を選び、数式バーの合計式を確認する。原紙と見出し・列幅・行高・表示書式・印刷プレビューを比較し、出力は保存せず閉じる。
7. Log.csvの今回分を開き、保存完了の基準日D・店舗数N・出力パスを照合する。原紙のハッシュ不変と、作業用.mcm-report-*.xlsが残らないことを確認する。

【入力値】
年月・店舗の入力なし。処理開始確認＝はい。
```

### 期待結果
```
【画面確認】
・取得からExcel編集へ進み、コメント欄に「処理を終了しました。」とT内の出力パスが表示される。
・開始・終了が再び有効になる。上部のPC日時を帳票基準日に読み替えない。

【ファイル確認】
・Tに月2桁Mの「M月保守状況.xls」が1つ作成される。ZIPやCSVの帳票にはならない。
・シート「デフォルトフォーム」のB2の月はDの月。原紙D列の各対応行のE＝保守契約数、F＝契約サポートID数、G＝保守金額が期待表に一致する。
・抽出されない店舗のE:Gは空欄。集計値が0の店舗を対象なしの空欄と混同しない。
・E92・F92・G92は各4～91行の合計式を保持し、計算結果は期待合計と一致する。
・見出し、列幅・行高、表示書式、印刷設定が原紙と一致し、原紙のハッシュは変わらない。原紙の印刷分割を1ページに変更する期待はない。
・Log.csvの今回分に「処理開始」と「保存完了: D / 店舗 N件 / 出力パス」がある。Dはyyyy/MM/dd形式。作業用ファイルは残らない。

【DB確認】
実施不要（業務表は参照のみ。期待値準備のための読み取り照会は準備担当者が実施）。
```

### 期待メッセージ
```
1. 表示タイミング＝「開始」押下時。
表示形式＝確認ダイアログ（タイトル「処理開始確認」、はい／いいえ）。
メッセージID＝－。
表示文言＝処理を開始しますか？
作業者操作＝はいを押す。

2. 表示タイミング＝帳票の保存・終了ログ後。
表示形式＝画面中央のコメント欄。
メッセージID＝－。
表示文言＝処理を終了しました。
次行に出力ファイルの絶対パス。
作業者操作＝画面を記録し、表示された出力を開いて照合する。
```

### 備考
金額を月額化せず、同一店舗・サポートIDの重複とNULLのグループを考慮する。短い途中表示を撮れなかった場合はその確認を未確認と記録し、完了結果だけで途中の活性制御まで試験済みにしない。会社PCの印刷プレビューは実機確認が必要。

## TL32-004

### 項番
TL32-004

### テスト項目
TL32（保守状況報告データ抽出）：同名帳票の上書きに同意すると、既存の旧表示を当日の集計へ置き換え、原紙を変更しないこと。

### 前提条件
```
実施区分＝通常（正常取得できる設定・既存出力・当日期待値確保後）。

【この試験で確認すること】
新規作成ではなく、同名ファイルを置き換える保存経路。

【実施する人】
・実施者（上書きに同意し、出力・原紙を照合する人）。
・準備担当者（既存出力と当日期待表を用意する人）。

【実施者に必要なもの】
・設定済み137一式、Excel、専用T。

【準備担当者が用意するデータ】
001と同じ基準で当日D・店舗数N・全店舗期待値・原紙対応を確認する。
独立した試験コピーTに、以前生成できた有効な帳票を当月の出力名で置く。
その既存出力の、期待表でデータが入る店舗行rのEセルだけに「旧結果確認用」と入力して保存・終了する。原紙には入力しない。
既存出力と原紙のハッシュ、Log.csvの最終行を控える。

試験データ表：
| T／D／M／全店舗期待表／N | |
| 店舗名・行r／E:rに入れた識別文字／期待するE/F/G | |
| 既存出力のハッシュ／原紙のハッシュ／ログ位置 | |

【開始時の状態】
Tに同名の既存帳票があり、出力・原紙ともExcelで閉じている。
```

### 操作内容
```
1. TのEXEを開き、「開始」→「はい」で取得する。
2. 「保存確認」で「同名の帳票があります。上書きしますか？」とT内の既存出力パスが表示されることを確認し、「はい」を押す。
3. コメント欄の「処理を終了しました。」を確認する。
4. 同じ出力パスの帳票を開き、行rのEセルから「旧結果確認用」が消え、数値が期待値になったことを確認する。
5. 当日月・店舗別3値・合計を期待表と照合し、帳票は保存せず閉じる。
6. 原紙のハッシュが不変で、Log.csvの今回分に保存完了のD・N・同じ出力パスがあること、作業用ファイルが残らないことを確認する。

【入力値】
処理開始確認＝はい、保存確認＝はい。
```

### 期待結果
```
【画面確認】
・保存確認の出力先は準備した既存帳票。はいの後、正常完了のコメントと出力パスを表示する。

【ファイル確認】
・既存パスが当日の帳票へ置き換わり、旧識別文字は残らない。期待表の店舗別3値・月・合計に一致する。
・原紙のハッシュは不変。同名帳票を連番等の別ファイルに増やさず、作業用ファイルを残さない。
・今回のLog.csvに保存完了がある。上書きキャンセルの記録にはならない。

【DB確認】
実施不要（参照のみ、DB更新なし）。
```

### 期待メッセージ
```
1. 表示タイミング＝開始時。
表示形式＝確認ダイアログ「処理開始確認」（はい／いいえ）。
メッセージID＝－。
表示文言＝処理を開始しますか？
作業者操作＝はいを押す。

2. 表示タイミング＝取得完了後、同名出力が存在する時。
表示形式＝確認ダイアログ「保存確認」（はい／いいえ）。
メッセージID＝－。
表示文言＝同名の帳票があります。上書きしますか？
次行に既存出力ファイルの絶対パス。
作業者操作＝パスを確認してはいを押す。

3. 表示タイミング＝上書き完了後。
表示形式＝コメント欄。
メッセージID＝－。
表示文言＝処理を終了しました。
次行に出力ファイルの絶対パス。
作業者操作＝同じパスの帳票を開き、旧表示が置き換わったことを確認する。
```

### 備考
001の新規ファイル作成とは保存経路が異なる。識別文字は試験用既存出力だけへ入れる。ファイル名が同じという確認だけでは、上書き成功と判定しない。

```

## TL32-006

### 項番
TL32-006

### テスト項目
TL32（保守状況報告データ抽出）：同一基準日・同一元データの現行版と137で、店舗別3集計と合計が一致すること。

### 前提条件
```
実施区分＝要確認。実行可能な現行版・同時点の両DB・現行帳票の取得経路が揃わなければ実施不可。

【この試験で確認すること】
保存場所等の意図した変更を除いた、店舗別の契約数・サポートID数・金額の維持。

【実施する人】
・実施者（両版を実行し、出力Excelを比較する人）。
・準備担当者（基準日・両DBの対象・原紙対応と保存先を確認する人）。

【実施者に必要なもの】
・動作する現行版と接続環境、設定済み137一式、Excel、両版別の出力保存場所。
・現行版は135の解析資料ではなく、実行可能なEXEを使う。

【準備担当者が用意するデータ】
両DBが同じ日Dで、当日対象の契約・期間・製番・店舗・金額・サポートIDが同時点で一致することを確認する。
期待値は用語表の条件で準備し、両版が同じ結果という理由だけで正しいと判定しない。
現行版は旧共有原紙と実際の保存先を事前に確認し、業務帳票を上書きしない出力方法を確保する。現行原紙の店舗・合計式が比較できることも確認する。
137は同名出力のない専用Tを使う。出力比較が終わるまで両版のファイルを上書きしない。

試験データ表：
| D／同時点データの確認記録／全店舗3期待値と合計 | |
| 現行EXE・共有原紙・実際の出力先と識別方法 | |
| 新版T／両原紙の店舗対応／旧PCの月とDB基準月 | |

【開始時の状態】
両版で正常取得・原紙到達・出力取得が可能。検証枠の並行更新を停止する。
```

### 操作内容
```
1. 現行版を開き、「開始」→「はい」で実行する。コメント欄の「処理を終了しました」を記録する。
2. 準備担当者が確認した現行側の出力を取得し、比較用として別に保管する。実ファイルが取得できなければ比較を中止する。
3. 137のTでEXEを開き、「開始」→「はい」で実行する。コメント欄の「処理を終了しました。」と保存パスを確認する。
4. 両出力の「デフォルトフォーム」を開き、行番号だけでなくD列の店舗名で対応を取り、各店舗のE・F・Gと合計を比較する。同じ期待表とも照合する。
5. 新版のB2と出力名はDB基準日Dの月、現行の月は現行PC月を根拠に確認する。保存先・ログの全文一致は求めない。

【入力値】
両版とも年月入力なし、開始確認＝はい。
```

### 期待結果
```
【画面確認】
・現行は「処理を終了しました」、新版は「処理を終了しました。」と保存パスをコメント欄へ表示する。

【ファイル確認】
・同じ店舗の保守契約数・契約サポートID数・保守金額と3合計が両版で一致し、準備した期待値にも一致する。
・原紙の行順や名称に違いがあっても、対応できない店舗を省略して合格にしない。
・新版は同梱原紙と実行用フォルダーを使い、B2・月2桁の出力名がDB基準月に一致する。原紙の書式と合計式を保持する。

【DB確認】
実施不要（参照のみ。両DBの元データ一致は準備段階で確認する）。
```

### 期待メッセージ
```
1. 表示タイミング＝両版の開始時。
表示形式＝開始確認のダイアログ。
メッセージID＝－。
表示文言＝処理を開始しますか？
作業者操作＝はいを押す。

2. 表示タイミング＝各版の正常終了時。
表示形式＝コメント欄。
メッセージID＝－。
表示文言＝現行：処理を終了しました
