# TL31（サポートID付替プログラム） 骨子

133のコードを根拠に本文8件を作成。既存データを使うDB更新試験。更新対象・対象外・復元方法を事前に控える。

| 項番 | 目的 | 主な確認先 |
|---|---|---|
| 001 | 未使用先へ付替え | 元Aの5表、対象納入先、フラグ・監査項目、画面と確定ログ |
| 002 | 既存先へ付替え | 先Bの既存行保持、共有納入先は正当な更新対象として識別 |
| 003 | 入力エラー4条件 | 元空欄・元未登録・先空欄・元先同一の独立判定、DB不変 |
| 005 | 開始取消 | 開始確認キャンセルとDB・ログの不変 |
| 006 | 現行比較 | 同時点の独立環境、業務値だけを比較 |
| 007 | 設定不足で起動中止 | 専用設定のServerを空欄、起動エラー・更新なし |
| 008 | 入力・参照制御 | 7文字上限、納入先とメッセージ欄の読取専用 |
| 009 | 終了確認 | キャンセルで継続、OKで終了 |

004は帳票出力機能がないため対象外。対象表0件・複数プラント／納入先・BIGINT等は001の準備表で適用可否を記録する。元ID空白は003の未入力チェックと同じTrim分岐なので、必要な場合は入力値を半角空白に替えて独立判定する。各条件を実施済みと一括判定しない。

途中失敗時の複数表ロールバック、Webとの同時更新、DTS連携先への反映は結合テストへ移管。取得失敗やログ出力障害は開発者の独立テストへ割当て、共有環境を壊す通常手順を作らない。既存の133・134模擬検証は根拠として参照するが、会社環境での合格扱いにはしない。

[確認観点対応](../TL30-32_確認観点対応.md)に、残す確認の割当て・対象外理由を明記する。実DB実行は未実施。
