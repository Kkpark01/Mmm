# TL30（申請前check.vbs） 用語表・根拠

2026-11-02。利用者の「旧版を参照して作成」に従い、旧VBSから移行先の試験仕様を作成した。移行版コードは未作成・未受領。本文6ケースは実装後の要求であり、現時点で実行可能という意味ではない。業務コードの改修・DB実行は今回行っていない。

## 旧版に存在する動作

| 対象 | 根拠と採用する業務動作 |
|---|---|
| 起動 | 申請前check.vbs。Excel・Webメニューのボタンではない |
| 入力 | 見積Noを入力してください。店舗基本見積の見積Noで、見積依頼Noや契約Noではない |
| 検索 | MCM_UM_KIHON_MITSUMORI.UM_MITSUMORI_NO＝UPPERした入力文字列 |
| 結合 | UM_KIHON_MITSUMORI_IDでMCM_UM_MITSUMORIへ結合 |
| 明細 | MITSUMORI_GKIN・KAISI_DT・SYURYO_DT。開始日昇順。同じ開始日内の順序は未指定 |
| 状態・重複 | 状態や有効フラグでの追加絞り込み、重複削除はない |
| 結果 | 見出し【見積金額】。各行は【金額】yyyy/mm/dd - yyyy/mm/dd |
| 金額 | 旧書式FML999,999,999。通貨記号は旧DBのNLS設定に依存し、旧表示または同じ条件の照会で期待文字列を控える |
| 再試行 | 前回見積Noを初期値にして再入力。結果文字列はクリア |
| 正常0件 | 見出しだけ。FEEDBACK OFFのため専用の対象なし通知は生成しない |
| 更新・帳票 | DB更新もExcel帳票もなし |

原本はOracle/sqlplusとReqEst.sql・店舗見積額.txtを使う。新MCMの接続方式は実装で用意する。旧作業ファイルの生成や旧認証の引継ぎを業務上の必須要件にはしない。旧原本を新MCM用として実行しない。

## 原本と区別した移行要求

| 原本の不足 | 今回の試験仕様で定めた要求 | ケース |
|---|---|---|
| 入力の空文字を判定せず検索する | 入力キャンセル・空欄OKは追加通知なしで終了し、検索しない | 005 |
| 業務用の例外処理と失敗通知がない | 前回結果や正常0件と区別し、失敗通知後に終了 | 007 |

007の「データの取得に失敗しました。接続先と入力した見積Noを確認してください。」は今回定めた移行設計要求であり、旧版で確認した文言ではない。実装時に別文言を採用する場合は、操作・期待メッセージと実装を一緒に改訂する。実装済みとは報告しない。

## 試験データ

既存A・Bと一致しないZを準備し、各見積の全明細の金額表示・期間・件数を控える。結果から期待値を逆算しない。複数明細・英字・同じ開始日が実在しない場合、その分岐を未確認と記録する。NULL金額や旧書式上限を超える額の表示は、通常データから推測しない。

接続方式・起動パス・旧新の項目対応は、[実施前確認票](../TL30-32_実施前確認票.md)へ記入する。移行版未作成の現時点では6ケースとも実装待ち。
