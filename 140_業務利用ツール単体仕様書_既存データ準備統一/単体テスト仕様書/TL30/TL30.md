# TL30（申請前check.vbs） 単体テスト仕様書

準備方針：[共通方針と準備記録](../00_試験準備の共通方針.md)。このケースで使う既存入力値・期待件数・対象版を準備担当者が記入する。DBの試験データ新規登録は行わない。

旧版を参照して作成する、という利用者の指示に基づく新MCM用の試験仕様。**移行版の実装は未作成・未受領**。本書は実装後に満たす業務動作を定める文書で、試験実施済み・動作確認済みを意味しない。

正常取得・再試行・0件・終了・現行比較・取得失敗の6ケース。起動入口は旧版と同じ「申請前check.vbs」、入力案内は「見積Noを入力してください。」、結果は「【見積金額】」と金額・期間、ボタンは再試行／キャンセルを移行要求とする。

凡例：
- 実施者＝移行版を操作し結果を照合する人。準備担当者＝既存の見積No・期待値・検証接続を用意する人。
- A・B＝異なる既存の店舗見積No、Z＝検索に一致しないことを確認した文字列。DBへ試験用見積を新規登録しない。
- 全ケースは移行版作成後に実施する。受領した旧Oracle版を新MCM用として起動しない。
- 旧版の入力・表示・検索の根拠と、キャンセル判定・例外通知に必要な移行要求を[用語表](用語表.md)で区別する。[骨子](骨子.md)にケース対応を示す。
- 新MCMの接続は会社で確認した検証用設定を使う。設定ファイル名等は実装で決めた情報を[実施前確認票](../TL30-32_実施前確認票.md)に記入する。記入前は実施しない。

## TL30-001

### 項番
TL30-001

### テスト項目
TL30：指定した見積Noの金額・契約期間を、開始日の昇順で表示すること。

### 前提条件
```
実施区分＝要確認（移行版実装後に実施）。

【この試験で確認すること】
見積Noの一致条件、店舗見積との結合、金額と期間・件数・順序。

【実施する人】
・実施者（入力・結果照合）。
・準備担当者（既存見積と期待表を用意）。

【実施者に必要なもの】
・検証DBへ接続する移行版一式。実施前確認票の起動パス・設定先が記入済み。

【準備担当者が用意するデータ】
既存のAについて、店舗基本見積IDに紐づく店舗見積の金額・開始日・終了日を開始日昇順で準備する。状態や有効フラグを追加で絞らない。
可能なら開始日の異なる複数行を含める。ない場合は1行の取得を判定し、複数行の並びは未確認と記録する。
期待表は「見積No A／基本見積ID／各明細の金額表示文字列・開始日・終了日／件数」を記入する。金額表示は旧版の通貨記号・桁区切りを控える。見積金額がNULL・書式上限超等の通常確認に不向きな対象は使わない。

【開始時の状態】
移行版の入力ダイアログをまだ開いていない。検証枠の対象見積変更を停止する。
```

### 操作内容
```
1. 確認票の起動パスの申請前check.vbsを開く。
2. 「見積Noを入力してください。」にAを入力し、「OK」を押す。
3. 「【見積金額】」の結果を記録する。明細数と各行の金額・開始日・終了日を期待表と照合する。
4. 開始日の早い行から並ぶことを確認し、結果の「キャンセル」で閉じる。

【入力値】
見積No＝A、入力＝OK、結果＝キャンセル。
```

### 期待結果
```
【画面確認】
・結果の先頭に「【見積金額】」、明細に「【金額】開始日 - 終了日」の形式で期待件数を表示する。
・金額表示文字列は準備値に一致し、日付はyyyy/mm/dd。開始日の昇順で、A以外の明細を含めない。
・同じ開始日の明細の内部順序は固定しない。重複除去処理を勝手に追加しない。

【ファイル確認】
帳票Excelや恒久保存するCSVを作らない。内部の作業ファイル有無は実装方式に依存するため、旧sqlplus用ファイルの作成を必須にしない。

【DB確認】
実施不要（参照のみ。期待値準備は読み取り照会）。
```

### 期待メッセージ
```
表示タイミング＝起動時と検索結果表示時。
表示形式＝見積No入力ダイアログ、結果ダイアログ（再試行／キャンセル）。
メッセージID＝－。
表示文言＝見積Noを入力してください。
結果の見出し＝【見積金額】。明細文字列は期待表と一致する。
作業者操作＝Aを入力してOK、照合後に結果のキャンセル。
```

### 備考
検索は入力文字列を大文字へ変換した見積Noとの一致。小文字で入力する追加確認は、英字を含む実在Aがある場合に実施する。旧版のNLS通貨設定を推測して記号を固定しない。

## TL30-002

### 項番
TL30-002

### テスト項目
TL30：再試行で前回の見積Noを引き継ぎ、別の見積Noの結果へ入れ替えること。

### 前提条件
```
実施区分＝要確認（移行版実装後に実施）。

【この試験で確認すること】
再入力時の初期値と、前回結果を今回結果へ混ぜないこと。

【実施する人】
・実施者。
・準備担当者（異なるA・Bの期待表を用意）。

【実施者に必要なもの】
・確認票を記入した移行版一式。

【準備担当者が用意するデータ】
A・Bは結果の金額または日付で区別できる既存見積No。各件数・各明細値を控える。表示内容が全く同じ組は選ばない。

【開始時の状態】
新しく起動して入力前。
```

### 操作内容
```
1. 移行版を起動し、Aを入力して「OK」を押す。
2. Aの結果で「再試行」を押す。再入力欄の初期値がAであることを確認する。
3. 入力欄全体をBへ置き換え、「OK」を押す。
4. 結果がBの件数・値だけで、Aの明細が連結されていないことを確認する。
5. 結果の「キャンセル」で閉じる。

【入力値】
初回A、結果で再試行、次回B。
```

### 期待結果
```
【画面確認】
・再入力欄には前回Aが入る。Bで取得した結果はBの期待表に一致し、Aの明細を残さない。
・1回の再試行で入力ダイアログを重複表示しない。

【DB確認】
実施不要（参照のみ）。
```

### 期待メッセージ
```
表示タイミング＝結果の再試行後。
表示形式＝入力ダイアログと次の結果ダイアログ。
メッセージID＝－。
表示文言＝見積Noを入力してください。／【見積金額】
作業者操作＝初期値Aを確認してBへ変更し、OKを押す。
```

### 備考
旧版はEstNoを入力初期値へ渡し、ReadingTextをクリアして繰り返す。001の列・順序確認を繰り返す目的ではない。

## TL30-003

### 項番
TL30-003

### テスト項目
TL30：存在しない見積Noでは、前回明細を残さず見出しだけの結果を表示すること。

### 前提条件
```
実施区分＝要確認（移行版実装後に実施）。

【この試験で確認すること】
0件の結果と前回表示の消去。

【実施する人】
・実施者。
・準備担当者（Aと未登録Zを確認）。

【実施者に必要なもの】
・確認票を記入した移行版一式。

【準備担当者が用意するデータ】
Aは1件以上の既存見積、Zは入力を大文字化しても店舗基本見積の見積Noに一致しない文字列。DBへZを登録しない。Aの件数と代表明細、Z不存在の確認日時を控える。

【開始時の状態】
入力前。
```

### 操作内容
```
1. 移行版でAを入力し、明細を表示する。
2. 「再試行」を押し、見積NoをZへ置き換えて「OK」を押す。
3. 「【見積金額】」だけで、Aの明細が残らないことを確認する。
4. 結果の「キャンセル」で閉じる。

【入力値】
初回A、再試行後Z。
```

### 期待結果
```
【画面確認】
・結果は見出し「【見積金額】」だけで、金額・期間の明細行がない。
・旧Aの明細、SQLのエラー文字列、別の見積の明細を今回結果として表示しない。
・旧版にない「対象データがありません」等の専用通知は、この旧版準拠仕様の必須期待に加えない。

【DB確認】
実施不要（参照のみ）。
```

### 期待メッセージ
```
表示タイミング＝Zの取得完了時。
表示形式＝結果ダイアログ（再試行／キャンセル）。
メッセージID＝－。
表示文言＝【見積金額】
作業者操作＝明細なしを確認してキャンセル。
```

### 備考
原本はPROMPTの見出しを出し、FEEDBACK OFFのため正常0件の専用通知を作らない。取得エラーをこの0件結果として扱わない。

## TL30-005

### 項番
TL30-005

### テスト項目
TL30：入力のキャンセル・空欄と、結果のキャンセルで処理を終了すること。

### 前提条件
```
実施区分＝要確認（移行版実装後に実施。入力時の終了は改善要求）。

【この試験で確認すること】
終了操作と、入力を取り消した後の不要な検索防止。

【実施する人】
・実施者。
・準備担当者（Aと接続先を用意）。

【実施者に必要なもの】
・確認票を記入した移行版一式。入力時の終了判定が実装済み。

【準備担当者が用意するデータ】
条件表を1行ずつ別起動で実施する。
| 行 | 操作 |
| 1 | 初回入力でキャンセル |
| 2 | 初回入力を空欄のままOK |
| 3 | Aを取得し、結果でキャンセル |
検索コマンドが実行されないことの確認は開発者が移行版の呼出記録またはテストで照合し、画面だけで判定済みにしない。

【開始時の状態】
条件ごとに入力ダイアログ未起動。
```

### 操作内容
```
1. 移行版を起動する。
2. 条件表の操作を1行分だけ行う。行3はAを入力してOK、結果表示後にキャンセルを押す。
3. ダイアログが閉じ、入力や結果を再表示せず処理が終了することを確認する。
4. 行1・2の検索未実行の確認記録と照合する。次の行は別起動で実施する。

【入力値】
条件表の3行。行3の見積No＝A。
```

### 期待結果
```
【画面確認】
・3行とも終了し、不要な結果・エラー・再入力ダイアログを出さない。
・入力を取り消した行1・2では検索を開始しない。行3は取得済み結果を閉じるだけ。

【DB確認】
実施不要（更新なし）。入力時の検索未実行は開発者の呼出記録で別判定。
```

### 期待メッセージ
```
表示タイミング＝入力または結果のキャンセル時、空欄のOK時。
表示形式＝追加通知なし。
メッセージID＝－。
表示文言＝なし。
作業者操作＝ダイアログが閉じたことを確認する。
```

### 備考
原本は結果のキャンセルを終了判定するが、InputBoxが返す空文字を判定せず検索してしまう。入力時の終了は原本の確認済み動作ではなく、移行時の改善要求として明示した。

## TL30-006

### 項番
TL30-006

### テスト項目
TL30：同一元データの現行版と移行版で、金額・期間・件数・開始日順が一致すること。

### 前提条件
```
実施区分＝要確認（移行版実装後に実施。両環境を揃えられない場合は実施不可）。

【この試験で確認すること】
旧版から新MCMへの業務結果の維持。

【実施する人】
・実施者。
・準備担当者（同時点の既存見積と両実行環境を用意）。

【実施者に必要なもの】
・現行版が動作する環境、検証用の移行版、各DBの参照権限。

【準備担当者が用意するデータ】
同じ見積No A、基本見積IDへの関連、見積金額・開始日・終了日が両DBで一致する既存データ。両版の件数・表示文字列の期待表を用意する。接続先のパスワードは記録しない。

【開始時の状態】
同時点の期待値を確保し、対象の並行更新を停止。
```

### 操作内容
```
1. 現行版でAを入力し、結果の見出しと明細を記録する。キャンセルで閉じる。
2. 移行版で同じAを入力し、結果を記録する。
3. 件数・各行の金額と期間・開始日順を、両結果と事前期待表で照合する。
4. 移行版の結果をキャンセルで閉じる。

【入力値】
両版の見積No＝A。
```

### 期待結果
```
【画面確認】
・両結果の明細件数、金額、開始日・終了日が期待表に一致し、開始日の昇順となる。
・接続方式や内部作業ファイルの違いは比較対象にしない。金額の通貨表示は旧版から控えた期待文字列で確認する。

【DB確認】
実施不要（参照のみ。両DBの元データ一致は準備段階で確認）。
```

### 期待メッセージ
```
表示タイミング＝両版の起動時・結果表示時。
表示形式＝見積No入力と結果ダイアログ。
メッセージID＝－。
表示文言＝見積Noを入力してください。／【見積金額】
作業者操作＝同じAを入力して結果を記録し、キャンセルで閉じる。
```

### 備考
同時点のDBを揃えられなければ実施不可とし、単独確認だけで現行比較済みにしない。

## TL30-007

### 項番
TL30-007

### テスト項目
TL30：検索失敗を正常0件にせず、前回結果を表示しないこと。

### 前提条件
```
実施区分＝開発者テスト（移行時の改善要求・実装後に実施）。

【この試験で確認すること】
接続・取得失敗と、正常な0件を区別すること。

【実施する人】
・開発者（失敗条件と呼出記録を用意し実施）。

【実施者に必要なもの】
・移行版の独立テスト環境。外部DBを使わず、取得処理が失敗を返す代替処理。

【準備担当者が用意するデータ】
初回にAの既知結果を返し、再試行時に接続失敗または取得失敗を返す独立テストを用意する。共有検証DBの停止・パスワード変更で条件を作らない。実装前は実施しない。

【開始時の状態】
独立テストでAの結果が表示できる状態。
```

### 操作内容
```
1. Aを取得し、既知結果を表示する。
2. 再試行後の取得処理を失敗させる条件で、Aを入力してOKを押す。
3. 失敗通知が出て、旧明細と「見出しだけの正常0件」が表示されないことを確認する。
4. 通知を閉じ、処理が終了することを確認する。接続失敗と取得失敗を別実行で判定する。

【入力値】
A、再試行時の接続失敗／取得失敗。
```

### 期待結果
```
【画面確認】
・失敗を明示し、前回のA明細や正常0件結果を表示しない。
・パスワード等の認証情報を画面やログへ出さない。通知を閉じると終了する。

【DB確認】
実施不要（外部DBを使用しない独立テスト）。
```

### 期待メッセージ
```
表示タイミング＝取得に失敗した時。
表示形式＝エラー通知（OK）。
メッセージID＝－。
表示文言＝データの取得に失敗しました。接続先と入力した見積Noを確認してください。
作業者操作＝通知を記録してOKを押し、旧結果が表示されないことを確認する。
```

### 備考
原本には業務用の例外処理・エラー文言がない。上記文言は移行設計要求として今回定めたもので、旧版または未作成の移行版に存在すると報告するものではない。実装側で異なる文言を採用する場合、本ケースと実装を同時に整合させる。
