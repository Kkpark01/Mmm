# TL02（支払いデータ取得） 単体テスト仕様書

準備方針：[共通方針と準備記録](../00_試験準備の共通方針.md)。このケースで使う既存入力値・期待件数・対象版を準備担当者が記入する。DBの試験データ新規登録は行わない。

対象：支払いデータ取得ver2.0.xlsm（改修版）。「操作シート」に支払い月を入れて「①支払い抽出」を押すと、新MCM（SQL Server）から取引先への保守費の支払いデータを取り出し、支払金額を計算して、シート「支払一覧データ」に書く。「④支払一覧作成」で、テンプレートから支払一覧を作って保存する。DBは読むだけで、更新しない。

凡例：
- 実施者：試験を行う人。Excelでツールを実行し、シートと保存されたファイルを確認する。
- 準備担当者：検証DBにある取引先契約から試験用の契約を選び、試験データ表に値を書いて実施者に渡す人（新しく登録はしない。作成者の判断 2026/11/02）。
- 試験データ表：準備担当者が、選んだ取引先契約の値と、期待する支払金額を書く表。各ケースの前提条件にある。
- 月M：試験に使う支払い月（月の1日）。
- 各ケースの「前提条件」「操作内容」「期待結果」は、そのケースだけを読んで実施できるように書いてある。他のケースは参照しない。
- 準備担当者が既存データを選定する。準備未完のケースは開始せず、未確認を合格へ読み替えない。
- このツールにはメッセージIDがないため、期待メッセージの「メッセージID」は「－」とする。
- 実施区分：通常／要確認／開発者テスト／実施不可／除外候補（test-spec-common-rules.md 14.7章）

項番の欠番：

| 項番 | 理由 |
|---|---|
| 003 | 支払い月が空欄のときのメッセージ。DBに接続する前に止まり、処理が元のツールと同じため、作らない（TL01 と同じ判断。作成者承認 2026/11/02） |
| 004 | 接続エラー。共通部品が TL11（店舗見積実績検索）と同じため、TL11-007 で確認する |

## TL02-001

### 項番
TL02-001

### テスト項目
TL02(支払いデータ取得)：月払の契約の支払金額が、見積の仕切合計を月数で割った額になり、割り切れない余りが見積期間の最初の月に足されること

### 前提条件
```
【この試験で確認すること】
「①支払い抽出」で、月払（支払回数12）の取引先契約の支払金額が、見積の仕切合計金額を見積期間の月数で割った整数の額（月額）になること。割り切れない余りは、見積期間の最初の月の支払金額にだけ足されること。

【実施する人】
・実施者（試験を行う人）
・準備担当者（検証DBから試験用の取引先契約を選び、試験データ表を渡す人）

【実施者に必要なもの】
・Excel（マクロを有効にできること）が入ったPC。
・改修版のフォルダー「02_支払いデータ取得」一式を、PCにコピーしてあること。フォルダーの中の「Mcm移行部品」フォルダーも、同じ位置関係のままコピーする。
・OLE DB ドライバー（MSOLEDBSQL19）が、PCに入っていること。
・SQL認証の場合のみ、MCM_MACRO_DB_USER・MCM_MACRO_DB_PASSWORDを実施者の環境に設定する。Windows認証では不要。認証情報は本書へ書かない。
・接続先が本番ではないこと（依頼元に確認済みであること）。

【準備担当者が用意するデータ】
検証DBにある取引先契約から、次の2件を選ぶ（新しく登録しない）。どちらも、同じ支払い月（以下、月M）に支払いがある契約にする。
・契約A：月払（支払回数12）。月Mが、単価が参照する見積期間の最初の月。見積期間は1つだけで、終了日がある。仕切合計金額が、見積期間の月数で割り切れない。
・契約B：月払（支払回数12）。月Mが、単価が参照する見積期間の2か月目以降。見積期間は1つだけで、終了日がある。仕切合計金額が、見積期間の月数で割り切れない。
選んだら、下の「試験データ表」を書いて実施者に渡す。期待する支払金額は、次の計算で求める。
・月額＝仕切合計金額÷見積期間の月数の、小数点以下を切り捨てた額
・余り＝仕切合計金額－月額×見積期間の月数
・契約Aの期待する支払金額＝月額＋余り、契約Bの期待する支払金額＝月額
（例：仕切合計 100000 円、12か月 → 月額 8333 円、余り 4 円。契約A＝8337 円、契約B＝8333 円）

試験データ表（準備担当者が記入する）：
| 項目 | 契約A | 契約B |
| 契約書No | | |
| 取引先名 | | |
| サポートID | | |
| 見積期間の開始日・終了日 | | |
| 見積期間の月数 | | |
| 仕切合計金額 | | |
| 月額・余り | | |
| 期待する支払金額 | | |
月M＝（例：2026/10/01）

【開始時の状態】
Excelを起動していなくてよい。
```

### 操作内容
```
1. エクスプローラーで、コピーしたフォルダー「02_支払いデータ取得」を開く。「Mcm移行部品」フォルダーの McmMacroSettings.ini をメモ帳で開き、サーバー名・DB名が準備記録の検証接続先と一致することを確認する。変更せずにメモ帳を閉じる。

2. 「支払いデータ取得ver2.0.xlsm」をダブルクリックで開く。画面上部に、マクロを有効にするかを尋ねる黄色の帯が出た場合は、帯のボタンを押下して有効にする。

3. シート「操作シート」を選ぶ。C3（支払い月）を選び、試験データ表の月Mを「2026/10/01」の形で入力して、Enterキーを押す。

4. 「①支払い抽出」ボタンを押下する。取得には数分かかることがある。メッセージが表示されたら、内容を確認して「OK」を押下する。

5. シート「支払一覧データ」を選ぶ。Ctrl＋F で契約Aの契約書Noを検索し、その行（E列が契約Aの契約書No）を確認する。同じようにして、契約Bの行を確認する。同じ契約書Noの行が複数あるときは、そのすべての行を確認する。

6. ツールを閉じる。保存するかを尋ねられた場合は、保存しない方のボタンを押下する（ツールのブックを変えないため）。

【入力値】
・支払い月（C3）＝試験データ表の月M
```

### 期待結果
```
【画面確認】
1. 手順4で、期待メッセージのメッセージが表示される。
2. 手順5で、シート「支払一覧データ」に、E列（契約書No）が契約Aの行と、契約Bの行がある。
3. 契約Aの行のI列（支払金額）が、試験データ表の契約Aの期待する支払金額と同じである。
4. 契約Bの行のI列（支払金額）が、試験データ表の契約Bの期待する支払金額と同じである。
5. 契約A・Bの行とも、次のとおり。
　B列（CSﾅﾝﾊﾞ）＝「P」＋サポートIDの先頭2桁＋「-」＋残りの5桁（例：サポートID 2802381 → P28-02381）
　F列（取引先名）＝試験データ表の取引先名
　G列（支払回数）＝12
　H列（支払月）＝月Mの年と月（表示は「2026年10月」の形）

【DB確認】
実施不要（このツールはDBを読むだけで、更新しないため）。
```

### 期待メッセージ
```
表示タイミング＝手順4で、「①支払い抽出」ボタンを押下し、取得が終わったとき
表示形式＝メッセージボックス（見出し「Microsoft Excel」、記号なし、「OK」ボタンのみ）
メッセージID＝－
表示文言＝「支払データ取得しました。」、空行を1行はさんで「引き続き、【BCP対策】支払いリストと照合してください。」
作業者の操作＝「OK」を押下する
```

### 備考
```
【実施区分】通常
【根拠】改修版 支払いデータ取得ver2.0.xlsm。CreateList モジュール PayList → Create_SQL（McmNewDb.McmExportSqlServer "M04"、内蔵SQL queries/T18_00_default_01.sql。支払い月は yyyy/mm/01 の日付で渡す）→ tran_csv（McmWriteCached）。支払金額（9列目）は、McmNewDb の ApplyPayment が、期間ID・開始日・終了日・支払月（内蔵SQLの22〜25列目）と、payment-batch-rates.sql（見積期間の開始日・終了日・仕切合計金額）、payment-batch-dates.sql（支払明細でONの月）から、McmCalculatePayment で計算する。月額は仕切合計÷月数の整数、余りは見積期間の最初の月に足す。元のツールはDBの関数 MCM_FN_SIHARAI で計算していた。PRE_Edit：CSﾅﾝﾊﾞ、支払月の表示形式「yyyy年m月」、支払金額の表示形式「#,##0」。
【確認していないこと】見積期間が2つ以上ある契約、終了日のない見積期間（12か月ごとに余りを足す）。月払以外の支払回数（2〜11回）。取得にかかる時間（単体テストでは扱わない。作成者の判断 2026/11/02）。
【要確認】検証DBに、条件に合う契約A・Bがあるか（ない場合は作成者に相談する）。比較照合キーの重複があると、完了のメッセージが「重複した支払いデータが抽出されてます。」になる（データによる。このときは、表示を記録して手順5に進む）。マクロを有効にする帯と、保存するかの確認のボタン名（Excelの版で表示が異なる）。
【不合格のとき】契約A・Bの行の画面の写しと、試験データ表を記録する。
```

## TL02-005

### 項番
TL02-005

### テスト項目
TL02(支払いデータ取得)：「④支払一覧作成」で、ツールのブックが「YYYY年M月度支払い一覧.xlsm」の名前でツールと同じフォルダーに保存され、支払一覧に取得した支払いデータが写されること

### 前提条件
```
【この試験で確認すること】
「①支払い抽出」のあと「④支払一覧作成」を押すと、テンプレートから支払一覧のシートが作られ、ツールのブック自体が「YYYY年M月度支払い一覧.xlsm」の名前で、ツールと同じフォルダーに保存されること（元のツールと同じ保存のしかた）。元の「支払いデータ取得ver2.0.xlsm」のファイルは変わらないこと。シート「支払一覧」に、シート「支払一覧データ」の行と支払金額がそのまま写されること。

【実施する人】
・実施者（試験を行う人）

【実施者に必要なもの】
・Excel（マクロを有効にできること）が入ったPC。
・改修版のフォルダー「02_支払いデータ取得」一式を、PCにコピーしてあること。フォルダーの中の「Mcm移行部品」フォルダーと「【テンプレート】支払一覧.xlsx」も、同じ位置関係のままコピーする。
・OLE DB ドライバー（MSOLEDBSQL19）が、PCに入っていること。
・SQL認証の場合のみ、MCM_MACRO_DB_USER・MCM_MACRO_DB_PASSWORDを実施者の環境に設定する。Windows認証では不要。認証情報は本書へ書かない。
・接続先が本番ではないこと（依頼元に確認済みであること）。

【準備担当者が用意するデータ】
なし（検証DBにある支払いデータを使う）。支払い月は、支払いデータがある月にする（以下、月M。例：2026/10/01）。

【開始時の状態】
Excelを起動していなくてよい。コピーしたフォルダー「02_支払いデータ取得」に、「月度支払い一覧.xlsm」で終わるファイルがないこと（あれば別の場所へ移す）。「【テンプレート】支払一覧.xlsx」を開いていないこと。

### 操作内容
```
1. エクスプローラーで、コピーしたフォルダー「02_支払いデータ取得」を開く。「支払いデータ取得ver2.0.xlsm」の更新日時を確認する（エクスプローラーの「更新日時」の列）。

【実施する人】
・実施者（試験を行う人）
