# TL02（支払いデータ取得） 骨子

方針（00_進捗.md 決定事項3・5）：最低限。移行で変わった「支払金額の計算」（DBの関数 → VBA）を最優先にする。期待値は、準備担当者が選ぶ試験用の取引先契約の値と、用語表5章の計算のしかたから決める。元のツールとの比較は、動かせる場合だけの別ケースにする。接続エラーは TL11-007 で代表する。

共通の前提：
- 役割：実施者（Excelでマクロを実行し、シートと出力ファイルを確認する。DBは見ない）、準備担当者（試験用の取引先契約を選び、試験データ表を渡す）
- 試験データは、新規に登録せず、検証DBにある取引先契約から準備担当者が選ぶ（支払いの計算に必要なデータ（ユーザ契約、製番、見積期間、支払明細）がそろった契約を新しく作るのは手間が大きいため）。

欠番：
- TL02-003（支払い月が空欄のメッセージ）：DBに接続する前に止まり、処理が元のツールと同じため作らない（TL01 と同じ判断）。
- TL02-004（接続エラー）：共通部品が同じため、TL11-007 で代表する。

対象外とした観点：
- 「②データ照合」（DBを使わず、元のツールと同じ処理）
- 特殊ソート（操作シートT〜W列）と、取引先・契約Noの組み合わせによるE付与（O〜Q列）（DBを使わず、元のツールと同じ処理。TL02-006 で差が出れば分かる）
- 比較照合キーの重複のメッセージ（元のツールと同じ処理）
- 一時ファイル（支払一覧生成.SQL、支払一覧.csv）が作られないこと

作成者の判断（2026/11/02「1：B、2：A、3：OK、4：たぶんOK」）：
1. 「④支払一覧作成」の保存のしかたは、元のツールに合わせて直す（ツールのブック自体の名前を「YYYY年M月度支払い一覧.xlsm」に変えて保存する）。VBA の変更のため、作成者が Excel の VBA の画面で直す（00_進捗.md 2.1章）。TL02-005 の期待結果は、直した後の動きで書く。
2. 取得にかかる時間は、単体テストでは扱わない（性能の確認として別に扱う）。
3. TL02-006 で比べる支払い月は 2022/03。
4. 試験データは、検証DBにある取引先契約から準備担当者が選ぶ。条件に合う契約が見つからない場合は、作成者に相談する（【要確認】）。
