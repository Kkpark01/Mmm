# #361 MCM2003U 見積変更なし判定と入力保持

基準：2026-09-16受領のsrc (3).zip。元のmcm-web/srcは変更していません。

## 調査結果

VBのMcm2003uScreen.vbのMitsumoriButton_Click（691行付近）はcheckChangedStatusを呼び、変更なしの場合にCPDataNotChangedExceptionを発生させています。新規選定時は変更あり扱いです。

最新JavaにはDataNotChangedException自体はありますが、Mcm2003uService.saveでは未使用で、変更なしでもブランド・ヘッダー更新と集計を実行していました。

Mcm2003uController.saveでは、bindHeaderが完了してからセッションにフォームを保存していました。そのため途中で金額等の検証が失敗すると、直前に入力した正常な項目も新しいフォームから引き継がれません。この経路はローカルテストで確認しています。また、DB登録処理にセッションと同じフォームを渡していたため、保存前処理でフォームが変更されると失敗後の入力に影響し得ます。

会社で表示された「見積登録ができませんでした。入力を保持します。」という文言は今回の最新Controllerとは異なります。実際のサーバーログがないため、会社での登録失敗がどのSQL・例外によるものかは未特定です。必須項目入力済みでも失敗するケースが全て解消したとするものではありません。

## 修正内容

- 既存見積の登録は、編集可能なヘッダーとブランド・構成の変更列を比較し、変更なしなら「データに変更がありません。」を表示。更新SQL・集計を実行しません。
- 空文字とNULL、BigDecimalの桁数表現の違いで不要な変更判定をしません。ブランド編集を元に戻した場合も変更なしと判定します。
- NULLの金額が画面で0表示されただけで、ブランドの自動計算・変更が発生する問題を防止。
- バインド開始前にフォームをセッションに確保し、途中エラー時も正常に取り込めた入力を保持。
- 型変換できなかった文字列等は許可した入力項目だけをFlash属性で引き継ぎ、再表示時に復元。読み取り専用項目や内部ID・トークンには反映しません。
- 保存処理にはフォームのコピーを渡し、登録失敗時に保存前処理による書換えが画面の入力へ波及するのを防止。
- 新規見積は従来のDraftService経路を維持。変更なし判定は既存見積の見積登録に限定し、発行・申請には追加していません。
