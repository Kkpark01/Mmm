# TL05（終息リスト作成） 単体テスト仕様書

準備方針：[共通方針と準備記録](../00_試験準備の共通方針.md)。このケースで使う既存入力値・期待件数・対象版を準備担当者が記入する。DBの試験データ新規登録は行わない。

対象：終息リスト作成ver3.7.xlsm（改修版）。シート「操作シート」のボタンで、新MCM（SQL Server）から機器・製番・取引先契約期間・個体の取引先を取り出し、シート「取込データ」に書く。そのデータから、終息リスト（「店舗別　『機器一覧』_日時.xlsx」）を、ツールと同じフォルダーに保存する。DBは読むだけで、更新しない。

凡例：
- 実施者：試験を行う人。Excelでツールを実行し、シートと出力ファイルを確認する。
- 準備担当者：検証DBにあるサポートIDから試験用のデータを選び、試験データ表に値を書いて実施者に渡す人（新しく登録はしない）。
- 試験データ表：準備担当者が、選んだデータの値を書く表。各ケースの前提条件にある。
- システムコード変換表：サポートID付替えの変換表。設定ファイル（Mcm移行部品\McmMacroSettings.ini）の Reference_01 の場所のファイルを開く。本番は共有フォルダーを読む。試験ではツールのフォルダーの写しを読む（00_進捗.md 2.2章）。
- 各ケースの「前提条件」「操作内容」「期待結果」は、そのケースだけを読んで実施できるように書いてある。他のケースは参照しない。
- 準備担当者が既存データを選定する。準備未完のケースは開始せず、未確認を合格へ読み替えない。
- このツールにはメッセージIDがないため、期待メッセージの「メッセージID」は「－」とする。
- 実施区分：通常／要確認／開発者テスト／実施不可／除外候補（test-spec-common-rules.md 14.7章）

項番の欠番：

| 項番 | 理由 |
|---|---|
| 002 | 「データリスト作成」（全件取得）。取得に約8分かかり、取り出すSQLの形が 001 の「指定リスト抽出」と同じ形のため作らない（作成者回答 2026/11/02） |
| 003 | 「契約中リスト抽出」。使うSQLが全件取得に含まれるため作らない（作成者回答 2026/11/02） |
| 005 | 「支払いデータ抽出」。元のツールで使われているか分からず、探す条件（1年契約、ハードウェア製番あり、指定月に支払いあり）が多いため作らない（作成者回答 2026/11/02） |
| 007 | 接続エラー。共通部品が TL11（店舗見積実績検索）と同じため、TL11-007 で確認する |

「リスト作成再開」は、改修版がCSVを作らないため使えない扱いとし、試験しない（作成者回答 2026/11/02）。

## TL05-001

### 項番
TL05-001

### テスト項目
TL05(終息リスト作成)：サポートIDを指定して「指定リスト抽出」を押すと、そのサポートIDの機器だけが取込データに取り出され、担当店舗・機器分類・製番・取引先が当て込まれること

### 前提条件
```
【この試験で確認すること】
操作シートのM12にサポートIDを入れて「指定リスト抽出」を押すと、そのサポートIDの機器だけが新MCMから取り出され、シート「取込データ」に書かれること。同じ機器管理IDは1行にまとまり、担当店舗、機器分類、製番、取引先が当て込まれること。

【実施する人】
・実施者（試験を行う人）
・準備担当者（検証DBから試験用のサポートIDを選び、試験データ表を渡す人）

【実施者に必要なもの】
・Excel 2021 または Microsoft 365（XLOOKUP関数が使えること。取引先の当て込みで使う）が入ったPC。マクロを有効にできること。
・改修版のフォルダー「05_終息リスト作成」一式を、PCにコピーしてあること。中の「Mcm移行部品」フォルダー、「システムコード変換表.xlsx」、「_【テンプレート】店舗別　『機器一覧』.xlsx」、「【テンプレート】支払一覧.xlsx」も、同じ位置関係のままコピーする。
・OLE DB ドライバー（MSOLEDBSQL19）が、PCに入っていること。
・SQL認証の場合のみ、MCM_MACRO_DB_USER・MCM_MACRO_DB_PASSWORDを実施者の環境に設定する。Windows認証では不要。認証情報は本書へ書かない。
・接続先が本番ではないこと（依頼元に確認済みであること）。
・「システムコード変換表.xlsx」が、Excelで開かれていないこと。

【準備担当者が用意するデータ】
検証DBにあるサポートIDから、次の1つを選ぶ（新しく登録しない）。
・機器が登録されている（1件以上）。
・このツールのシート「店舗リスト」のA列にそのサポートIDがあり、B列に担当店舗が入っている（A列は、Ctrl＋FでサポートIDを検索して確かめる）。
次の機器は、あれば試験データ表に書く。なければ、その行を空にして、期待結果の該当番号を外す。
　機器Q：製番（ハードウェア製番、ソフトウェア製番）が登録された機器（1つ）
　機器R：個体に取引先が登録され、機器分類（機器分類表のE列の値）が「■」で始まるか「○」の機器（1つ）
選んだら、下の「試験データ表」を書いて実施者に渡す。値は、新MCMの画面かDBで確かめた値を書く。

試験データ表（準備担当者が記入する）：
| 項目 | 値 |
| サポートID（7桁） | |
| 取り出される機器の件数（同じ機器管理IDは1件） | |
| 担当店舗（店舗リストのB列） | |
| 機器Q：機器管理ID、製番開始日、製番終了日、ハードウェア製番、ソフトウェア製番 | |
| 機器R：機器管理ID、機器分類、個体の取引先名 | |

【開始時の状態】
Excelを起動していなくてよい。
```

### 操作内容
```
1. エクスプローラーで、コピーしたフォルダー「05_終息リスト作成」を開く。フォルダーの中の「Mcm移行部品」を開き、McmMacroSettings.ini をメモ帳で開く（右クリック→「プログラムから開く」→「メモ帳」）。「Server=ILCM-SYSDEV」「Database=SYSDEV」「Reference_01=システムコード変換表.xlsx」と書かれていることを確認する。変更せずにメモ帳を閉じる。

2. フォルダー「05_終息リスト作成」に戻り、「終息リスト作成ver3.7.xlsm」をダブルクリックで開く。画面上部に、マクロを有効にするかを尋ねる黄色の帯が出た場合は、帯のボタンを押下して有効にする。

3. 画面下のシートの見出しから「店舗リスト」を選ぶ。A1のセルを選び、Ctrl＋↓ キーを押す。画面左端に出る行番号（最終行の番号）を控える。次に、シート「取込データ」を選び、2行目から下に前回のデータが入っていることを確認する。

4. シート「操作シート」を選ぶ。M12のセル（「サポートID指定」の下にある数字のセル）を選び、試験データ表のサポートIDを入力して、Enterキーを押す。

5. 「指定リスト抽出」と書かれたボタンを押下する。取得に数分かかることがある。画面左下に「新MCMから取得中」「新MCMのデータ展開中」などが表示される間は、Excelを操作しないで待つ。メッセージが表示されたら、内容を確認して「OK」を押下する。

6. シート「取込データ」を選ぶ。B1のセルを選び、Ctrl＋↓ キーを押して、画面左端に出る行番号（最終行の番号）を確認する。行数は、最終行の番号から1を引いた数である（1行目は見出し）。続けて、次を確認する。
　・C列（見出し「店舗」）の2行目から最終行まで
　・D列（見出し「サポートID」）の2行目から最終行まで

7. シート「取込データ」で、機器Qと機器Rの行を探す。Ctrl＋Fを押し、「検索する文字列」に機器管理IDを入力して「すべて検索」を押下し、一覧に出た行を押下してそのセルへ移動する。同じ行の次のセルを、試験データ表と照合する。
　・A列（1行目の見出しは空）：機器分類
　・AR列〜AU列（1行目の見出しは「開始日」「終了日」「ハードウェア製番」「ソフトウェア製番」）：製番
　・BA列（1行目の見出しは「備考」）：取引先名

8. シート「店舗リスト」を選び、A1のセルを選んで Ctrl＋↓ キーを押し、最終行の番号を確認する。

9. Excelを閉じる。保存するかを尋ねられた場合は、保存しない方のボタンを押下する（ツールのブックを変えないため）。

【入力値】
・サポートID（M12）＝試験データ表のサポートID
```

### 期待結果
```
【画面確認】
1. 手順5で、期待メッセージのメッセージが表示される。
2. 手順6で、シート「取込データ」の行数（最終行の番号−1）が、試験データ表の件数と同じである（同じ機器管理IDが2行以上残っていると、件数が多くなる）。手順3で確認した前回のデータは残っていない。
3. 手順6で、D列がすべて試験データ表のサポートIDである。（サポートID付替えの対象のプラントでは、付替え後のサポートIDに置き換わる。D列の値が入力と違い、システムコード変換表.xlsx に対象として載っている場合は、不合格にせず、そのことを記録して、別のサポートIDで実施し直す。）
4. 手順6で、C列がすべて試験データ表の担当店舗である。
5. 手順7で、機器Qの行のAR列、AS列、AT列、AU列が、試験データ表の製番開始日、製番終了日、ハードウェア製番、ソフトウェア製番と同じである。
6. 手順7で、機器Rの行のA列が試験データ表の機器分類と同じで、BA列が試験データ表の取引先名と同じである。
7. 手順8で、シート「店舗リスト」のA列の最終行の番号が、手順3で控えた番号と同じである（新規サポートIDの追加がない）。

【DB確認】
実施不要（このツールはDBを読むだけで、更新しないため）。
```

```

### テスト項目
TL05(終息リスト作成)：同じ時点のデータで、元のツールと改修版の「指定リスト抽出」の結果（取込データ）が一致すること

### 前提条件
```
【この試験で確認すること】
旧DB（Oracle）と新MCM（SQL Server）が同じ時点のデータを持っているとき、元のツールと改修版で同じサポートIDを入れて「指定リスト抽出」を押すと、シート「取込データ」の行数と値が一致すること。

【実施する人】
・実施者（試験を行う人）

【実施者に必要なもの】
・改修版の試験（TL05-001など）が行えるPC。
・元のツールが動く環境（旧DBに接続できること。準備は依頼元に聞く）。
・元のツールのフォルダー一式を、PCにコピーしてあること（元のフォルダーでは実行しない。元のツールは、実行したフォルダーにファイルを作るため）。
・改修版のフォルダー「05_終息リスト作成」一式を、PCにコピーしてあること。
・旧DBと新MCMのデータが、同じ時点のものであること（移行のリハーサルの直後など）。依頼元に確認済みであること。
・2つのブックのシート「店舗リスト」「機器分類表」「個別機器分類表」と、「システムコード変換表.xlsx」が、同じ内容であること（違う場合は、元のツールのシートを改修版へ貼り付けてそろえる。そろえられない場合は、違いが出た列を記録する）。

【準備担当者が用意するデータ】
準備担当者は、両DBで指定リストの対象があり、店舗対応表にも存在する既存サポートID Sを選ぶ。旧DBと検証DBで対象の元データが同時点で一致することを読み取り確認する。
固定の過去サンプル番号は入力しない。表示・帳票を取得するために必要な結合先と原紙・対応表が揃うものを選ぶ。取得結果を見てから期待値を決めない。

| 両版へ入力する値（文字列そのもの） | |

| 両版で期待する件数・代表値の控え | |
| 両版の起動先・接続設定・原紙／対応表 | |
| 実施できない場合の理由 | |
同時点・対象ありを確認できなければ実施不可とし、空の結果同士を比較して合格にしない。

Excelを起動していなくてよい。
