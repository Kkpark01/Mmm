## 5. 支払金額の計算（McmNewDb.McmCalculatePayment）

- 元のツールは DB の関数（MCM_FN_SIHARAI）で計算していた。改修版は同じ計算を VBA に移した（Web版 MCM3002U の Java と同じ考え方）。
- 見積期間ごとに、仕切合計金額（MCM_TM_KIKAN.SIKIRIGOKEI_KIN）を月数で割り、整数の月額を各月に配る。割り切れない余りは、見積期間の最初の月に足す（終了日のない見積期間は、12か月ごとの最初の月に足す）。
- 支払月（支払明細で ON の月）から、次の支払月の前の月までの月額を合計したものが、その支払月の支払金額になる。月払（毎月が支払月）なら、その月の月額。年払（期間の最初の月だけが支払月）なら、12か月分の合計。
- 例：仕切合計 100000 円、見積期間 12か月、月払 → 1か月目 8337 円（8333＋余り4）、2か月目以降 8333 円。年払 → 100000 円。

## 7. 元のツールとの違い

| 項目 | 元のツール | 改修版 | 扱い |
|---|---|---|---|
| 支払金額の計算 | DBの関数 MCM_FN_SIHARAI | VBA（McmCalculatePayment） | 計算結果が同じであることを確認する（TL02-001、002、006） |
| 「④支払一覧作成」の保存 | ツールのブック自体を「YYYY年M月度支払い一覧.xlsm」に名前を変えて保存（開いているブックの名前が変わる） | 改修版は写しを保存し、ツールのブックの名前は変わらなかった | 作成者の判断で、元のツールに合わせて直した（2026/11/02。00_進捗.md 2.1章）。同じ名前のファイルがあると、Excel が上書きするかを尋ねる。上書きしないと「支払い一覧の作成・保存を中断しました。」＋原因（警告の記号）が出る（元のツールでは実行時エラーだった） |
| 取得にかかる時間 | 不明 | 検証DBで、支払い月1か月分の取得に数分かかった（2026/11/02。3か月分で約10分）。設定の待ち時間の上限は600秒 | 単体テストでは扱わない（作成者の判断 2026/11/02。性能の確認として別に扱う） |
| 一時ファイル | 支払一覧生成.SQL、支払一覧.csv を作って消す | 作らない | テストしない |

検証DBでの取得結果（2026/11/02、見るだけ）：2022/03 → 1569行（うち支払回数1が12行）、2026/10 → 2714行、2026/11 → 2444行。どれもエラーなし、25列（21列＋計算用の4列）。
