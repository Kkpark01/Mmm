# TL09（TSSA保守情報更新） 単体テスト仕様書・本文案

準備方針：[共通方針と準備記録](../00_試験準備の共通方針.md)。このケースで使う既存入力値・期待件数・対象版を準備担当者が記入する。DBの試験データ新規登録は行わない。

対象：136の「TSSA保守情報更新ver2.0.xlsm」。131の15の試験用フォルダーに136の同名Excelを差し替え、接続設定と対応表を引き継いだ状態で使う。主要3ケースに絞り、取得・日付金額・引当・CSVを確認する。実DB・業務マクロ・CSV生成の試験は未実施。

凡例：
- 実施者：Excelの操作・表示・CSVを確認する人。
- 準備担当者：検証DBの既存対象、全件・保守会社の対応表、期待値を用意する人。DBへの試験用登録は行わない。
- 試験データ表：実施前に取得元と対応表から期待値を記入する。実行結果から逆算せず、必要条件が揃わなければ「準備未完」とする。
- 各ケースは独立した試験専用フォルダー・ブックを使う。更新用CSVの作成までであり、TSSAへの登録は行わない。
- メッセージIDは「－」。実施区分は通常／要確認／開発者テスト／実施不可／除外候補。
- [用語表](用語表.md)にシート・列と136の修正根拠、[骨子](骨子.md)に補助確認を記載する。003～005・007は独立ケースを作らず、主要番号は詰めない。

## TL09-001

### 項番
TL09-001

### テスト項目
TL09（TSSA保守情報更新）：更新情報作成で7種類のデータを取得・加工し、対応付け・日付・年額が一致し、4本のCSVを作成できること。

### 前提条件
```
実施区分＝通常（対応表と既存データを準備後）。

【この試験で確認すること】
136の修正で7本のSQL取得が完了し、代表機器の引当・日付・年額と4本CSVの件数・識別値を確認する。

【実施する人】
・実施者（更新情報作成と結果確認をする人）。
・準備担当者（検証DBの対象と対応表を確認する人）。

【実施者に必要なもの】
・マクロとTEXTJOINが使えるExcel。SQL接続ドライバー・認証を準備した131の15の試験用フォルダー一式。
・同名Excelは136の修正版へ差し替え済み。INIの接続先は検証DBと確認済み。
・実行Excelのある場所へ新規フォルダー・CSVを作れること。

【準備担当者が用意するデータ】
「全件」A列プラントIDとD列の対応先サポートID、「保守会社」C・D列が取得対象全体を対応付け、ID整合が取れているコピーを用意する。代表機器だけを対応付けても他の行で停止するため、全対象を確認する。
既存の代表プラントPと機器Xを選び、各出力に含まれる値を控える。年額確認は、取引先契約機器明細に抽出される整数月の契約Yを選ぶ。
Yが12か月または支払回数1なら、期待年額は仕切単価と同額。可能なら支払回数2以上・6か月または18か月の既存契約Zも選び、「仕切単価÷月数×12」を控える。なければ非12か月の分岐は未確認として残す。

試験データ表：
| 実施日／対応表の版／対象全体の対応・ID整合を確認した人 | |
| PのプラントID／引当先サポートID | |
| Xの機器管理ID／品名／型式／シリアル番号／数量 | |
| Xの取引先契約ID／契約書番号／解約日（空欄の場合は空欄と記入） | |
| Y（あればZ）の機器管理ID／対象期間開始日（AB）／対象期間終了日（AC）／支払回数／仕切単価／契約月数／期待年額 | |
| CSV期待明細数010／020／030（数量展開後）／040 | |

【開始時の状態】
Excelを起動していなくてよい。試験用フォルダー内に今回と紛らわしい出力は置かず、試験中はDB・対応表を変更しない。
```

### 操作内容
```
1. 136を反映した試験用ブックを開き、「操作シート」を選ぶ。
2. 「更新情報作成」（B6付近）を押す。完了まで待ち、開始・終了日時の通知を記録して「OK」を押す。
3. 次の7シートが作られ、各1行目に見出しがあることを確認する。
　CSM_MNT_RECV010、CSM_MNT_RECV020、CSM_MNT_RECV030、CSM_MNT_RECV040、ブランド契約（TSSA連携用）、ユーザ契約機器明細（TSSA連携用）、取引先契約機器明細（TSSA連携用）。
4. 「CSM_MNT_RECV010」A列でPを完全一致検索し、C列のサポートIDを照合する。「CSM_MNT_RECV030」A列でXを検索し、D列サポートID、F列取引先契約ID、H列シリアル番号、O列品名、P列型式、Q列数量、R列契約書番号、W列解約日を準備値と照合する。
5. 「取引先契約機器明細（TSSA連携用）」A列でY（あればZ）を検索し、AB列「契約開始日(本年)」・AC列「契約終了日(本年)」・AI列支払回数・AU列仕切単価(MCM)・AV列仕切単価を準備値と照合する。月数計算にはAB・ACの対象期間を使い、AA列の初回契約開始日とは区別する。金額は数式バーの数値も確認する。
6. 「操作シート」のM・P・S・X列に「×」がなく、ID不整合通知が出ていないことを確認する。
7. 実行Excelと同じフォルダー内で、今回作成された14桁の日時フォルダーを開く。CSM_MNT_RECV010.csv、CSM_MNT_RECV020.csv、CSM_MNT_RECV030.csv、CSM_MNT_RECV040.csvの4本を確認する。
8. 各CSVをExcelで開いて、見出しを除く明細数と列数を確認する。010＝14列、020＝14列、030＝19列、040＝7列。030はQ列数量の合計分の明細になる。CSVは保存せずに閉じる。
9. 同じCSVをメモ帳でも開く。010のNameとSystemName__c、030のSupportID__c・SerialNO__c・Hinmei__c・Katashiki__c・KeiyakushoNo__cからP・Xの値を照合する。030のNameは8桁連番であることを確認する。
10. エビデンスを記録し、試験用マクロは保存せずに閉じる。CSVをTSSAへ登録する操作は行わない。

【入力値】
検索条件の入力はない。「全件」「保守会社」は準備済みの対応表を使う。
```

### 期待結果
```
【画面確認】
・開始・終了日時の通知が表示され、7種類の取得が完了する。MONTHS_BETWEEN等のSQLエラーで中止しない。
・P・Xの識別値、契約情報、品名・型式・数量が準備値と一致する。対応先サポートIDの先頭0が欠けない。
・Yの開始日・終了日・支払回数・仕切単価が一致し、AV列年額が準備値と一致する。Zを用意した場合は非12か月の換算も一致する。
・操作シートのM・P・S・X列に「×」がなく、「ID不整合があります！」は出ない。

【ファイル確認】
・実行Excel配下の今回の日時フォルダーに、指定した4本のCSVが存在する。正常終了後の成果物はtxtではない。
・列数と明細数が準備値に一致する。030は数量分の行があり、Nameが00000001からの8桁連番となる。
・実ファイルの対応先サポートID・製番・契約書番号・品名・型式が一致し、先頭0や日本語が欠けない。
・年額の確認先は取得シートAV列。CSVの契約金額欄へ同額が自動転記されることは期待しない。

【DB確認】
実施不要（参照・ブック内加工・CSV生成のみ。DBとTSSA本体の更新はしない）。
```

### 期待メッセージ
```
表示タイミング＝CSV4本の作成完了後。
表示形式＝Excelメッセージボックス。
メッセージID＝－。
表示文言＝
開始：開始日時
終了：終了日時
作業者操作＝日時を記録し「OK」を押す。日時は今回の実行時刻と照合し、固定の年月日を期待しない。
```

### 備考
対応表未登録やID不整合で止まった場合は正常完了と判定しない。ExcelでCSVを開いた時の自動数値化による表示差は、メモ帳で実ファイルを確認する。136の258パターンは既存検証を参照し、ここでは既存契約の代表値と一連動作に絞る。

## TL09-002

### 項番
TL09-002

### テスト項目
TL09（TSSA保守情報更新）：対応表にない既存プラントを検知して確認停止し、正しいサポートIDを補完すると取得済みデータから再開できること。

### 前提条件
```
実施区分＝通常（試験専用対応表を準備後）。

【この試験で確認すること】
未対応プラントをCSVへ流さずに止め、対応表を補完して「処理再開」でCSV作成へ進めること。

【実施する人】
・実施者（確認停止後に対応を補完して再開する人）。
・準備担当者（既存の1プラントだけを未対応にしたローカルコピーを作る人）。

【実施者に必要なもの】
・136のExcel、131の接続INIを組み合わせた試験用15フォルダー一式。検証DB接続・認証・ドライバーとExcel。
・書込可能な試験用出力場所。元の対応表・業務ブックには変更を加えない。

【準備担当者が用意するデータ】
まず全体が正常に対応付けられる試験用対応表を用意し、取得対象の既存プラントPを1件選ぶ。Pの対応先は7桁の正しいサポートIDであり、「移行不要」ではないこと。
Pの「全件」A:Gの行を別のExcelファイルへ控えて保存してから、その行を試験用コピーだけで削除する。マクロと同じブックに控えシートを追加しない（取得開始時に削除されるため）。A列にPが残っていないことを確認する。他の対応・DBは変えない。
これはローカル対応表を未対応状態にする準備であり、DBへ新しいプラントを作る試験ではない。

試験データ表：
| PのプラントID／正しいサポートID／元のA:G控え | |
| 正常完了時のCSV期待明細数010／020／030／040 | |
| 他のプラント・保守会社の対応とID整合を確認した人 | |

【開始時の状態】
独立した試験用ブックから開始する。途中でExcelを閉じず、同じ取得データを使って再開する。
```

### 操作内容
```
1. 準備済みの試験用ブックを開き、「操作シート」の「更新情報作成」を押す。
2. 新規プラントの確認通知を記録して「OK」を押す。「全件」へ切り替わったことを確認する。
3. 「全件」A列でPを完全一致検索する。Pの新しい行が追加され、D列の引当先が未設定であることを確認する。開始・終了日時の完了通知と、今回のCSV出力がないことを確認する。
4. 追加されたPの行のD列へ、控えにある正しい7桁サポートIDを文字列で入力する。架空値・他プラントの値は使用しない。
5. Excelを閉じずに「操作シート」の「処理再開」（B13付近）を押す。開始・終了日時の通知を記録して「OK」を押す。
6. 「CSM_MNT_RECV010」のA列でPを検索し、C列の対応先が補完した値と一致することを確認する。
7. 今回作成された日時フォルダーに4本のCSVがあり、各明細数が準備値と一致することを確認する。操作シートにID不整合の「×」がないことも確認する。
8. エビデンスを記録してブックを保存せずに閉じる。元の業務用対応表へ試験上の行削除を反映しない。

【入力値】
追加された全件シートのP行D列＝控えにある正しいサポートID。
```

### 期待結果
```
【画面確認】
・未対応のPが「全件」に追加され、新規プラントの確認通知で処理が止まる。停止時点では正常終了の日時通知は出ない。
・正しいサポートIDを補完後、「処理再開」で処理が続き、Pの対応付けが一致して正常終了する。PをDBへ追加し直す操作は不要。
・再開は既に取得した7シートを使う。SQL失敗後の途中データで再開する操作ではない。

【ファイル確認】
・確認停止中は今回のCSVを作成しない。補完・再開後は新しい日時フォルダーに4本のCSVが揃い、件数が準備値と一致する。

【DB確認】
実施不要（試験で編集するのはローカルExcelの全件対応表。DBへの更新なし）。
```

### 期待メッセージ
```
表示タイミング＝更新情報作成で未対応プラントを検知した時。
表示形式＝Excelメッセージボックス（警告）。

表示タイミング＝処理再開後、CSV4本を作成した時。

### 備考
この「新規」は対応表に未登録という意味で、DBへ新規登録する必要はない。取得に失敗した時は本ケースの再開操作を行わず、原因確認後に最初の「更新情報作成」からやり直す。

## TL09-006

### 項番
TL09-006

### テスト項目
TL09（TSSA保守情報更新）：同時点・同じ対応表の現行版と改修版を実行し、代表機器・年額・4本CSVの内容を比較すること。

### 前提条件
```
実施区分＝要確認。同じ元データ・対応表を揃えられなければ実施不可。

【この試験で確認すること】
Oracle版と136適用のSQL Server版について、取得・加工とCSVの代表値・件数を比較する。

【実施する人】
・実施者（両版を実行して比較する人）。
・準備担当者（同じ元データと全件・保守会社対応表を揃える人）。

【実施者に必要なもの】
・実行可能な現行版と136適用の改修版。各接続環境とExcelを準備し、別々の試験用フォルダーに置く。
・取得対象全体の対応・ID整合が取れた、同じ全件・保守会社対応表。

【準備担当者が用意するデータ】
元データ時点と採用する契約期間が一致することを確認する。代表プラントP、機器Xと、年額換算対象の契約Yを選ぶ。数量2以上や非12か月の既存契約があれば比較対象へ追加する。

試験データ表：
| 両版のファイル名・接続先識別名／元データ時点の一致根拠 | |
| 全件・保守会社の対応表の版 | |
| P／X／YのIDと、両版で同じ契約期間を使う確認根拠 | |

【開始時の状態】
両版とも正常作成できる状態で開始する。異なるデータ時点の件数差を処理差と断定しない。
```

### 操作内容
```
1. 現行版を開いて「更新情報作成」を押す。完了通知の日時を控えて「OK」を押す。
2. 7取得シートの見出しを除く件数、Pの対応先、Xの品名・型式・数量・製番・契約NoとYの開始日・終了日・年額を比較用ブックの「現行」へ値で控える。今回の4本CSVの場所・明細数も控える。ツールは保存せずに閉じる。
3. 136適用の改修版で同じ操作を行い、対応する値と4本CSVの場所・明細数を比較用ブックの「改修」へ控える。
4. P・X・Yのキーで対応を合わせ、取得件数、対応先サポートID、日付・年額・機器の値を比較する。
5. CSVは両版でファイル名・列数・明細数・代表機器の各フィールドを比較する。先頭0はメモ帳で実ファイルを確認する。030の連番は行順で変わり得るため、連番だけで機器を対応付けず、サポートID・製番・品名・型式等で照合する。
6. 差があれば対象ID・項目名・両値を記録する。比較結果を保存し、ツールは保存せずに閉じる。

【入力値】
検索条件の入力はない。対応表・元データを両版で揃える。
```

### 期待結果
```
【画面・比較用ブック確認】
・7取得シートの件数と、代表P・X・Yの対応先・契約期間・年額・機器情報が一致する。
・両版が正常終了し、4本CSVのファイル名・列数・明細数と、代表機器の各フィールドが一致する。
・データ時点・採用期間・対応表・出力順に差がある場合、影響する項目を切り分ける。理由が確定するまで一致・合格と扱わない。

【DB確認】
更新結果の確認は不要。比較前提の元データ時点・契約期間・対応表は準備時に確認する。
```

### 期待メッセージ
```
表示タイミング＝両版でCSV作成が完了した時。
表示形式＝Excelメッセージボックス。
メッセージID＝－。
表示文言＝「開始：開始日時」、改行、「終了：終了日時」。
作業者操作＝各日時を記録して「OK」を押す。異なる実行日時そのものの文字一致は求めない。

### 備考
現行環境の実行不可・データ時点不一致は実施不可と記録する。CSVの全列全行の完全比較ではなく、全件数と代表値の比較。TSSAへの取込結果は今回の試験範囲に含めない。
