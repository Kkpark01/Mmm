# TL09（TSSA保守情報更新） 用語表・根拠

2026-11-02。**136の配布用TSSA保守情報更新ver2.0.xlsm**を基準とする。131の15にある同名ブックにはSQL変換漏れが残るため、そのまま試験対象としない。136のブックを、131の15の試験用コピーへ差し替え、既存のMcm移行部品／McmMacroSettings.iniを使う。利用者が編集した対応表・接続設定は別途引き継ぐ。

根拠は[136の修正説明](../../../136_TSSA保守情報更新_SQL変換漏れ修正/README.md)と[TL09調査記録](../../../../検証記録/20261102_業務利用ツール引継ぎ/TL09_調査)。VBA10モジュール、抽出SQL7本とボタン割当を確認。業務マクロ・実DB・CSV生成は今回実行していない。

## 操作シートと対応表

| 表示名 | 位置・割当 | 動作 |
|---|---|---|
| 更新情報作成 | B6付近・TSSA_MainteData | 旧取得シートを削除して7種類を取得、対応表適用、ID整合チェック後にCSVを作成 |
| 処理再開 | B13付近・Restart_TSSA_MainteData | 今のブックの取得済み7シートから再開。通常のDB再取得はしない |
| クリア | B2付近・Data_Claer | 操作シート・全件・保守会社・発行SQL・内蔵SQL以外のシートを削除 |
| 全件 | A列＝プラントID、D列＝引当先サポートID | データは3行目から。DB取得対象の全プラントを対応付ける必要がある |
| 保守会社 | C列キー・D列担当CE | 取得したメーカー名＋保守会社名から担当CEを引く |

抽出条件の入力欄はない。①指定月等の入力を他ツールから流用しない。「処理再開」は正常取得後の対応表確認停止からの再開用。SQL失敗・取得シート不足の状態で押す手順にしない。

取得元はT05_00_default_01～07.sql。新規プラントIDが対応表にないと、7種類の取得後、「全件」へ対象を追記して確認停止する。正常終了の日時表示とCSV生成には進まない。D列へ確認済みサポートIDを設定して、同じExcelを開いたまま「処理再開」を使う。

ID整合チェックは操作シートのM・P・S・X列。参照先のないIDに「×」、該当する先頭欄に「↓◆不整合あり◆」を表示して「ID不整合があります！」で止まる。

## 136で直した計算

修正SQLは取引先契約機器明細の07だけ。OracleのMONTHS_BETWEEN、日付±1、時刻切り出し等をSQL Serverへ置き換えた。年額換算は次のまま。

- 契約月数が12、または支払回数が1：仕切単価(MCM)をそのまま採用。
- その他：仕切単価(MCM)÷契約月数×12。
- 契約月数は開始日と終了日の翌日から求める。同日・両月末は整数月、それ以外は31日基準の端数・時刻を考慮する。

本文の代表には整数月の既存契約を使う。例示金額をDBへ登録しない。年額の確認先は取得シートのAV列。CSM_MNT_RECV030の契約金額欄にAVを自動で転記する呼出は見当たらず、CSVへ年額が出るという期待値にはしない。

月数の根拠は対象期間のAB列「契約開始日(本年)」とAC列「契約終了日(本年)」（SQLのTKB.KAISI_DT・TKB.SYURYO_DT）。AA列「契約開始日」は初回契約開始日であり、この月数の開始日に使わない。

136ではSQL7本の空の一時テーブル実行と、日付・年額258パターンの検証記録がある。今回同じ検証は再実行せず参照する。これは検証DBの実データでの一連実行を確認した記録ではない。

## 出力

保存先は実行ブックと同じフォルダーの下に作る `yyyymmddhhmmss` フォルダー。通常の他ツールと違い、CSVを実行ブックの直下へ4本並べる仕様ではない。

| ファイル名 | 出力列数・データ行数 |
|---|---|
| CSM_MNT_RECV010.csv | 14列。加工後010の明細行数 |
| CSM_MNT_RECV020.csv | 14列。加工後020の明細行数 |
| CSM_MNT_RECV030.csv | 19列。加工後030のQ列数量の合計行数。数量分に展開する |
| CSM_MNT_RECV040.csv | 7列。加工後040の明細行数 |

010・020・040はシートのB列を除く。030はD:PとR:Wを出力し、内部IDと数量列は出さない。030の出力4列目Nameは00000001からの8桁連番。1行目は見出し。文字値を二重引用符で囲みカンマで区切る。内部では一度txtを作り、最後にcsvへ改名する。正常終了時の成果物はCSV。

メモ帳で引用符内の値・先頭0を確認する。ExcelでCSVを開いた表示は自動的に数値化されることがあるため、表示だけで先頭0欠落と判定せず実ファイルを確認する。CSVをExcelから上書き保存しない。

## メッセージ

すべてメッセージIDは「－」。

| 条件 | 表示文言 |
|---|---|
| 新規プラントの確認停止 | 新規プラントIDが追加されました。／空行／サポートIDを確認してください。 |
| 引当エラー | サポートID引当エラー発生！／空行／全件シート、CSM_MNT_RECV010シートのプラントIDにVLOOKUPで参照エラーが発生 |
| ID不整合 | ID不整合があります！ |
| 正常終了 | 開始：開始日時／終了：終了日時 |

正常終了は「更新を完了しました。」等の固定文ではない。マクロは更新用CSVを作るが、DB更新・TSSA本体への登録は行わない。
