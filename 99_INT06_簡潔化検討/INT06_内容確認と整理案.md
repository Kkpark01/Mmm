# INT06 内容確認と整理案

2026-10-17。98のExcelのINT06全12項番と、85の全文MD・関連コードを確認した初期案。本文作成・Excel反映・実機試験は未実施。

## 簡潔化する方針

- 02～05・INT03と同じ8項目の体裁とし、準備・操作・画面／帳票確認・DB確認を分ける。
- 実施者には画面名・入力欄・対象契約・帳票の見出しで案内する。ON／OFFは「チェックを入れる／外す」、受領Web等は「Web版」と記載する。
- 支払い明細出力指示（MCM3002U）は「支払い月」「年払い／月払い」「出力」の画面。検索ボタンや検索結果一覧を前提にしない。
- 発注確認書・支払い明細の2帳票は残す。契約番号・製番・金額等の対象データの一致に絞り、全行・全マスタ・監査値の比較を毎回求めない。
- 出力対象になるデータと期待額は準備担当者が用意する。内部ID・ビューの結合条件・計算式の調査を通常の実施者へ求めない。DB担当者による前提確認は必要だが、SQL条件を本文全件へ繰り返さない。

## 項番別の整理案

| 項番 | 最低限残す確認 | 簡潔化する内容 |
|---|---|---|
| 01 | 年払いの契約が対象月の両帳票に出る | 契約1件の契約番号・製番・金額を照合。反対区分の比較データは02との分担を検討。 |
| 02 | 月払いの契約が対象月の両帳票に出る | 01と同じ流れで、対象1件に絞る。 |
| 03 | 支払月のチェック変更が出力対象月へ反映される | 契約1件の旧月・新月を確認。変更前後の全帳票項目比較を省く。対象月の保存値はDBで限定確認。 |
| 04 | 期間切替前後で正しい金額が出る | 1契約・旧新2期間・切替前後2か月に絞る。 |
| 05 | 端数を含む金額が正しく出る | 12か月すべての出力は省き、最初の月と翌月の2回を確認する案。年間全月の一致まで確認済みとはしない。 |
| 07 | 確認済み製番だけが出る | 確認済み・未確認の2条件を基本とし、期間外との複雑な組合せは省略する案。 |
| 08 | 無効な期間が出力対象にならない | 承認前後の一連操作は省き、有効・無効の比較に絞る。未承認を一律除外するという元タイトルは訂正する。 |
| 09 | 契約更新後の再出力に変更が反映される | 1契約・変更項目1つに絞る。「検索後更新」という画面にない表現を訂正。別PCを必要とするかは、残す観点に応じて本文作成時に整理する。 |
| 10 | 取引先ごとに宛先・契約・金額が分かれる | 取引先Xに2契約、Yに1契約の最小構成で確認。全マスタ・全契約の再照合は省く。 |
| 11 | 対象がなくなるとエラーになり、前回の帳票を再出力しない | 初回出力→対象月のチェックを外して登録→再出力の1契約に絞る。「検索結果消失」という表現を訂正。 |
| 12 | チェックした月だけを出力する | 通常操作で作れない内部フラグの組合せは省略。通常のチェック解除確認は03へまとめ、この項番を今回対象外とする案。 |
| 13 | 取引先解約後の対象除外と、ユーザー解約時の製番表示 | 日単位の全組合せ・前後月総当たりを省き、取引先とユーザーを分けた代表条件に絞る。採否と製番印を混同しない。 |

管理項番は12件（01～05・07～13、06は原本で13へ統合済みの欠番）。上記案を採用する場合は実施11件・12のみ今回対象外。現時点では整理案であり、Excelの実施区分は変更していない。

## 仕様・実装の確認点

- VBの支払ビューは期間のYUKO_FLG <= 0を条件とし、承認状態を直接条件にしていない。「未承認なら必ず出力されない」とは記載しない。
- 支払明細の対象はON_FLG＝1・OFF_FLG＝0。通常画面から作れないON_FLG＝0・OFF_FLG＝0を一般実施者の準備条件にしない。
- 取引先の解約日による出力可否と、ユーザーの解約日によるハード製番の「* 」表示は別の仕様。
- mcm-web/srcの3002UはZIPで2帳票を返す。修正コード75には個別ダウンロード版があるが、実環境への反映状況は未確認。本文では実行環境の方式を確認して記載し、誤った取得方法を断定しない。
- 支払金額の配分・端数の根拠はVB支払関数とWeb版calculatePaymentへ照合。ケース05の例は元仕切額12,001円、12か月、毎月支払で初月1,001円・翌月1,000円。採用条件・入力値をそろえること。
