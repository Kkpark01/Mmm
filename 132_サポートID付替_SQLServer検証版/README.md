# サポートID付替ツール：新MCM検証版

現行のVBツールを基に、SQL Server上の新MCMに対応した検証用のツールです。**実DBのテーブルや権限、Web画面との一連操作は未確認のため、本番用としては使用しないでください。**

## フォルダの内容

- `実行用`：実行ファイルと設定ファイル。2つを同じフォルダに置いて使用します。
- `ソース`：修正後のVisual Basicのプロジェクト。Visual Studioで開く場合は、フォルダ内の `.sln` を使用します。

`ソース/bin`・`ソース/obj` はビルド時に作成されたファイルです。通常の検証には `実行用` を使用してください。

既存の131のマクロ、Webアプリ、受領した元のVBツールは変更していません。

## 変更内容

- 現行の画面、付替元・付替先の入力確認、確認ダイアログ、ログ出力を基に、新MCMのSQL Serverへ接続します。
- 既存の更新対象を維持し、プラント・納入先のDTS連携フラグと、プラント・見積・契約期間のサポートIDを一つのトランザクションで更新します。失敗時はまとめて取り消します。
- Oracle固有のSQLをSQL Server向けに変更し、更新前に対象を固定して同時更新を制御します。新DBのBIGINTのIDにも対応します。
- Web側が更新日時で更新競合を判定するため、更新対象の更新日時と更新者を設定します。秒精度の更新日時でも変更を検出できるよう、既存値が現在時刻以上なら既存値より1秒進めます。そのため、短時間の連続更新や既存値が未来の場合、表示時刻が実際の時刻より先になることがあります。
- 現行の画面の枠線は、実行に必要な旧PowerPacksが受領資料に含まれていなかったため、Windows標準の描画に変更しています。

## 検証前の設定

`実行用` の `.exe.config` をメモ帳などで開き、会社で確認した環境の設定に変更して保存します。**初期状態は接続先と更新者の方式が空欄のため、接続・更新されません。**

| 設定項目 | 内容 |
|---|---|
| Server | SQL Server名と必要なポート。検証環境の候補は `ILCM-SYSDEV,1433`。実際の接続先を確認してください。 |
| Database | データベース名。検証環境の候補は `SYSDEV`。実際の対象を確認してください。 |
| Authentication | `Windows` または `SqlLogin`。会社で確認した認証方式を指定します。 |
| AuditUserMode | 更新者の記録方法。`Windows` は実行者のWindowsユーザー名、`Fixed` は下のAuditUserを使用します。運用を確認して選択してください。 |
| AuditUser | AuditUserModeが`Fixed`のときの更新者ID。1～50文字。 |
| TrustServerCertificate | 初期値は `false`。証明書と暗号化の設定はDB管理者に確認してください。 |

SQL認証の場合、環境変数 `MCM_TOOL_DB_USER` と `MCM_TOOL_DB_PASSWORD` を会社の管理方法で設定し、ツールを開き直します。パスワードは設定ファイルへ書き込みません。Windows認証の場合、この2つの環境変数は不要です。

## 操作と確認

1. DB管理者と、検証用の付替元・付替先サポートID、更新してよい対象データ、復元方法を確認します。
2. 実行用フォルダの `.exe` を開き、付替元・付替先のIDを入力します。画面に表示される納入先を確認します。
3. 「開始」を押し、確認画面で内容を確認して実行します。処理結果は画面と同じフォルダの `log.txt` で確認します。
4. Web画面とDBで、対象データのサポートID、DTS連携フラグ、更新日時・更新者、および対象外データを確認します。Web画面で表示中のデータとの同時操作も検証します。

元のツールと同じく、これは画面から複数の表を直接更新する機能です。Webアプリ側の画面処理を通して更新するものではありません。実環境で必要な業務上の連携・権限・監査要件は別途確認してください。

## 実施した検証

- 32bit版をビルドし、画面タイトル・開始／終了ボタン・ID入力欄の存在と長さを確認。画面全体の実機比較は未実施。
- このPC内に作った独立したSQL ServerテストDBで、6表を使って正常更新、対象外の維持、BIGINTのID、途中失敗時の取り消し、更新日時・更新者、同時更新の待機・解除を確認。テストDBは終了後に削除しました。
- 接続先未設定では接続しないこと、更新者のWindows／固定値の両方式を模擬DBで確認。
- 実行ファイルと設定の出力先を照合し、元の接続文字列を成果物に含めていないことを確認。

## 未確認・制約

- 検証DBの実テーブル・列・型、認証、権限、証明書、トリガー、データとの整合性は未確認です。検証DBや本番DBには接続・更新していません。
- Web画面と本ツールを使った同時操作、エラー復帰、実データによるDTS連携・監査記録は未確認です。今回の同時更新テストは、模擬DBで同じ行に対して待機することを確認したものです。
- このPCには .NET Framework 4 の参照アセンブリがなく、ビルド時はインストール済みのアセンブリを使う警告が出ました。実行確認はこのPC上で実施しましたが、配布・正式ビルドには、会社のVisual Studio／対象フレームワークの環境で再ビルドして確認してください。
- 更新者をWindowsユーザー名と固定IDのどちらで記録するかは運用確認待ちです。
